# 18 · 点云与粒子：海量点与 CPU 粒子的两条渲染路

> 阅读前提：读过 [04-3DTiles加载与LOD.md](04-3DTiles加载与LOD.md)（瓦片树与内容分派）、[15-Model与glTF加载.md](15-Model与glTF加载.md)（新 Model 架构与 pipeline stage）；[13-渲染命令与着色器.md](13-渲染命令与着色器.md)（DrawCommand/派生命令）与 [03-Entity数据体系.md](03-Entity数据体系.md)（Billboard 底座）分别是 EDL 与粒子系统的地基。
> 一句话：Cesium 的「点」有两条完全不同的路——3D Tiles 点云（pnts）在新 Model 架构里走 GPU 管线、靠衰减与 EDL 保证任意距离可读；[`ParticleSystem`](../packages/engine/Source/Scene/ParticleSystem.js#L58) 则是纯 CPU 模拟 + Billboard 渲染的粒子引擎——本篇把两条路各自的主战场、关键参数与 1.145 架构变化讲清。

**本文讲什么**：

- 点云双路线总览：3D Tiles pnts（经 [`Model3DTileContent`](../packages/engine/Source/Scene/Model/Model3DTileContent.js) 走新 Model 架构）vs [`TimeDynamicPointCloud`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L41)（时序点云，内部仍用旧 [`PointCloud`](../packages/engine/Source/Scene/PointCloud.js#L57)）
- pnts 在 1.145 的归宿：[`preprocess3DTileContent`](../packages/engine/Source/Scene/preprocess3DTileContent.js#L27) 识别 + [`Cesium3DTileContentType.POINT_CLOUD`](../packages/engine/Source/Scene/Cesium3DTileContentType.js#L48) 分派
- 点大小衰减：[`PointCloudShading`](../packages/engine/Source/Scene/PointCloudShading.js#L21) 全参数与 [`PointCloudStylingPipelineStage`](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L57) 的 shader 注入
- 眼睛圆顶光照 EDL：[`PointCloudEyeDomeLighting`](../packages/engine/Source/Scene/PointCloudEyeDomeLighting.js#L171) 「劫持 POINTS 命令 → 离屏重画 → 全屏混合」的派生命令玩法
- 时序点云：帧调度（平均加载时间预取/跳帧）、内存上限与 LRU 卸载
- 粒子系统：[`ParticleSystem`](../packages/engine/Source/Scene/ParticleSystem.js#L58) 粒子池/发射率/双矩阵、[`Particle.update`](../packages/engine/Source/Scene/Particle.js#L126) 单步积分、发射器家族（Cone/Circle/Sphere/Box）

## 1. 总览：两条「点」路线

「点云」在 Cesium 里指两种东西，源码入口完全不同：

| 维度 | 3D Tiles 点云（pnts） | 时序点云（TimeDynamicPointCloud） |
|---|---|---|
| 典型数据 | las/pgmwy 处理成的 3D Tiles（建筑物扫描、倾斜摄影点云） | 逐帧独立的 pnts 序列（施工进度、雷达体扫） |
| 挂载方式 | `Cesium3DTileset.fromUrl(...)` | `viewer.scene.primitives.add(new TimeDynamicPointCloud({clock, intervals}))` |
| 内容类 | [`Model3DTileContent`](../packages/engine/Source/Scene/Model/Model3DTileContent.js)（新 Model 架构，见 §2） | 内部 [`new PointCloud`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L386)（旧专用类，见 §5） |
| LOD | 瓦片树 SSE（[04](04-3DTiles加载与LOD.md) 全套） | 时间维调度（帧预取/跳帧，空间维不分层） |
| 渲染质量 | attenuation + EDL + 样式（§3/§4） | 同套 [`PointCloudShading`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L99)（`shading` 字段） |
| 内存口径 | `tileset.totalMemoryUsageInBytes`（[16 §内存](16-性能调试与优化.md)） | 自有 `maximumMemoryUsage`（默认 256MB） |

粒子系统（§6 起）与点云没有源码交集：它是 [`Scene`](../packages/engine/Source/Scene/Scene.js#L623) 上的一个普通 primitive，CPU 逐粒子积分后交给 BillboardCollection 上屏——放本篇只因业务上常一起出现（点云表达静态地形、粒子表达动态烟火）。

## 2. pnts 在 1.145 的归宿：并入新 Model 架构

1.145 已**没有独立的 PointCloud3DTileContent**（[`Model3DTileContent` 文件头导读](../packages/engine/Source/Scene/Model/Model3DTileContent.js#L2) 原话：三维模型与点云瓦片内容都由本类承担）。链路：

```
Cesium3DTileset.fromUrl（04 §加载）
   │ 拉到瓦片 payload（ArrayBuffer）
   ▼
preprocess3DTileContent（L27）            ← 魔数嗅探：b3dm/i3dm/pnts/... 
   │ 识别为 "pnts"（Cesium3DTileContentType.POINT_CLOUD，L48）
   ▼
Cesium3DTileContentFactory → Model3DTileContent（pnts 与 glb 同途）
   │ 内部构造 Model（15 §两层架构）+ pointCloudShading
   ▼
Build/管线 stage 链（15 §pipeline stages）
   └─ PointCloudStylingPipelineStage（§3：注入 gl_PointSize 衰减/剔除/样式）
   ▼
POINTS 图元的 DrawCommand（13 §命令编队）
```

要点：pnts 的**解析**（feature table 里的量化坐标/RGB/法线/批量 ID）由 [`PntsParser.parse`](../packages/engine/Source/Scene/PntsParser.js#L33) 完成（子解析器：[`parsePositions` L329](../packages/engine/Source/Scene/PntsParser.js#L329)、[`parseColors` L394](../packages/engine/Source/Scene/PntsParser.js#L394)、[`parseNormals` L484](../packages/engine/Source/Scene/PntsParser.js#L484)、[`parseBatchIds` L526](../packages/engine/Source/Scene/PntsParser.js#L526)、Draco 压缩属性 [`parseDracoProperties` L256](../packages/engine/Source/Scene/PntsParser.js#L256)），解析产物被适配成 glTF 风格的顶点语义（BATCH_ID 映射为 `_FEATURE_ID_0`，见 [15 §特性样式](15-Model与glTF加载.md)）——「pnts 只是另一种被翻译成 Model 的容器」。

样式：3D Tiles 1.0 的 `pointCloudColorStyle`/3D_STYLES 表达式由新架构的 [`CPUStylingPipelineStage`](../packages/engine/Source/Scene/Model/CPUStylingPipelineStage.js)/着色函数注入承接（[`PointCloudStylingPipelineStage.getStyleShaderFunctionInfo` L285](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L285) 把样式表达式编译成 GLSL 函数），内建属性名收集在 [`getBuiltinPropertyNames` L358](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L358)（`COLOR`/`POSITION`/normalShading 需要的法线等）。

## 3. 点大小衰减：PointCloudShading 全参数

点云最核心的观感参数是「点该画多大」。屏幕上 1px 的点在拉近后变成稀疏的坑，拉远后混成噪点——**attenuation（衰减）**按几何误差把点大小映射到真实世界尺度：

| 参数 | 默认 | 作用 | 锚点（[PointCloudShading.js](../packages/engine/Source/Scene/PointCloudShading.js#L21)） |
|---|---|---|---|
| `attenuation` | false | 总开关：按几何误差算点大小 | [L29](../packages/engine/Source/Scene/PointCloudShading.js#L29) |
| `geometricErrorScale` | 1.0 | 几何误差缩放（数据集本身偏稀/偏密时调） | [L36](../packages/engine/Source/Scene/PointCloudShading.js#L36) |
| `baseResolution` | 自动 | 单点基准分辨率（米）；算不出时手动给 | [L50](../packages/engine/Source/Scene/PointCloudShading.js#L50) |
| `maximumAttenuation` | undefined→点大小上限 | 点的屏幕尺寸封顶（px） | [L42](../packages/engine/Source/Scene/PointCloudShading.js#L42) |
| `eyeDomeLighting` | true | EDL 开关（§4） | [L60](../packages/engine/Source/Scene/PointCloudShading.js#L60) |
| `eyeDomeLightingStrength` | 1.0 | EDL 强度 | [L67](../packages/engine/Source/Scene/PointCloudShading.js#L67) |
| `eyeDomeLightingRadius` | 1.0 | EDL 半径 | [L75](../packages/engine/Source/Scene/PointCloudShading.js#L75) |
| `backFaceCulling` | false | 背面点剔除（有法线数据才有意义） | [L84](../packages/engine/Source/Scene/PointCloudShading.js#L84) |
| `normalShading` | true | 法线着色（消费 [17 §光照总线](17-天空光照与大气.md) 的 `czm_sunDirectionEC`） | [L92](../packages/engine/Source/Scene/PointCloudShading.js#L92) |

挂载与消费链（三处入口、一份实现）：

- tileset 侧：[`Cesium3DTileset.pointCloudShading` getter/setter L1713](../packages/engine/Source/Scene/Cesium3DTileset.js#L1713)（构造 [L610](../packages/engine/Source/Scene/Cesium3DTileset.js#L610)）；
- Model 侧：[`Model.pointCloudShading` L833](../packages/engine/Source/Scene/Model/Model.js#L833)（构造期 [`new PointCloudShading` L385](../packages/engine/Source/Scene/Model/Model.js#L385)，同时快照 `attenuation`/`backFaceCulling` 用于脏检查）；
- shader 注入：[`PointCloudStylingPipelineStage.process` L57](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L57)——`attenuation` 打开时加 `HAS_POINT_CLOUD_ATTENUATION` 定义（[L119-L124](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L119)），顶点着色器里以 `gl_PointSize = attenuation(几何误差, 距离)` 动态改写点大小；`backFaceCulling` 对应 `HAS_POINT_CLOUD_BACK_FACE_CULLING`（[L127-L132](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L127)）；样式含 alpha 时整片元 pass 改 [`Pass.TRANSLUCENT`](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L108)；uniform 装配 [`model_pointCloudParameters` L153-L155](../packages/engine/Source/Scene/Model/PointCloudStylingPipelineStage.js#L153)。

**为什么 EDL 依赖 attenuation**：不衰减时点永远 1px，屏幕上孔隙与表面无密度差，EDL 无从判断「洞」；衰减后点按真实间距铺开，深度不连续处才可检测（见 §4 门控条件）。

## 4. EDL：眼睛圆顶光照的派生命令玩法

点云没有三角形面，每个点各自为政，光照靠法线着色（`normalShading`，§3 表）仍显单薄。**Eye Dome Lighting** 的思路：渲染点的深度到离屏纹理，再对每个像素采样邻域深度差，把「近处突起」加亮、「凹陷」压暗——一种屏幕空间的假全局光照，让散点瞬间「成壳」。

源码实现是派生命令（[13 §变体](13-渲染命令与着色器.md)）教科书级的应用，全部在 [`PointCloudEyeDomeLighting`](../packages/engine/Source/Scene/PointCloudEyeDomeLighting.js#L22)：

```
Cesium3DTileset.update 尾声（L3352-L3361）
   条件：attenuation && eyeDomeLighting && 本帧有点云命令
        │
        ▼
PointCloudEyeDomeLighting.update(frameState, commandStart, ...)（L171）
   ① 扫描 commandList[commandStart..end]：
      只劫持 primitiveType === POINTS 且非 TRANSLUCENT 的命令（L192-L201）
   ② 对每条命令做 DrawCommand.shallowClone（L208 附近）→ derivedCommands.pointCloudProcessor
      · framebuffer ← 本类离屏 FBO（含 color+depth 两附着，L23-L50）
      · shaderProgram ← 派生版（getECShaderProgram：把原片元的 out_FragColor
        换成写「深度编码色」，缓存键=原 program，L157 createDerivedShaderProgram）
   ③ 原命令照常执行（此时已画进离屏 FBO）
   ④ 末尾追加一条全屏混合命令（createCommands L92 的 blendFS viewport-quad）
      · 采样离屏 color/depth，按 _strength/_radius（L181-L183，来自
        eyeDomeLightingStrength × pixelRatio）做邻域深度差加权
      · 画回主 FBO，等效把点云「描边增厚」
```

两个细节值得记：

- **复用缓存**：派生命令对象缓存在 `command.derivedCommands.pointCloudProcessor`（[L192-L199](../packages/engine/Source/Scene/PointCloudEyeDomeLighting.js#L192)），原 shader 或 FBO 尺寸变化才重造（`command.dirty`/`originalShaderProgram` 比对，[L201-L210](../packages/engine/Source/Scene/PointCloudEyeDomeLighting.js#L201)）——与 [13 §derivedCommands](13-渲染命令与着色器.md) 的 dirty 闸门同一套纪律；
- **能力探测**：不支持所需 FBO 特性时静默跳过（[`isSupported` 判定 L177-L179](../packages/engine/Source/Scene/PointCloudEyeDomeLighting.js#L177)）。

时序点云同样复用这一类：[`TimeDynamicPointCloud` 构造 L171](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L171) 自建一个实例，update 流程里同款劫持。

## 5. 时序点云：TimeDynamicPointCloud 与旧 PointCloud 战场

[`TimeDynamicPointCloud`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L41) 解决「同一地点 N 个时刻各一帧点云」：构造需要 `clock`（[10 §Clock](10-时间与动态属性.md)）与 `intervals`（时间区间→帧 URL 映射）。核心字段：`maximumMemoryUsage = 256`MB（[L93](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L93)）、`shading = new PointCloudShading(...)`（[L99](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L99)）、`frameFailed`/`frameChanged` 两个事件（[L150](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L150)/[L165](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L165)）。

帧调度策略（文件头注释 [L22-L24](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L22) 的原话翻译）：**按最近 N 帧的平均加载时间预取**当前播放速度下即将到达的帧；中间帧加载不及就直接跳过，帧足够小或时钟足够慢则不跳。实现拆在这些私有函数：

| 函数 | 行号 | 职责 |
|---|---|---|
| [`getClockMultiplier`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L283) | L283 | 时钟速度→帧预取节奏 |
| [`getCurrentInterval`/`getNextInterval`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L324) | L324/L294 | 由当前时间定位目标帧 |
| [`requestFrame`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L360) | L360 | 按需发请求（走 [05 §RequestScheduler](05-帧更新与渲染循环.md)） |
| [`updateAverageLoadTime`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L399) | L399 | 维护平均加载时长 |
| [`prepareFrame`/`renderFrame`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L411) | L411/L468 | 换帧前准备与渲染（`new PointCloud` L386） |
| [`getNearestReadyInterval`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L552) | L552 | 目标帧没就绪时找最近已就绪帧顶上（防黑屏） |
| [`unloadFrames`](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L510) | L510 | 按 `maximumMemoryUsage` LRU 卸载旧帧 |
| [`update`（入口）](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L612) | L612 | 每帧总控 |

内部真正的渲染器是旧 [`PointCloud`](../packages/engine/Source/Scene/PointCloud.js#L57) 类（**只服务时序点云这一条路**了），主战场：

- [`initialize` L200](../packages/engine/Source/Scene/PointCloud.js#L200)：调 [`PntsParser.parse` L201](../packages/engine/Source/Scene/PointCloud.js#L201) 解析 ArrayBuffer（与 §2 同一解析器！两代架构共用 pnts 解析）；
- [`createResources` L353](../packages/engine/Source/Scene/PointCloud.js#L353)：建 VAO/纹理（含近似包围球采样 [`computeApproximateBoundingSphereFromPositions` L301](../packages/engine/Source/Scene/PointCloud.js#L301)、随机采样 [`getRandomValues` L287](../packages/engine/Source/Scene/PointCloud.js#L287)）；
- [`createUniformMap` L613](../packages/engine/Source/Scene/PointCloud.js#L613)：点云参数 uniform（含 `u_quantizedVolumeScaleAndOctEncodedRange` L702 量化补偿）；
- [`createShaders` L768](../packages/engine/Source/Scene/PointCloud.js#L768)：按 [`style`](../packages/engine/Source/Scene/PointCloud.js#L119)（[`makeStyleDirty` L264](../packages/engine/Source/Scene/TimeDynamicPointCloud.js#L264) 触发重建）生成样式 shader；Draco 解码 [`decodeDraco` L1166](../packages/engine/Source/Scene/PointCloud.js#L1166)；
- [`update` L1273](../packages/engine/Source/Scene/PointCloud.js#L1273)：模式切换的投影换算（2D/CV 下平移缩放模型矩阵，L1290-L1340）、`attenuation` 变化置脏（L1347）、样式重建、透明/不透明 pass 判定（L1386-L1390）后压入 commandList。

## 6. 粒子系统：CPU 模拟 + Billboard 上屏

[`ParticleSystem`](../packages/engine/Source/Scene/ParticleSystem.js#L58) 是**纯 CPU** 粒子引擎：每帧 JS 里积分每个粒子的位置/速度/生命周期，再逐粒子映射成一张 Billboard（GPU 只画公告板，见 §8）。构造参数极多但都成对出现（最小/最大区间随机采样）：

| 参数组 | 字段（构造锚点） | 说明 |
|---|---|---|
| 发射 | `emitter`（[L93](../packages/engine/Source/Scene/ParticleSystem.js#L93)，默认 ConeEmitter）、`emissionRate = 5`/s（[L114](../packages/engine/Source/Scene/ParticleSystem.js#L114)） | 每秒新增粒子数 |
| 寿命 | `minimumParticleLife`/`maximumParticleLife`（[L119-L120](../packages/engine/Source/Scene/ParticleSystem.js#L119)） | 单粒子寿命随机区间 |
| 速度 | `minimumSpeed`/`maximumSpeed`（[L116-L117](../packages/engine/Source/Scene/ParticleSystem.js#L116)） | 初速率区间 |
| 体积 | `minimumMass`/`maximumMass`（[L123-L124](../packages/engine/Source/Scene/ParticleSystem.js#L123)）、`minimumImageSize`/`maximumImageSize`（[L126-L129](../packages/engine/Source/Scene/ParticleSystem.js#L126)） | 质量（影响重力）与公告板尺寸 |
| 外观 | `startColor`/`endColor`（[L104-L107](../packages/engine/Source/Scene/ParticleSystem.js#L104)）、`startScale`/`endScale`（[L111-L112](../packages/engine/Source/Scene/ParticleSystem.js#L111)）、`image`（[L87](../packages/engine/Source/Scene/ParticleSystem.js#L87)） | 颜色/缩放沿寿命插值 |
| 空间 | `modelMatrix`（[L97](../packages/engine/Source/Scene/ParticleSystem.js#L97)）、`emitterModelMatrix`（[L98](../packages/engine/Source/Scene/ParticleSystem.js#L98)） | 双矩阵见下文 |
| 系统 | `loop`（[L80](../packages/engine/Source/Scene/ParticleSystem.js#L80)）、`bursts`（[L95](../packages/engine/Source/Scene/ParticleSystem.js#L95)）、`lifetime`（[L136](../packages/engine/Source/Scene/ParticleSystem.js#L136)）、`sizeInMeters`（[L134](../packages/engine/Source/Scene/ParticleSystem.js#L134)） | 循环/爆发/系统寿命/尺寸单位 |
| 回调 | `updateCallback`（[L73](../packages/engine/Source/Scene/ParticleSystem.js#L73)） | 自定义力场（每粒子每帧调用，官方篝火示例的风与 flicker） |

**双矩阵**是定位精髓：`modelMatrix` 定系统整体（如绑到某飞行器 ENU，[11 §ENU](11-坐标变换.md)），`emitterModelMatrix` 定喷口局部偏移与旋转；系统内每帧把二者相乘缓存 `_combinedMatrix`（[L102](../packages/engine/Source/Scene/ParticleSystem.js#L102)，`_matrixDirty` 置脏追踪），发射与积分都在合成矩阵空间完成，update 末段再变换回世界系（§7 图）。

## 7. update 主循环：从发射到 Billboard

[`ParticleSystem.update` L704](../packages/engine/Source/Scene/ParticleSystem.js#L704) 一帧六步：

```
update(frameState)
│ ① 懒建 _billboardCollection（L709-L710）
│ ② dt = frameState.time - _previousTime（L721，负数钳 0）
│ ③ 逐粒子：Particle.update(dt, updateCallback)（L732）
│      失败(寿命尽) → 回收进 _particlePool（updateParticlePool L509）
│      存活       → updateBillboard(system, particle)（L586）
│ ④ 补发射：calculateNumberToEmit(system, dt)（L666）
│      num = emissionRate·dt + 欠账余数；bursts 到点整发（loop 回绕时 _complete 复位 L815-L820）
│      每个新粒子：getOrCreateParticle（池里取或 new）（L549）
│        emitter.emit(particle)（§9）→ 区间随机 mass/speed/life/size
│        → 组合矩阵变换到世界系（L777-L800：position = M·(emit起点+velocity·t)，速度同向 normalize）
│        → updateBillboard
│ ⑤ _billboardCollection.update(frameState)（L807）   ← 真正产生 DrawCommand
└ ⑥ _currentTime += dt（L809）；系统寿命尽且 loop → 时间回绕（L811 起）
```

单粒子积分在 [`Particle`](../packages/engine/Source/Scene/Particle.js#L27)（数据类：`position`/`velocity`/`mass`/`life`/`startColor`→`endColor` 等，[L35-L89](../packages/engine/Source/Scene/Particle.js#L35)），核心是 [`Particle.prototype.update` L126](../packages/engine/Source/Scene/Particle.js#L126)：`life` 倒计时归一化出 `normalizedAge`，颜色/缩放按它插值（`colorForValue`/`scaleForValue` 可覆写），`updateCallback(dt, particle)` 在此插入自定义力学（重力/风力/浮力全靠它，引擎本体只提供寿命与初始速度）。

[`updateBillboard` L586](../packages/engine/Source/Scene/ParticleSystem.js#L586) 把粒子状态翻译成 billboard 属性：position/imageId/颜色/尺寸（`sizeInMeters` 决定 width/height 是否按米解释）；粒子回收时 [`removeBillboard` L580](../packages/engine/Source/Scene/ParticleSystem.js#L580) 归还 billboard，池清空时释放 GPU（`freeParticlePool` L563）。

## 8. 为什么快不起来：Billboard 底座与性能账

粒子系统的一切渲染都压在 [`BillboardCollection`](../packages/engine/Source/Scene/BillboardCollection.js) 上（[L709](../packages/engine/Source/Scene/ParticleSystem.js#L709) 懒建）：一个合批的公告板图元（顶点缓冲按 billboard 展平，[03 §Visualizer](03-Entity数据体系.md) 已述 BillboardVisualizer 复用它）。性能边界要心里有数：

- **每帧全量 CPU 遍历**：`particles.length` 个 JS 对象逐个积分 + 属性写回。千级粒子轻松，万级开始吃主线程（[16 §卡顿源](16-性能调试与优化.md)）；
- **属性写回即顶点缓冲脏**：位置/颜色逐帧变 → billboard 顶点数据逐帧重传（对比点云：静态顶点 + shader 衰减，CPU 近零成本）；
- **优化方向**：降 `emissionRate`/缩短 `life` 控制同时在场的粒子数；`image` 用小图集避免换纹理；量大且效果可公式化时迁 [09 §CustomPrimitive](09-几何图元与材质.md) 或 GPU 方案（官方 `SimpleSystem`/compute 粒子实验分支思路）。

一句话对比：**点云是「一次上传、GPU 反复画」，粒子是「CPU 每帧重算、Billboard 批量转卖」**——这是本篇两条路线最本质的分野。

## 9. 发射器家族与 ParticleBurst

发射器只干一件事：给定粒子对象，写入**局部空间**的初始 `position` 与 `velocity`（统一入口 [`emit(particle)`](../packages/engine/Source/Scene/ParticleEmitter.js#L19)，基类 [`ParticleEmitter` L19](../packages/engine/Source/Scene/ParticleEmitter.js#L19) 只定契约）：

| 发射器 | 形状与采样 | emit 锚点 |
|---|---|---|
| [`ConeEmitter`](../packages/engine/Source/Scene/ConeEmitter.js#L16) | 锥顶角内随机方向（默认喷泉） | [L46](../packages/engine/Source/Scene/ConeEmitter.js#L46) |
| [`CircleEmitter`](../packages/engine/Source/Scene/CircleEmitter.js#L14) | 圆盘内随机点、法向速度（篝火底座） | [L50](../packages/engine/Source/Scene/CircleEmitter.js#L50) |
| [`SphereEmitter`](../packages/engine/Source/Scene/SphereEmitter.js#L14) | 球体内随机点向外（爆炸球） | [L50](../packages/engine/Source/Scene/SphereEmitter.js#L50) |
| [`BoxEmitter`](../packages/engine/Source/Scene/BoxEmitter.js#L22) | 长方体内随机点（体积雾） | [L60](../packages/engine/Source/Scene/BoxEmitter.js#L60) |

[`ParticleBurst`](../packages/engine/Source/Scene/ParticleBurst.js#L14)（`time` L22 / `minimum` L28 / `maximum` L34）在系统时刻走到 `time` 时一次性喷射 `minimum~maximum` 个粒子（`_complete` 标记防止重复触发，系统 loop 回绕时统一复位，§7 ④）；`loop = false` 且 `lifetime` 到点后系统停止发射、存量粒子自然消亡，billboard 集合随后释放（[L826-L844](../packages/engine/Source/Scene/ParticleSystem.js#L826)）。

## 10. 动手实验与常见坑

### 动手实验

```js
// 实验 1：点云衰减与 EDL 的观感对比（§3/§4）
const tileset = await Cesium.Cesium3DTileset.fromIonAssetId(1642); // 官方点云资产示例 id
viewer.scene.primitives.add(tileset);
tileset.pointCloudShading.attenuation = true;    // 先开这个
tileset.pointCloudShading.maximumAttenuation = 4;
tileset.pointCloudShading.eyeDomeLighting = false; // 关掉 EDL 对比「沙感」
tileset.pointCloudShading.eyeDomeLightingStrength = 2.0; // 再拉强对比

// 实验 2：样式表达式给点云上色（§2）
tileset.style = new Cesium.Cesium3DTileStyle({
  color: "color('red', clamp(${POSITION}[2] / 100.0, 0.1, 1.0))",
});

// 实验 3：最小粒子系统（§6-§9）
viewer.scene.primitives.add(new Cesium.ParticleSystem({
  image: "./particle.png",
  emitter: new Cesium.ConeEmitter(Cesium.Math.toRadians(25)),
  emissionRate: 50,
  startColor: Cesium.Color.ORANGE.withAlpha(0.8),
  endColor: Cesium.Color.BLACK.withAlpha(0),
  startScale: 2, endScale: 0.5,
  minimumParticleLife: 1.0, maximumParticleLife: 2.5,
  updateCallback: (p, dt) => {          // 自定义重力
    Cesium.Cartesian3.multiplyByScalar(p.velocity, 0.99, p.velocity);
    p.velocity.z -= 9.8 * dt;
  },
}));

// 实验 4：时序点云帧跳看预取（§5）
const tdp = new Cesium.TimeDynamicPointCloud({ clock, intervals });
viewer.scene.primitives.add(tdp);
viewer.clock.multiplier = 60;   // 加速播放，观察 frameChanged 与偶发跳帧
```

### 常见坑

| 坑 | 真相 | 对策 |
|---|---|---|
| 点云拉近变稀疏「筛子」 | attenuation 没开，点恒定 1px | `pointCloudShading.attenuation = true`（§3） |
| EDL 开了没效果 | 门控要求 `attenuation && eyeDomeLighting` 同时为 true（§4） | 先开衰减 |
| `baseResolution` 告警/点大小异常 | tileset 缺 geometricError，自动推算失败 | 手动填 `baseResolution`（米/点） |
| 点云整体全黑/过暗 | normalShading 需要法线与光照方向（[17 §光照](17-天空光照与大气.md)），无法线数据时被 shader 屏蔽 | 关 `normalShading` 或调 `eyeDomeLightingStrength` 补立体感 |
| 时序点云播着播着跳帧 | 带宽跟不上 clock.multiplier，按策略跳过中间帧（§5） | 降倍速/压帧体积/接受跳帧 |
| 时序点云越播越卡 | 帧缓存涨破 `maximumMemoryUsage` 前的 LRU 滞后 | 调低上限或缩短 intervals |
| 粒子在 2D/CV 模式错位 | 粒子系统按 3D 世界系积分，2D 投影仅做平移缩放近似 | 粒子场景尽量锁定 SCENE_3D |
| 粒子颜色/大小不随时间变 | 写的是 `scale` 简写（构造期定值），运行时改需 `startScale/endScale` + `makeStyleDirty` 同思路 | 构造时给区间，运行时改 `_startScale` 等内部属性无效，应重建系统 |
