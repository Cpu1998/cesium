## 0. 全景：一条 DrawCommand 从 Primitive 到 gl.drawElements

```
 Primitive（09）                     Scene 编队（本文 §2）                Context（本文 §5）
┌──────────────────────┐  update   ┌───────────────────────────────┐ execute  ┌──────────────────────┐
│ createShaderProgram  │──────▶   │ frameState.commandList         │──────▶  │ Scene.executeCommand │
│ createVertexArray    │          │  （按 pass 字段分箱：View.      │          │  按帧开关换成变体：    │
│ new DrawCommand{     │          │   createPotentiallyVisibleSet  │          │  logDepth/hdr/pick/  │
│   va/sp/rs/uniforms, │          │   → insertIntoBin → 每视锥每   │          │  depth/shadows）     │
│   pass, boundingVol} │          │   Pass 一个数组）               │          │  ↓ command.execute   │
└──────────────────────┘          │ executeCommands 按 Pass 顺序扫 │          │ Context.draw         │
                                   │  ENV→COMPUTE→GLOBE→…→OPAQUE→  │          │  beginDraw: 绑 FBO/  │
                                   │  TRANSLUCENT→…→OVERLAY        │          │   RS/program         │
                                   └───────────────────────────────┘          │  continueDraw: 设    │
                                                                              │   uniform→绑 VAO→    │
                                                                              │   gl.drawElements    │
                                                                              └──────────────────────┘
```

三个设计要点先立住：

1. **命令是纯数据**：DrawCommand 不含逻辑，`execute` 只是转发（§1）；同一份 VAO/Program 可以被多条命令复用（09 的合批正靠此）。
2. **编队按 Pass 不按对象**：透明/不透明/贴地分类的绘制次序由 `command.pass` 决定，与对象类型无关——Globe、Model、Billboard 的命令混在同一个数组里排队。
3. **变体在执行前一刻替换**：拾取帧/对数深度/HDR 不重建命令，只在 `executeCommand` 入口换指针（§3）——08 的「pick pass 重画场景」成本因此可控。

## 2. Pass 编队：命令如何排队与执行

**通道枚举**（[`Pass.js` L17-L31](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Pass.js#L17-L31)）就是绘制次序表：

| 值 | 通道 | 干什么 |
|---|---|---|
| 0 | ENVIRONMENT | 天空盒/大气（先画，多视锥每层都画） |
| 1 | COMPUTE | GPGPU 计算命令（§6，不分视锥） |
| 2 | GLOBE | 地球本体（07） |
| 3 | TERRAIN_CLASSIFICATION | 等高线等贴地形效果 |
| 4–8 | CESIUM_3D_TILE_* | 3D Tiles 本体与贴 3D Tiles 分类（04） |
| 9 | OPAQUE | **不透明主通道**（early-z 优势，最大队） |
| 10 | TRANSLUCENT | 半透明（排序/OIT 特殊处理） |
| 11–12 | VOXELS / GAUSSIAN_SPLATS | 体素/高斯泼溅专道 |
| 14 | OVERLAY | IMAGELAYER 上的贴图叠加，最后画 |

**编队三步**（每帧）：

1. **收集**：[`updateAndRenderPrimitives` L3955](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3955) 依次调 `groundPrimitives/primitives.update`（Cesium3DTileset、Model、Billboard…）与 `globe.render`，各对象把命令 push 进 `frameState.commandList`。
2. **分箱**：[`View.createPotentiallyVisibleSet` L285](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L285) 遍历 commandList：`COMPUTE/OVERLAY` 单独出列；其余按 `boundingVolume` 与剔除体积（前 5 平面，去掉远平面）求交，算出命令的 near/far，交给 [`updateFrustums` L168](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L168) 拟合多视锥切分（06 §6 的多视锥由此落地），再由 [`insertIntoBin` L236](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L236) 把命令放进**每个相交视锥**的 [`FrustumCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrustumCommands.js#L13)（`commands[pass][index]` 二维数组），分箱末尾顺手 `scene.updateDerivedCommands(command)`（[L280](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L280)）预热变体。
3. **执行**：[`updateAndExecuteCommands` L3391](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3391)（[render 主链路 L4631](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4631) 调用）→ [`executeCommandsInViewport` L3667](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3667) → 逐视锥 [`executeCommands` L2796](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2796)。

`executeCommands` 内的通道次序（`performPass` 定义在 [L2845](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2845)，统一入口是 §3 的 `executeCommand`）：

```
renderEnvironment（视锥外先画天空，L3191）
 → Pass.GLOBE（L2898：先 clearGlobeDepth 再画，穿透地球深度处理）
 → TERRAIN_CLASSIFICATION → CESIUM_3D_TILE 分类/本体
 → Pass.OPAQUE（L3105：early-z 主力通道）
 → CESIUM_3D_TILE_EDGES_DIRECT / GAUSSIAN_SPLATS 专道
 → Pass.TRANSLUCENT（L2623 起：视锥间不重叠防混合重影；逐条按包围球
    远近排序 back-to-front［executeTranslucentCommandsBackToFront L2458］，
    OIT 可用时整队换成 oit.executeCommands）
 → executeOverlayCommands（L3265：画 IMAGELAYER 叠加）
```

拾取帧复用同一套编队：`executeIdCommand`（[L2398](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2398)）绕过调试钩子直画 pick 变体（08 §3）。

**多视锥分箱实例**：设相机 far=5e7，本帧命令 near/far 分布 [1e3,1e4]（近处飞机）与 [1e6,5e7]（地球）——`updateFrustums` 拟合出两个视锥（如 [1e3,3e4]、[3e4,5e7]），飞机只进第 1 个，地球两个都进（除非 `executeInClosestFrustum` 置位则只进最近的，[insertIntoBin 内 break，L264](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L264)）；远裁剪面拉近→深度精度↑，这正是 06 §6 多视锥的动机。命令没给 boundingVolume 时按相机最坏 near/far 处理（进所有视锥，[View.js L381 起](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L381)）——**漏填包围体积不是小 optimisation 损失，而是整个多视锥机制失效**。

## 3. derivedCommands：一条命令的多副面孔

同一个几何体，渲染帧画原色、拾取帧画 pickId、对数深度场景要写 logDepth、HDR 屏要色调映射、阴影要乘遮挡——**全部靠变体命令**，在 [`Scene.prototype.updateDerivedCommands` L1906](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L1906)（内部实现 [`updateDerivedCommands` L1814](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L1814)）派生，按 `dirty` 闸门（L1930-L1950：帧开关翻转或命令首次入队才重建）缓存在 `command.derivedCommands` 里：

| 变体键 | 派生工厂 | 与原命令的差异 |
|---|---|---|
| `picking` | [`createPickDerivedCommand` L315](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L315) | 片元输出换成 `v_pickColor`（重写 main，见 §4）+ pick 专用 RenderState |
| `depth` | [`createDepthOnlyDerivedCommand` L95](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L95) | 只写深度的极简 program（colorMask 全关） |
| `logDepth` | [`createLogDepthCommand` L231](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L231) | 给源码注入 `LOG_DEPTH` define（[getLogDepthShaderProgram L139](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L139) 用**正则探测**源码里有没有 `czm_vertexLogDepth` 调用，L136-L137） |

## 4. ShaderSource → ShaderProgram：GLSL 的拼装、注入与缓存

从一段 GLSL 字符串到可用 program 要过四道工序：

**① 拼装**：业务侧两条路。老 API 直接给字符串/ShaderSource（Primitive、Globe 走这）；新一代 Model 用 [`ShaderBuilder` L56](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L56)——[`addDefine` L120](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L120)/[`addUniform` L278](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L278)/[`addAttribute` L349](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L349)/[`addVarying` L379](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L379) 把着色器拆成「部件行」，[`buildShaderProgram` L470](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L470) 按 顶点/片元 × define/uniform/varying/struct/function 分桶 join 成两个 ShaderSource。

**② 合成**：[`combineShader` L155](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L155) 把多段源码并成一个大字符串：归置 `#version`/`#extension` 到顶部、摘除 precision 声明、每段源前插 `#line 0` 保住报错行号；拾取时按 `pickColorQualifier` 触发 [`createPickFragmentShaderSource` L450](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L450)——用 [`replaceMain` L363](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L363) 把 `main` 改名成 `czm_pick_main`，再包一层新 `main` 只输出 `gl_FragColor = v_pickColor`（08 §2 颜色编码的着色器侧真相）。

**③ 内置注入**：[`getBuiltinsAndAutomaticUniforms` L138](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L138) 对源码做**依赖图拓扑排序**——从 `main` 出发扫用到的 `czm_*` 函数（[`getDependencyNode` L23](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L23) 递归找它依赖的其它 czm 函数，[`sortDependencies` L87](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L87) 排序），**按需**把函数体粘进最终源码（`_czmBuiltinsAndUniforms` 表在 [L414 起](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js#L414) 注入自 CzmBuiltins 合集）。所以你在 GLSL 里随手写 `czm_modelViewProjection * position` 就能编译——依赖的声明都是这里递归补齐的。

合成后的最终字符串形状（自上而下）：

```glsl
#extension GL_OES_standard_derivatives : enable   // ② 归置到顶部的扩展
precision highp float;                             // ② 统一注入的 precision
#define LOG_DEPTH                                   // defines（①拼装阶段收集）
uniform mat4 czm_model;  uniform mat4 czm_viewProjection;  // ③按需注入的自动 uniform
vec3 czm_phong(...) { ... }                        // ③拓扑排序后的内置函数体
                                                    //   （依赖者先声明，被依赖者在前）
attribute vec3 position;                            // 原始源码（每段前有 #line 0）
void main() { gl_Position = czm_modelViewProjection * vec4(position,1.0); }
```

排在最后的是你写的 main；改一处 define 即产生一个**新的 cacheKey**（defines 是键的一部分）——这正是变体工厂用 define 开关而非字符串拼接改源码的原因（④级缓存友好）。

**④ 缓存与编译**：[`ShaderCache.getShaderProgram` L75](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderCache.js#L75) 用 [`ShaderSource.getCacheKey` L377](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L377)（defines 排序 + 源码全文 + attributeLocations）做键——**命中即免做 ②③ 的昂贵字符串加工**；miss 才 `createCombinedVertexShader/FragmentShader`（[L395/L406](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L395)）并 `new ShaderProgram`（引用计数：`cachedShader.count`，`replaceCache` [L75](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L75) 在计数归零时释放 GL program——Primitive 每帧覆写 `primitive._sp` 用的正是它，[Primitive.js L1746](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1746)）。Context 持有全局缓存：[`_shaderCache = new ShaderCache(this)` L89](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L89)。[`ShaderProgram` L17](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L17) 本体**懒编译**（首次 `_bind` 才 link），uniform 分两类（见下节）。

## 5. 两种 uniform：automatic 与 manual

[`ShaderProgram._setUniforms` L546](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L546) 每次绘制前刷新两族 uniform：

- **automatic（`czm_*`）**：编译期由 [`createUniform.js` L21](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/createUniform.js#L21) 识别并绑定到 [`AutomaticUniforms.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js) 注册表，取值函数拿 [`UniformState`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/UniformState.js) 快照：`czm_model`（[L264](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L264)，值 = 本命令 modelMatrix，由 Context 在 continueDraw 里写进 `_us.model`）、`czm_view` L313、`czm_projection` L509、`czm_inverseProjection` L532、`czm_viewProjection` L728、`czm_modelViewProjection` L783、`czm_viewportTransformation` L135（11 §7 的落点）、`czm_frameNumber` L1472、`czm_pass` L1539（当前通道号，pass 切换时由 `uniformState.updatePass` 更新——[Scene.js L3244](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3244) 等）。
- **manual（`u_*`）**：来自命令的 `uniformMap`——业务提供的「名字→工厂函数」表，`_setUniforms` 逐个**调用函数**取值（惰性：只在本次绘制真的用到才求值）；采样器类由 [`setSamplerUniforms` L444](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L444) 统一绑纹理单元并记录 `maximumTextureUnitIndex` 防超限。

## 6. Context.draw：三步终点站

[`Context` L48](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L48) 是对 `WebGL2RenderingContext` 的全权包装（构造于 Scene 初始化期，01 §3），持有 shaderCache（L89）、[`uniformState` L344](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L344)、以及 VAO 工厂（[`glCreateVertexArray` L238](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L238) 起）。[`Context.prototype.draw` L1414](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1414) 把一条命令拆成两步：

## 9. 常见坑

- **`pass` 决定次序而不是 z 值**：两个不透明命令的先后只由 Pass 号定（同 Pass 内不保证次序）；想让 B 永远画在 A 之上要靠深度测试或拆 Pass，别指望「后 add 先画」。
- **透明对象别塞 OPAQUE**：TRANSLUCENT 通道才有逐命令排序与 OIT；`pass` 填错通道会出现时隐时现的混合顺序错误。
- **uniformMap 是函数表不是值表**：`uniformMap: { u_time: () => clock.currentTime }` 每帧绘制时重新求值；写成常量对象会导致「改了不生效」。
- **变体按需重建有闸门**：`dirty` 只在帧开关变化或首次派生时触发（L1930-L1950）；直接改命令的 shaderProgram/renderState 后**必须置 `command.dirty = true`**，否则 pick/logDepth 变体还挂着旧 program。
- **RenderState 走缓存**：`RenderState.fromCache` 以**内容**为键全局复用；每次 new 字面量不浪费 GL 状态对象但会绕过缓存去重——高频路径请把 fromCache 的结果存成员变量（Primitive 的 `_frontFaceRS` 即此，[L1690](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1690)）。
- **ShaderCache 键含源码全文**：字符串里任何一字符不同（哪怕注释）都是新 program；频繁拼 shader 字符串 = program 洄泄，`numberOfShaders` 是第一现场指标。
- **ComputeCommand 的 outputTexture 尺寸即"计算规模"**：它没有顶点数据，全屏四边形像素数就是要算的元素数；输出纹理用完记得释放，否则离屏 FBO 堆积。
