# 13 · 渲染命令与着色器

> 阅读前提：读过 [05-帧更新与渲染循环](05-帧更新与渲染循环.md)（一帧怎么跑）、[09-几何图元与材质](09-几何图元与材质.md)（Primitive 合批）、[08-拾取系统](08-拾取系统.md)（pick 派生命令）。
> 一句话：**Renderer 层的两根支柱——DrawCommand（把一次 draw 封装成可延迟、可派生的对象）与 ShaderSource/ShaderBuilder（把 GLSL 片段 + 内置函数/自动 uniform 拼成最终着色器）；本篇把「一条命令从出生到 `gl.drawElements`」整条管线走完。**

本文讲什么：

- 命令对象：[`DrawCommand.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js)、[`ClearCommand.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ClearCommand.js)、[`ComputeCommand.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ComputeCommand.js)
- 着色器装配：[`ShaderSource.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js)、[`ShaderBuilder.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderBuilder.js)、[`ShaderProgram.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js)、[`ShaderCache.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderCache.js)、[`AutomaticUniforms.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js)
- 终点站：[`Context.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js) 的 draw、[`VertexArray.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/VertexArray.js)、[`RenderState.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/RenderState.js)
- 编排层：[`Scene.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js) 的 pass 顺序与 [`DerivedCommand.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js) 派生体系

## 0. 全景：一条 DrawCommand 从 Primitive 到 gl.drawElements

```
【构建期】(通常只发生一次，见 09-几何图元与材质 §3)
Primitive.update L2079 ─ loadSynchronous L1309
  ├─ createVertexArray L1622 ─ VertexArray.fromGeometry L575
  │     └─ Buffer.createVertexBuffer L135 / createIndexBuffer L194
  │        （顶点 ≥64K 且支持 uint 索引 → Uint32Array 索引 L699）
  └─ createCommands L1842 ─ new DrawCommand{ vertexArray, shaderProgram,
        uniformMap, renderState: RenderState.fromCache(...), pass }
        shaderProgram = context.shaderCache.getShaderProgram(
          new ShaderSource({sources/defines/pickColorQualifier}))   ← §3

【每帧】(05-帧更新与渲染循环 §2 的画帧阶段)
Scene.updateAndExecuteCommands L3391
  └─ updateAndRenderPrimitives L3955   ← 各 Primitive.update 把命令 push 进 commandList
  └─ executeCommands L2796             ← 视锥剔除 + 按 Pass 枚举顺序执行（05 §5）
        │  对每条命令:
        ├─ scene.updateDerivedCommands(command) L1906   ← §5：按帧开关派生变体
        ├─ executeCommand L2291 ─ 变体切换(logDepth/hdr/pick/depth/snap/shadow)
        └─ command.execute(context, passState)  DrawCommand L676
              └─ Context.draw L1414                   ← §4
                    ├─ beginDraw L1303  bindFramebuffer L1240 / applyRenderState L1213
                    │                  / shaderProgram._bind L541
                    ├─ continueDraw L1330  _us.model ← command.modelMatrix L1359
                    │                  _setUniforms L546 (uniformMap求值+自动uniform)
                    │                  va._bind L884
                    └─ gl.drawElements / gl.drawArrays L1377/L1400  ← 终点
```

记住三个分层：**Scene 层**（决定「什么时候、以什么变体画」）、**Command 层**（封装「画什么」的全部参数）、**Context 层**（把参数翻译成一串裸 gl 调用）。

## 1. DrawCommand：一次 draw 的参数包

[`class DrawCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L76)（文件头【导读】即「一次 draw 的参数包」）本质是把 `gl.drawXXX` 需要的全部状态装进对象——**构建时只存参数，不碰 WebGL**；执行时一次性消费。字段到 GPU 状态的映射：

| 字段（getter） | 定义行 | 落到哪 |
|---|---|---|
| `vertexArray` | [L267](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L267) | VAO 绑定（§4 continueDraw） |
| `shaderProgram` | [L335](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L335) | `gl.useProgram` + uniform 上传 |
| `uniformMap` | 构造参数 | `_setUniforms` 里逐个求值（§3.4） |
| `renderState` | [L404](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L404) | 深度测试/混合/模板/剔除（§4.3） |
| `pass` | [L438](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L438) | 决定执行顺序与视锥分桶（§5.1） |
| `modelMatrix` | [L233](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L233) | `czm_model` 自动 uniform（§3.3） |
| `boundingVolume` | [L157](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L157) | 视锥剔除输入（不进 GPU） |
| `instanceCount` | [L318](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L318) | instanced draw 变体 |
| `owner` | [L478](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L478) | 调试用归属（`debugCommandFilter`） |

三个设计点：

- **位标志**：阴影投/受投、剔除、pick-only 等 8 个布尔压进 [`Flags`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L29) 位掩码（`CULL:1`/`OCCLUDE:2`/`CAST_SHADOWS:16`/`RECEIVE_SHADOWS:32`/`PICK_ONLY:64`…），getter/setter 走 `hasFlag`/`setFlag`，省内存且 clone（浅拷贝+flags 整体复制）便宜。
- **`derivedCommands = {}`**（[L140](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L140)）：命令自己不生成变体，Scene 把 pick/depth/logDepth/hdr/shadow 变体**挂在它身上**（§5.2）；配 `dirty`/`lastDirtyTime`（[L134](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L134)）供派生缓存失效。
- **execute 只有一行**（[L676](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/DrawCommand.js#L676)）：`context.draw(this, passState)`——所有「何时/何种变体」的智慧都在 Scene 侧。

命令家族三兄弟：`DrawCommand`（画几何）、[`ClearCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ClearCommand.js#L10)（清缓冲，execute 走 [Context.clear](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1258)）、[`ComputeCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ComputeCommand.js#L10)（GPU 计算，§5.3）。

## 2. 命令的出生：Primitive 侧怎么攒参数

以 [09 §3](09-几何图元与材质.md) 的 Primitive 为例（3D Tiles/Model/地形瓦片同构）：

1. **VAO**：[`createVertexArray`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1622) → [`VertexArray.fromGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/VertexArray.js#L575)：逐 attribute 建 [`Buffer.createVertexBuffer`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Buffer.js#L135)；索引按顶点数选 16/32 位——**顶点数 ≥ 65536 且 context 支持 `elementIndexUint` 才用 Uint32**（[L699](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/VertexArray.js#L699)），否则被迫 16 位（超限几何会被拆批）。`instanceDivisor` 在这里进 VAO（instanced rendering）。
2. **着色器**：把 [`ShaderSource`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L332)（sources + defines + pick 变体标记）交给 [`context.shaderCache.getShaderProgram`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderCache.js#L75)（Context 构造时建 cache，[L89](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L89)）——**编译/链接只发生一次，之后按 cacheKey 复用**（§3.4）。
3. **RenderState**：[`RenderState.fromCache`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/RenderState.js#L461)——把「深度开+混合关」这类 JS 对象**两级 key**（partial JSON → 补全默认值后的 full JSON）查缓存，命中就引用计数 +1；每条命令持有的其实是全局共享的冻结实例（§4.3）。
4. **pass**：[`createCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1842) 按外观透明度定 `translucent ? Pass.TRANSLUCENT : Pass.OPAQUE`，两遍 translucent（twoPasses）时命令翻倍。

这条链每帧不动（除非 `dirty`）；每帧流动的只是命令引用本身。

## 3. 着色器装配线：ShaderSource → 拼接 → ShaderProgram

### 3.1 ShaderSource：声明式的「着色器材料表」

构造器（[`L332`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L332)）收 `sources[]`（多段 GLSL，支持伪多态如 `czm_getMaterial`）、`defines[]`（uber-shader 宏）、`pickColorQualifier`（给了就自动生成 pick 变体）。真正的拼接在私有函数 [`combineShader`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L155)（`createCombinedVertexShader`/[`createCombinedFragmentShader`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L406) 各调一次），固定顺序：

```
#version 300 es                    ← WebGL2 前置（L300；WebGL1 反向 demodernize L298）
#extension …                       ← 从源里抽出的扩展，提前（L175 起）
precision highp …（含 highp→mediump 降级宏）
内置函数 + 自动 uniform 声明        ← getBuiltinsAndAutomaticUniforms（L138→combineShader L273）
#define …（defines[]，uber-shader）  ← L250-L256
czm_pickColor 变体改写（可选）       ← createPickFragmentShaderSource L450（pick pass 用，08 §4）
layout(location=0) out vec4 out_FragColor;  ← GLSL3 输出声明（L287 起，替换 gl_FragColor）
#line 0\n + 用户 sources[]          ← 多段源拼接，#line 保行号（L162）
```

去注释（[`removeComments`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L8)）先做——防止注释里的 `#define` 干扰抽取。**源码里写的是 GLSL3 风格，WebGL1 路径靠 [`demodernizeShader`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L298)（in/out→attribute/varying 等）降级**，所以 Cesium 引擎内 shader 不用写两份。拼好的字符串进 [`ShaderProgram`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L17)；[`getCacheKey`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L377) 让「同源同 defines」在 ShaderCache 里只编译一次。

### 3.2 内置依赖扫描：`czm_*` 是怎么注入的

[`getBuiltinsAndAutomaticUniforms`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L138) 对拼接后的源跑正则扫描所有 `\bczm_[a-zA-Z0-9_]*` 标识：[`generateDependencies`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L52) 递归展开（内置函数又可能引用别的内置，[L81](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L81)），[`sortDependencies`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L87) 拓扑排序保证被依赖者在前，**只把用到的内置打进最终源**（死代码不进编译器）。

可用清单在模块加载时合并进 [`_czmBuiltinsAndUniforms`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L414)：一是 `CzmBuiltins`——**构建期从 [`Shaders/Builtin/Functions|Structs|Constants`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Shaders/Builtin/Functions/phong.glsl) 下的 .glsl 打包生成的 JS 模块**（源码树里搜不到 CzmBuiltins.js，它是构建产物）；二是 [`AutomaticUniforms`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js) 的声明文本。常用自动 uniform：

| uniform | 定义行 | 内容 |
|---|---|---|
| `czm_model` | [L264](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L264) | 命令的 modelMatrix（世界矩阵） |
| `czm_view` / `czm_projection` | [L313](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L313) / [L509](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L509) | 视图/投影矩阵 |
| `czm_viewProjection` / `czm_modelViewProjection` | [L728](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L728) / [L783](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L783) | 合并矩阵（顶点着色器只乘一个） |
| `czm_inverseProjection` | [L532](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L532) | pickPosition 深度复原用（[08 §6](08-拾取系统.md)） |
| `czm_viewportTransformation` | [L135](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/AutomaticUniforms.js#L135) | NDC→窗口（[11 §5](11-坐标变换.md)） |

**值从哪来**：[`UniformState`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/UniformState.js)（Context 构造时 `new`，[L344](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L344)）每帧被 [`update(frameState)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/UniformState.js#L1486)（+[`updateCamera`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/UniformState.js#L1422)/[`updateFrustum`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/UniformState.js#L1443)）填满相机/太阳/时间等帧级状态；命令级 `czm_model` 则在 draw 时单独注入：[`continueDraw` 里 `context._us.model = drawCommand._modelMatrix`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1359)——「帧级状态一次算，命令级状态换算时覆盖」是 Renderer 的核心分工。

### 3.3 pick 变体：同一段源改写出拾取版

给了 `pickColorQualifier` 时，[`createPickFragmentShaderSource`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L450) 用 [`replaceMain`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L363)（把用户 `main` 改名 `czm_pick_main`，插一段新 main：先调原 main，再把输出替换成 `czm_pickColor`）生成拾取专用片元源；配套 [`createPickVertexShaderSource`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L433)、法线/位置 varying 探测（[`findNormalVarying`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderSource.js#L507)）。这就是 [08 §4](08-拾取系统.md)「pick pass 里命令都换成 czm_pickColor 输出」的源头。深度版同理更极端——干脆替换整个 main 只写深度（[DerivedCommand.getDepthOnlyShaderProgram](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L21)，先正则探测源里有没有 `gl_FragDepth`/`discard` 决定是否需要派生）。

### 3.4 ShaderProgram 与缓存

[`ShaderProgram`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L17) 惰性编译（首次 `_bind` 才 [`initialize`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L458)：compile+link+反射 active uniform 列表）。执行期的 [`_setUniforms`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L546) 干两件事：普通 uniform 逐个调 uniformMap（用户回调函数）取值上传；**sampler（纹理）先走 [`setSamplerUniforms`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderProgram.js#L444) 统一分配纹理单元**（记进 `maximumTextureUnitIndex`，供 Context 追踪单元上限）。自动 uniform（czm_model 等）不占 uniformMap——它们的求值函数直接从 UniformState 现取。

[`ShaderCache`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderCache.js#L9) 以 cacheKey（源+defines+attribute 位置）为键复用 program；派生变体用 [`getDerivedShaderProgram`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ShaderCache.js#L168)（原始 program + 变体名再缓存一层）——所以开阴影/拾取不会导致重复编译。

### 4.2 几何提交（continueDraw，[L1330](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1330)）

`_us.model` 注入（[L1359](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1359)）→ `_setUniforms` → `va._bind()`（[L884](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/VertexArray.js#L884)，含 ANGLE 的 divisor workaround）→ 分流：

### 4.3 RenderState：冻结共享 + 双层缓存

[`function RenderState`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/RenderState.js#L91) 把 12 组子状态（cull/depthTest/depthMask/blending/stencilTest/scissor/viewport…）按 `?? 默认值` 补全成完整对象。[`fromCache`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/RenderState.js#L461) 的两层 key 设计（partial JSON 先查、miss 则补全后再查 full JSON 并同时登记两个 key）保证：**不同命令写不同粒度的「局部状态」也共享同一份完整实例**，partialApply 的 diff 前提（对象可比较、内容寻址）因此成立。[`removeFromCache`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/RenderState.js#L496) 引用计数归零才真删。

另外两个 Context 门面值得记住：[`createPickId`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1698)/[`getObjectByPickColor`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1671) 是拾取注册表（[08 §3](08-拾取系统.md)）；[`getViewportQuadVertexArray`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1599)/[`createViewportQuadCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1637) 造全屏三角形 quad——后处理与 ComputeCommand 的地基。

## 5. Scene 编排：pass 顺序与派生命令

### 5.1 Pass：15 档固定顺序

[`Pass`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Pass.js#L17)（ENVIRONMENT 0 → COMPUTE 1 → GLOBE 2 → TERRAIN_CLASSIFICATION 3 → CESIUM_3D_TILE_* 4–8 → OPAQUE 9 → TRANSLUCENT 10 → VOXELS 11 → GAUSSIAN_SPLATS 12 → … → OVERLAY 14）不是「多趟渲染」的趟，而是**单趟内的执行顺序**：[`executeCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2796) 依序消费，OPAQUE 先画吃满 early-z，TRANSLUCENT 按视锥远→近排序画（细节在 [05 §5](05-帧更新与渲染循环.md)）。命令进桶靠 [`View`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L42)：[`updateFrustums`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L168) 切多视锥，[`insertIntoBin`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L236) 按包围球覆盖区间把命令塞进各视锥的 [`FrustumCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrustumCommands.js#L13)（每视锥 × 每 pass 一个数组）。总入口 [`updateAndExecuteCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3391) → [`executeCommandsInViewport`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3667)；命令收集步 [`updateAndRenderPrimitives`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3955) 遍历 PrimitiveCollection（含 Globe/3D Tiles，见 05 §9 对照表）。

### 5.3 ComputeCommand：老派 GPGPU

[`ComputeCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ComputeCommand.js#L10) 的 `pass` 恒为 `Pass.COMPUTE`（最先执行）；[`execute`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ComputeCommand.js#L116) 转交 [`ComputeEngine.execute`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/ComputeEngine.js#L63)：没有 compute shader 的年代，Cesium 用 **viewport quad + 片元着色器渲染进纹理** 实现计算（`outputTexture` 当输出，`preExecute`/`postExecute` 前后钩子读写资源，`persists=false` 用完即毁）。典型用户：影像重投影（[05 §10](05-帧更新与渲染循环.md)）、waterMask、部分阴影处理。

## 6. 速查：一次 draw 的完整开销清单

```
每条命令的固定成本              来源
─────────────────────────────────────────────────────
uniformMap 求值                 _setUniforms（回调逐个执行——uniformMap 写得烂会掉帧）
纹理单元分配                    setSamplerUniforms（每条命令一次）
FBO / RenderState / program 切换 beginDraw（相同则 0 次 gl 调用）
va._bind                       有 VAO 时 1 次 bindVertexArray
drawElements/drawArrays        1 次（+instanced 变体）
```

调优抓手：**减命令数**（合批见 [09 §3](09-几何图元与材质.md)）、**减状态切换**（同材质同 RenderState 排在一起，OPAQUE 天然受益）、**减 uniformMap 开销**（回调里别做分配/查询，返回缓存值）。观察工具：`scene.debugCommandFilter`（按 owner 过滤打印每条命令）、`command.debugShowBoundingVolume`（画包围球）、`scene.debugShowFrustums`（视锥命中计数，insertIntoBin 里累加）。

// ① 抓一条真实命令看字段
const scene = viewer.scene;
let inspected = 0;
const old = scene.debugCommandFilter;   // 每条命令执行前都会问它
scene.debugCommandFilter = (command) => {

// ③ 看 shaderCache 里最终拼好的 GLSL（含注入的 czm_* 内置）
const program = scene.primitives.get(0)?._commands?.[0]?.shaderProgram; // Primitive 路径
console.log(program?.vertexShaderSource?.sources?.[0]?.slice(0, 2000));

// ④ 强制日志深度观察变体切换：viewer.scene.logarithmicDepthBuffer = true

## 8. 常见坑

- **uniformMap 是每帧每命令执行**：里面写 `new`/深查询（如每帧算 EllipsoidGeodesic）是隐形帧率杀手；返回值能缓存的缓存。
- **改 RenderState 对象无效**：cache 出来的是冻结共享实例，改字段污染所有同 key 命令；要改就 `RenderState.fromCache(新对象)`。
- **defines 是 cacheKey 的一部分**：动态拼 defines 字符串会碎掉 ShaderCache（每次都新 program）；宏集合应当有限且稳定。
- **pass 不能随手改**：TRANSLUCENT 命令画进 OPAQUE pass 会因顺序错乱出现「透明物遮挡错误」；反过来则丢混合。渲染顺序是 pass + 视锥排序共同决定的。
- **64K 顶点阈值**（§2）：geometry 顶点数刚好过 65536 又不支持 uint 索引时会走拆批/降精度路径，排查「大几何突然变慢/碎裂」先想到它。
- **derivedCommands 里的才是真画的**：debug 时直接改原始 command 的 shaderProgram 可能发现「没生效」——pick/logDepth/HDR 帧里执行的是变体。
- **ComputeCommand 输出纹理的生命周期**：`persists=false` 执行完即毁，想留着读结果必须 persists=true 并自己管理销毁。

## 9. 小结与交叉引用

- DrawCommand = 一次 draw 的参数包；构建在 Primitive（09）/Model/地形瓦片（07）各自 update 期，执行统一过 Scene 编排（05）与 Context 翻译。
- 着色器三段式：ShaderSource/ShaderBuilder 声明 → combineShader 拼接（内置 czm_* 按需拓扑注入、pick/depth 变体改写、WebGL1 自动降级）→ ShaderCache 复用编译结果。
- Renderer 的性能哲学：**能缓存的全缓存**（program、renderState、VAO、纹理单元），**能跳过的全跳过**（同状态不重绑），**用变体而非分支**（derivedCommands 换命令，不往 shader 里塞 if）。
- 与拾取（08 §4 pick 变体）、坐标（11 §3.3 自动 uniform 从 UniformState 取值）、帧循环（05 §5 pass 编排）互为表里——建议回读这三处再串一遍。

至此 00–13 十四篇成体系：从 `new Viewer()` 到 DOM 事件（12）到一条 draw 的终点（本篇），主线闭环。可继续深挖：OIT/`GlobeDepth` 深度拷贝链、Model/glTF 的 PipelineStage 装配（ShaderBuilder 的最大用户）、ShadowMap 级联。
