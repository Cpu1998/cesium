## 1. 方法论：先分层测量，再动参数

卡顿排查最忌「感觉慢就调 maximumScreenSpaceError」。1.145 的测量工具按「帧级 → 场景级 → 资源级」分三层：

```
帧级（这帧为什么久）      场景级（谁在吃资源）         资源级（哪个对象贵）
────────────────        ─────────────────           ─────────────────
debugShowFramesPerSecond  CesiumInspector（视锥/瓦片）  model.statistics
FrameRateMonitor          debugShowCommands/命令染色   tileset.statistics
（低帧率事件）             debugShowFrustums 剔除统计   totalMemoryUsageInBytes
Chrome DevTools 性能面板   debugShowBoundingVolume     ResourceCacheStatistics
```

帧级定位「慢在 CPU 提交还是 GPU 光栅」；场景级定位「剔除是否失效、命令是否爆炸」；资源级定位「该删哪个模型/瓦片集」。三层各有一组源码锚点，下文逐层展开。

排查决策树（先问现象再选工具）：

```
卡顿现象？
├─ 一直低帧 → 命令数多吗（debugShowCommands）？
│    ├─ 多 → 降 SSE/合批/关特效（§6/§7/§10/§11）
│    └─ 少 → GPU 带宽：像素比/MSAA/阴影（§10）
├─ 周期性尖刺 → 加载尾帧？drillPick 裸调？（§9/§11）
│    └─ 用 FrameRateMonitor 埋点对时间轴（§3）
├─ 静止时也烧 GPU → requestRenderMode 开了吗（§2）
└─ 越用越卡 → 内存三本账看涨不落（§5）
```

## 2. requestRenderMode：按需渲染

静态场景（无动画、无瓦片加载）下每帧重画纯烧电。开启 [`requestRenderMode`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L694)（构造参数，文档 [`L125`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L125)；[`CesiumWidget` 同名选项 L194、透传 L358](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L194)）后，rAF 循环照转但 [`Scene.render` 的 shouldRender 判定](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L92-L96)只放行「脏」帧。脏的来源（[05 §requestRenderMode](05-帧更新与渲染循环.md) 已画时序）：

- 显式调 [`scene.requestRender()`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4795)：改属性、Entity 动画、`camera.moveEnd` 等内部都会调；
- 相机在动（每帧自动标脏）；
- 模拟时间跳变超过 [`maximumRenderTimeChange`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L712)（默认 0.0=不变动就不画，判定点 [`L4709`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4709)）；
- **异步资源在途时自动补帧**：Globe/3D Tiles/Model 加载中往 `frameState.afterRender` 塞 `() => true`（如 [`Scene.js L100-L102` 的 requestSceneRender 工具](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L100-L102)；Model 侧见 [15 §1](15-Model与glTF加载.md)）——所以开按需渲染**不会**让瓦片加载卡成幻灯片。

**坑**：自定义交互（拖 DOM 覆盖层、改 CSS）不会自动标脏，改完必须 `scene.requestRender()`；忘了就会出现「数据变了画面没变」的经典工单。

脏来源速查（完整时序图见 [05 §requestRenderMode](05-帧更新与渲染循环.md)）：

| 来源 | 自动标脏？ | 锚点 |
|---|---|---|
| 相机在动（每帧 moveStart→moveEnd 区间） | ✅ | [05 §帧旅程](05-帧更新与渲染循环.md) |
| 模拟时间跳变超 `maximumRenderTimeChange` | ✅（阈值可调） | [Scene L4709](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4709) |
| Globe/3D Tiles/Model 资源在途 | ✅（afterRender 挂 `()=>true`） | [Scene L100-L102](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L100-L102) |
| 改 Entity/材质/样式等 API | ✅（各自内部调） | [03](03-Entity数据体系.md)、[15 §6](15-Model与glTF加载.md) |
| 自改 DOM/CSS/非 Cesium 对象 | ❌ 必须手动 | [Scene L4795](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4795) |

## 3. 帧率观测三件套

1. **内建 FPS 面板**：[`scene.debugShowFramesPerSecond = true`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L491)，每帧末尾在 canvas 旁更新 DOM（[`L4505-L4507` 的构造分支](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4505-L4507)），同时给出帧耗时（绿=快）。零依赖、适合现场快速看趋势。
2. **[`FrameRateMonitor`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L31)**：程序化帧率监控。内部维护 `_frameTimes` 时间戳数组，[update()](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L303) 每帧推进：滑出 [`samplingWindow`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L19)（默认 5s）的样本丢弃，窗口均值低于 [`minimumFrameRateDuringWarmup=4` / `minimumFrameRateAfterWarmup=8`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L24-L27)（FPS！）就触发 [`lowFrameRate` 事件（L83）](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L83)，恢复则发 `nominalFrameRate`。**用它做自动化埋点**：

   ```js
   // Scene 不自动创建；用 fromScene 惰性单例（定义 L168）：
   const monitor = Cesium.FrameRateMonitor.fromScene(scene);
   monitor.lowFrameRate.addEventListener((monitor, avg) =>
     report({ avgFps: avg, camera: scene.camera.positionCartographic })
   );
   // 场景切换/加载页可临时停采集，避免误报：
   monitor.pause();   // 定义 L243
   monitor.unpause(); // 定义 L257
   ```

   构造可调项一览（`new FrameRateMonitor({...})`，也可改 `FrameRateMonitor.defaultSettings` 全局默认）：

   | 选项 | 默认 | 语义 |
   |---|---|---|
   | `quietPeriod` | 3.0s | 静默期：初始化尖峰不算数 |
   | `warmupPeriod` | 5.0s | 预热期阈值用更宽松的 warmup 值 |
   | `samplingWindow` | 5.0s | 滑动窗口宽度 |
   | `minimumFrameRateDuringWarmup` | 4 FPS | 预热期低帧线 |
   | `minimumFrameRateAfterWarmup` | 8 FPS | 正式期低帧线（线上埋点建议按业务基线调高） |
3. **[`PerformanceWatchdog`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/PerformanceWatchdog/PerformanceWatchdog.js)**：Viewer 自带的低帧率提示条——[`ViewModel` 订阅 monitor.lowFrameRate`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/PerformanceWatchdog/PerformanceWatchdogViewModel.js#L66)，弹 [`lowFrameRateMessage`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/PerformanceWatchdog/PerformanceWatchdogViewModel.js#L18)（可自定义文案/关闭），适合给非技术用户一个「卡了请升级浏览器」的出口。

分工：面板看「现在」、Monitor 记「过程」、Watchdog 管「兜底告知」。

## 5. 内存三本账：谁在吃显存/内存

⚠️ 1.145 实况：不存在 `Renderer/Statistics.js` 这种「VAO/纹理计数」类（旧版资料常提）；GPU 对象级统计走 `Context.js` 的内部簿记（如 `context.shaderCache`），日常排查以上三本账为主。

## 9. 拾取：为什么 pick 一帧顶十帧渲染

拾取不是「查个像素」——它要**把候选命令以 pick 着色器重画一遍**（pick pass + pickId 解码，机制见 [08-拾取系统.md](08-拾取系统.md)）：

- [`scene.pick(windowPosition)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4833)（实现 [`Picking.js L419`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L419)）：一次 pick O(全部可见命令)；**别放 mousemove 里裸调**——节流（如 50ms）或改 click 触发。
- [`scene.drillPick`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L5126)（实现 [`Picking.js L943`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L943)，内部循环 [`drillPick L895`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L895)）：**每一层都是一次完整 pick**（把已命中的藏起来再 pick），limit 不传 = `Number.MAX_VALUE`（[`L895` 函数内默认值逻辑](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L895)）——重叠瓦片场景会雪崩。传 `drillPick(pos, 3)` 限层是最便宜的修复。
- [`scene.pickPosition`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L5103)：从深度缓冲取世界坐标，需 WebGL 深度纹理（能力探测 [`pickPositionSupported L917`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L917)）；它依赖 globe depth pass（[13 §GlobeDepth](13-渲染命令与着色器.md)），半透明物体会污染深度——排障时先关半透明。
- 宽窗口 pick（`pick(pos, width, height)`）：pick framebuffer 只重画窗口区域，但窗口越大候选命令越多，**扩窗拾取比定点拾取贵得多**，能用 1×1 就别 5×5。
- [`scene.pickFromRay`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L1267)（内部实现 [`pickFromRay L1224`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L1224)）/[`drillPickFromRay L1280`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L1280)：射线拾取同样走 pick pass，与屏幕拾取同价；`mostDetailed` 变体会等最精细瓦片（离线场景用，交互路径别开）。

生产级节流模板（交互拾取只认最后一击 + 限频）：

```js
let pending = null, last = 0;
handler.setInputAction((movement) => {
  const now = performance.now();
  if (now - last < 50) { pending = movement.endPosition; return; } // 50ms 限频
  last = now; pending = null;
  const picked = scene.pick(movement.endPosition, 1, 1); // 显式 1×1
  // drillPick 只在确需穿透时：scene.drillPick(movement.endPosition, 3)
}, Cesium.ScreenSpaceEventType.MOUSE_MOVE);
```

## 10. 像素比、MSAA 与视口

- [`useBrowserRecommendedResolution`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L180)（默认 true）+ [`resolutionScale`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L111-L114)：像素比计算公式在 [`CesiumWidget.js L109-L114`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L109-L114)（导读注释原话：忽略 devicePixelRatio 省电省 GPU）。高分屏「画面糊一点、帧率翻一倍」的第一选择：`viewer.useBrowserRecommendedResolution = false` 换清晰度，或 `resolutionScale = 0.8` 主动降。
- [`msaaSamples`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L128)（构造项，存储 [`L263`、getter L1715](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L263)，默认 4）：多重采样抗锯齿。模型边缘锯齿刺眼先降 2 或 1，MSAA 对显存带宽敏感设备是隐形大户。
- **费特效全家桶**：`scene.shadowMap`（构造于 [`L592`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L592)，阴影 = 额外一整个 depth pass）、`scene.fog`（[`L574-L575`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L574)，默认仅球体场景开启）、[`highDynamicRange L760`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L760)（默认 false，开 HDR 代价不小）——逐个关掉做 A/B，比盲目调 SSE 更容易定位「谁贵」。
- `scene.globe.show = false`/关天空盒等「少画一层」的粗暴开关在极端低配设备上依然是最有效的兜底。

## 11. Model 侧开销点（与 15 互补）

- **customShader**：注入 GLSL 会触发 `resetDrawCommands` 全量重编着色器（[15 §6](15-Model与glTF加载.md)）；频繁改参数用 uniform 通道（[`CustomShader.js L122` 起`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Model/CustomShader.js#L122)），别反复换 shader 代码。
- **轮廓（silhouette）**：额外 pass 放大重画背面，超过 256 个启用轮廓的模型有色偏风险（[`Model.js L178` 注释`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Model/Model.js#L178)）——批量高亮优先用 style/BatchTexture 路线（[15 §8](15-Model与glTF加载.md)）。
- **纹理翻转/重排**：KTX2/basis 转码在 worker，但 `flipY` 类像素级处理可能回主线程；排查加载尾帧尖刺用 §3 的 Monitor + Performance 面板对时。
- **`asynchronous: false`**：一次性建 GPU 资源，加载尾帧必卡（[`L3194` 文档`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Model/Model.js#L3194)）；默认分帧 + `incrementallyLoadTextures` 流式补纹理是生产配置。
- **海量小模型**：逐个 `Model.fromGltfAsync` 各自一条命令管线；改用 i3dm/gpu instancing（[15 §2](15-Model与glTF加载.md)）或 3D Tiles 合批。
- **点云渲染参数**：[`PointCloudShading`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PointCloudShading.js#L21)（挂在 `tileset.pointCloudShading`）：`attenuation`（按几何误差自动缩点，L8 文档）+ `eyeDomeLighting`（默认 true，对比度后处理，L12）都开时观感好但多一次后处理；`maximumAttenuation`（L10，默认跟 SSE 走）决定点最大像素——点云卡顿先把 attenuation 幅度收小试试。

## 13. 常见卡顿源清单（按命中率排序）

1. **requestRenderMode 没开**：展示型应用白白 60fps 满转（§2）。
2. **mousemove 里裸 pick/drillPick**：每动一次重画一遍场景（§9）。
3. **SSE 拉太低**（地形 1、瓦片 8 以下）：瓦片数平方级上涨（§6/§7）。
4. **Entity 海量点未走 Primitive/聚合**：DataCollection 每帧 diff（[03](03-Entity数据体系.md)、[14](14-向量数据源.md)）。
5. **关闭浏览器推荐分辨率**：4K 设备像素量 ×2.25 而业务看不清（§10）。
6. **每个小对象一个 Model**：命令/统计/着色器各自一份（§11）。
7. **shadows/fog/大气全家桶常开**：pass 数乘上去（[13](13-渲染命令与着色器.md)）。
8. **惯性 + 低帧率**：0.9 惯性在 20fps 下观感灾难（§8）。
9. **半透明大场景排序**：半透明 pass 每帧按深度排序重排命令，透明玻璃幕墙/水面大面积叠加是隐形大户（[13 §透明 pass](13-渲染命令与着色器.md)）。
10. **点云 attenuation 拉满 + EDL**：点被放大成大团面片，填充率暴涨（§11）。

## 14. 动手实验

1. **量化按需渲染**：静止场景开/关 `requestRenderMode`，用 [`FrameRateMonitor.lowFrameRate` 事件（L83）](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L83) + Chrome Performance 面板对比 GPU 占用。
2. **看剔除数字说话**：`scene.debugShowFrustums = true` 后拉远相机，观察近视锥命令数应趋零；不趋零→包围球问题，开 `debugShowBoundingVolume` 定位（§4）。
3. **内存三本账实操**：控制台打印 `tileset.totalMemoryUsageInBytes` 与 `model.statistics`，再调 `cacheBytes` 看 GC 行为（§5）。
4. **suspendUpdates 二分法**：Inspector 冻结瓦片更新转相机，对比冻结/解冻帧率——10 分钟内判定「流式加载 or 渲染本身」瓶颈（§4）。
5. **拾取成本实测**：`scene.drillPick(pos)` vs `scene.drillPick(pos, 3)` 在重叠 3D Tiles 城市里跑 1000 次取均值（§9）。
6. **特效逐项 A/B**：依次关 shadowMap→fog→HDR→MSAA，每步记 FPS 与 `debugFrustumStatistics` 命令数（§4/§10），把「哪个特性值回帧率」量化成表——这是向产品/客户要预算的硬通货。

## 15. 上线前性能检查单（发布前 15 分钟过一遍）

开发期看得见帧率，上线后才看得见口碑。把本篇的工具链压缩成一张发布门禁清单，每条都给源码锚点与判据：

- [ ] **按需渲染已评估**：展示型/大屏/低交互应用默认开启 [`requestRenderMode`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L694)，
  并按数据落地节奏设 `maximumRenderTimeChange`（§2）；判据：静止页面 GPU 占用应趋近 0。
- [ ] **SSE 分层设定**：地形 `maximumScreenSpaceError` 1.5–2、瓦片集 8–16 起步，视觉敏感区再逐层收紧（§6/§7，[07 §SSE](07-地形系统.md)、[04](04-3DTiles加载与LOD.md)）；
  判据：同一视角瓦片并发请求数不随窗口尺寸平方级暴涨。
- [ ] **缓存上限分档**：`globe.tileCacheSize` 与 [`cacheBytes`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Cesium3DTileset.js#L300)
  按目标设备内存设三档（低端/主流/高端），`maximumCacheOverflowBytes` 兜底（§5）。
- [ ] **高分屏实测**：4K/Retina 上 A/B `resolutionScale` 与 MSAA 档位（§10，
  [`CesiumWidget L111`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L111-L114)）；判据：像素量减半后肉眼可辨差异 ≤ 一档。
- [ ] **拾取节流**：mousemove 里禁止裸 `pick/drillPick`，至少节流到 30Hz 并限层（§9，
  [`Picking.js L895`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L895)）；
  判据：悬停划过密集区无帧尖刺。
- [ ] **特效按需开**：shadowMap/fog/HDR/大气不做「全家桶默认开」，逐项按场景价值取舍（§10/§11，[13](13-渲染命令与着色器.md)）；
  判据：全关与全开的 FPS 差值已知并写进发布说明。
- [ ] **点云参数随密度走**：attenuation 与 EDL 按点密度定档，不做全局常量（§11）。
- [ ] **内存三本账进监控**：`model.statistics`、`totalMemoryUsageInBytes`、[`ResourceCacheStatistics`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ResourceCacheStatistics.js#L20)
  埋点上报（§5/§11）；判据：连续巡航 30 分钟内存曲线有界不爬升。
- [ ] **低帧率告警接线**：[`FrameRateMonitor.lowFrameRate`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/FrameRateMonitor.js#L83)
  事件接前端监控，线上卡顿可回溯（§3）。
- [ ] **长驻页面防泄漏**：瓦片集/Model 的 `destroy` 与 `ResourceCache` 释放链路演练一遍（§5）；判据：反复进出场景 20 次，句柄/显存回落基线。
- [ ] **弱机 profile**：低端四核 + 集显实机跑一遍 §14 实验 1–6，把「哪个特性值回帧率」的量化表带进发布评审。

**通过标准**：以上 11 条全部有数据、有判据、有负责人——性能不是「感觉还行」，是这三样。
