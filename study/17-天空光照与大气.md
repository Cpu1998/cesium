# 17 · 天空光照与大气：环境家族的完整拼图

> 阅读前提：读过 [05-帧更新与渲染循环.md](05-帧更新与渲染循环.md)（帧旅程与 pass 编排）、[13-渲染命令与着色器.md](13-渲染命令与着色器.md)（DrawCommand/ComputeCommand/后处理变体）；[02-底图与影像体系.md](02-底图与影像体系.md) 与 [07-地形系统.md](07-地形系统.md) 提供地球侧背景，[15-Model与glTF加载.md](15-Model与glTF加载.md) 的 PBR 部分是 IBL 小节的另一半。
> 一句话：`new Viewer()` 之后你看到的星空、蓝天、太阳光斑、晨昏线、夜半球，全部由 Scene 上一个「环境家族」提供——本篇把每个成员的源码归宿、一帧里的执行时机、以及 HDR/雾/IBL 三条支线一次讲透。

**本文讲什么**：

- 环境家族全景：[`Scene`](../packages/engine/Source/Scene/Scene.js#L462) 上的 `skyBox`/`skyAtmosphere`/`sun`/`moon`/`atmosphere`/`fog`/`light` 七个字段，以及 [`CesiumWidget`](../packages/engine/Source/Widget/CesiumWidget.js#L382) 在 WGS84 椭球下的默认装配
- 天空盒：[`SkyBox`](../packages/engine/Source/Scene/SkyBox.js#L36) 六面 cube map 与 [`CubeMapPanorama`](../packages/engine/Source/Scene/CubeMapPanorama.js#L76) 的复用关系
- 空间大气：[`SkyAtmosphere`](../packages/engine/Source/Scene/SkyAtmosphere.js#L42) 的瑞利/米氏散射参数与「一命令渲染」结构；[`Atmosphere`](../packages/engine/Source/Scene/Atmosphere.js#L39) 物理参数块
- 地面大气与晨昏线：[`Globe`](../packages/engine/Source/Scene/Globe.js#L1003) 的 `showGroundAtmosphere`/`enableLighting`/四个淡入淡出距离如何逐帧同步进 tileProvider
- 太阳与月亮：[`Sun`](../packages/engine/Source/Scene/Sun.js#L42) 的 glow 纹理（ComputeCommand 生成）+ bloom 后处理链；[`Moon`](../packages/engine/Source/Scene/Moon.js#L32) 的 ICRF 旋转；行星历表 [`Simon1994PlanetaryPositions`](../packages/engine/Source/Core/Simon1994PlanetaryPositions.js#L638)
- 光照统一总线：[`Scene.light`](../packages/engine/Source/Scene/Scene.js#L780) → [`SunLight`](../packages/engine/Source/Scene/SunLight.js#L14) → [`UniformState.update`](../packages/engine/Source/Renderer/UniformState.js#L1486) 把光方向灌进 `czm_sunDirectionEC/WC`
- 雾：[`Fog`](../packages/engine/Source/Scene/Fog.js#L16) 的物理参数与「雾放行」剔除优化（[07](07-地形系统.md) 的 SSE 增益来源）
- HDR 与后处理：`highDynamicRange`/`gamma`/`sunBloom` 与 [`PostProcessStage`](../packages/engine/Source/Scene/PostProcessStage.js#L96) 家族
- IBL：`sphericalHarmonicCoefficients`/`specularEnvironmentMaps` 与 [`DynamicEnvironmentMapManager`](../packages/engine/Source/Scene/DynamicEnvironmentMapManager.js#L69) 的「天盒自动生成环境贴图」

## 1. 全景：Scene 的环境家族

一帧里最先画的是环境（`Pass.ENVIRONMENT`，见 [13 §Pass](13-渲染命令与着色器.md)），然后才轮到地球与图元。所有环境成员都是 `Scene` 的公开字段：

| 字段 | 类型/默认值 | 作用 | 源码锚点 |
|---|---|---|---|
| `skyBox` | `SkyBox`，默认地球星空盒 | 星空背景（六面 cube map） | [Scene.js L307](../packages/engine/Source/Scene/Scene.js#L307) |
| `skyAtmosphere` | `SkyAtmosphere`，默认 WGS84 开 | 地球边缘的蓝色辉光外壳 | [Scene.js L315](../packages/engine/Source/Scene/Scene.js#L315) |
| `sun` | `Sun` | 太阳光斑（可 bloom） | [Scene.js L323](../packages/engine/Source/Scene/Scene.js#L323) |
| `sunBloom` | `true` | 太阳泛光开关 | [Scene.js L330](../packages/engine/Source/Scene/Scene.js#L330) |
| `moon` | `Moon`，默认 WGS84 开 | 月亮（ICRF 定向） | [Scene.js L340](../packages/engine/Source/Scene/Scene.js#L340) |
| `atmosphere` | `new Atmosphere()` | 大气散射物理参数块（SkyAtmosphere 与 3D Tiles/模型大气共用） | [Scene.js L565](../packages/engine/Source/Scene/Scene.js#L565) |
| `fog` | `new Fog()`，非 WGS84 自动关 | 距离雾（兼作剔除优化器） | [Scene.js L574-L575](../packages/engine/Source/Scene/Scene.js#L574) |
| `light` | `new SunLight()` | 光照总线的光源对象 | [Scene.js L780](../packages/engine/Source/Scene/Scene.js#L780) |

默认装配发生在 [`CesiumWidget` 构造](../packages/engine/Source/Widget/CesiumWidget.js#L382)：仅当椭球是 WGS84 时才建地球星空盒（[`SkyBox.createEarthSkyBox`](../packages/engine/Source/Scene/SkyBox.js#L89) 在 [L385](../packages/engine/Source/Widget/CesiumWidget.js#L385) 调用）、月亮与大气；传 `skyBox: false` / `skyAtmosphere: false` 可以整体关闭（纯净模式，省一张 cube map）。注意 **globe 关闭时 SkyAtmosphere 也不显示**（[L400-L404](../packages/engine/Source/Widget/CesiumWidget.js#L400)：`skyAtmosphere.show = options.globe !== false && globe.show`）——没地球就没大气。

一帧中环境家族的更新与执行时机（谁先谁后）：

```
Scene.updateAndExecuteCommands（05 §帧旅程）
└─ executeCommandsInViewport
   ├─ Scene.updateEnvironment          ← 每帧收集：skyBox/skyAtmosphere/sun/moon 命令
   │    ├─ executeComputeCommands      ← sunComputeCommand：先把太阳 glow 纹理算进 GPU
   │    └─ （可见性判定：视锥 + 地球遮挡 Occluder）
   └─ executeCommands
      └─ renderEnvironment（Pass.ENVIRONMENT 最先画）
         ├─ skyBox 命令        （星空，无深度写入）
         ├─ skyAtmosphere 命令 （大气外壳）
         ├─ sun 命令 + sunBloom → SunPostProcess.execute/copy（6 级后处理链）
         └─ moon 命令          （透过大气可见，源码注释原话）
```

## 2. 天空盒：SkyBox 与 CubeMapPanorama

[`SkyBox`](../packages/engine/Source/Scene/SkyBox.js#L36) 是「六面贴图包成 cube map 画在无限远」的经典实现。构造参数 `sources` 需要 `positiveX/negativeX/positiveY/negativeY/positiveZ/negativeZ` 六个面（[L37](../packages/engine/Source/Scene/SkyBox.js#L37)）。1.145 的关键变化：**SkyBox 已退化为薄壳**，[`update`](../packages/engine/Source/Scene/SkyBox.js#L89) 只是一行转发给内部的 [`CubeMapPanorama`](../packages/engine/Source/Scene/CubeMapPanorama.js#L160)（[L101](../packages/engine/Source/Scene/SkyBox.js#L101)）——因为天空盒能力被推广成了「全景立方体贴图」原语：支持 `transform`（[L89](../packages/engine/Source/Scene/CubeMapPanorama.js#L89)）、`credit`、错误事件（[`_hasError` 分支 L179-L186](../packages/engine/Source/Scene/CubeMapPanorama.js#L179)），既当星空也当全景视频/环境背景。真正的 DrawCommand 在 [`CubeMapPanorama` 构造 L102](../packages/engine/Source/Scene/CubeMapPanorama.js#L102) 创建，six 面 shader 采样 cube map 后以 `Pass.ENVIRONMENT` 提交（命令收编见 §1 时序图）。

两个实用细节：

- **HDR 双版本**：`update` 的第二个参数 `useHdr`（[`L160`](../packages/engine/Source/Scene/CubeMapPanorama.js#L160)）会切换浮点纹理路径——`scene.highDynamicRange = true` 时星空盒也走 HDR 格式（见 §8）。
- **skyBox 兼职环境贴图**：[`Scene.updateFrameState` L2061](../packages/engine/Source/Scene/Scene.js#L2061) 每帧把 `skyBox._cubeMap` 塞进 `frameState.environmentMap`，这是 §9 IBL 自动生成链的原料。

## 3. 空间大气：SkyAtmosphere 与 Atmosphere 参数块

### 3.1 SkyAtmosphere：一条 DrawCommand 的外壳辉光

[`SkyAtmosphere`](../packages/engine/Source/Scene/SkyAtmosphere.js#L42) 画的是「从太空看地球」的蓝色边缘辉光（以及从地面看时的天空穹顶）。它的结构极简：**一个 DrawCommand 打天下**（[构造 L73](../packages/engine/Source/Scene/SkyAtmosphere.js#L73)），模型矩阵是椭球放大 1.025 倍的缩放壳（[`_scaleMatrix` L70](../packages/engine/Source/Scene/SkyAtmosphere.js#L70)），shader 是 [`SkyAtmosphereFS/VS`](../packages/engine/Source/Shaders/SkyAtmosphereFS.glsl) + 公共库 [`AtmosphereCommon`](../packages/engine/Source/Shaders/AtmosphereCommon.glsl)/[`SkyAtmosphereCommon`](../packages/engine/Source/Shaders/SkyAtmosphereCommon.glsl)（导入见 [L16-L19](../packages/engine/Source/Scene/SkyAtmosphere.js#L16)）。

关键开关与机制：

| 成员 | 含义 | 锚点 |
|---|---|---|
| `perFragmentAtmosphere` | 逐片元散射（更准更贵）；相机在地面附近自动启用 | [L60](../packages/engine/Source/Scene/SkyAtmosphere.js#L60)，判定 [L271-L272](../packages/engine/Source/Scene/SkyAtmosphere.js#L271)：`perFragmentAtmosphere \|\| translucent \|\| !defined(globe)` |
| `setDynamicLighting` | 动态光照模式注入 uniform 的 z 分量 | [L224-L225](../packages/engine/Source/Scene/SkyAtmosphere.js#L224) |
| `_radiiAndDynamicAtmosphereColor` | 打包 uniform：椭球半径 + 光色 + 模式 | [L168](../packages/engine/Source/Scene/SkyAtmosphere.js#L168)、uniformMap [L172](../packages/engine/Source/Scene/SkyAtmosphere.js#L172) |
| flags 位域 | 亮度校正/perFragment/半透明 三位拼 shader 宏，变化才重建 program | [L302-L337](../packages/engine/Source/Scene/SkyAtmosphere.js#L302)，`ShaderProgram.fromCache` [L331](../packages/engine/Source/Scene/SkyAtmosphere.js#L331) |

**动态大气光照**由 [`DynamicAtmosphereLightingType`](../packages/engine/Source/Scene/DynamicAtmosphereLightingType.js#L8) 三态决定：`NONE`（顶光常亮，L17）、`SUNLIGHT`（用真实太阳方向算昼夜明暗，L25）、`SCENE_LIGHT`（用 `scene.light` 方向，L33）。场景侧的仲裁在 [`Scene.updateEnvironment` L3775-L3781](../packages/engine/Source/Scene/Scene.js#L3775)：有 globe 时以 [`fromGlobeFlags`](../packages/engine/Source/Scene/DynamicAtmosphereLightingType.js#L42)（组合 `dynamicAtmosphereLighting`/`dynamicAtmosphereLightingFromSun` 两个 Globe 字段）为准；无 globe 才看 `scene.atmosphere.dynamicLighting`。还有个 `isReadyForAtmosphere` 闸门（[L3778-L3780](../packages/engine/Source/Scene/Scene.js#L3778)）：**首批地形瓦片渲染出来之前大气不显示**，避免「黑屏期」先亮一圈蓝边。

### 3.2 Atmosphere：物理参数的单一来源

[`Atmosphere`](../packages/engine/Source/Scene/Atmosphere.js#L39)（挂在 `scene.atmosphere`）是 1.120+ 拆出来的参数对象，同时服务空间大气、地面大气（§4）与 3D Tiles/模型的大气效果（[`AtmospherePipelineStage`](../packages/engine/Source/Scene/Model/AtmospherePipelineStage.js)）。参数物理含义一览：

| 参数 | 默认值 | 物理含义 | 锚点 |
|---|---|---|---|
| `rayleighCoefficient` | (5.5, 13.0, 28.4)e-6 | 瑞利散射系数（蓝紫 > 红的波长依赖，天空发蓝的根源） | [L54](../packages/engine/Source/Scene/Atmosphere.js#L54) |
| `mieCoefficient` | 21e-6 均匀 | 米氏散射系数（气溶胶，雾天发白的根源） | [L62](../packages/engine/Source/Scene/Atmosphere.js#L62) |
| `rayleighScaleHeight` | 10000 m | 瑞利标高（大气密度衰减到 1/e 的高度） | [L70](../packages/engine/Source/Scene/Atmosphere.js#L70) |
| `mieScaleHeight` | 3200 m | 米氏标高 | [L78](../packages/engine/Source/Scene/Atmosphere.js#L78) |
| `mieAnisotropy` | 0.9 | 相函数各向异性（0=各向同性，越接近 1 前向散射越强→日晕） | [L89](../packages/engine/Source/Scene/Atmosphere.js#L89) |
| `lightIntensity` | 10.0 | 入射光强 | [L46](../packages/engine/Source/Scene/Atmosphere.js#L46) |
| `hueShift`/`saturationShift`/`brightnessShift` | 0.0 | 色相/饱和度/亮度偏移（美术后处理旋钮） | [L98](../packages/engine/Source/Scene/Atmosphere.js#L98)/[L107](../packages/engine/Source/Scene/Atmosphere.js#L107)/[L116](../packages/engine/Source/Scene/Atmosphere.js#L116) |
| `dynamicLighting` | NONE | 无 globe 时的动态光照模式 | [L125](../packages/engine/Source/Scene/Atmosphere.js#L125) |

调参口诀：想要「火星黄昏」把 `rayleighCoefficient` 整体调小再 `hueShift` 偏橙；想要浓霾拉大 `mieCoefficient`；只想要颜色不变昼夜就 `dynamicLighting = SUNLIGHT` 并保证 `globe.dynamicAtmosphereLighting = true`。

## 4. 地面大气与晨昏线：Globe 侧的另一条散射管线

地形表面本身的「大气感」（远景泛蓝、夜半球变暗）走的是**第二条管线**：地形 shader 里直接混入 [`GroundAtmosphere`](../packages/engine/Source/Shaders/GroundAtmosphere.glsl) 片元（Globe 组装于 [L676](../packages/engine/Source/Scene/Globe.js#L676)/[L690](../packages/engine/Source/Scene/Globe.js#L690)）。开关与参数都在 Globe 上（与 §3.2 的 Atmosphere 同名但以 `atmosphere*` 前缀区分）：

| 字段 | 默认 | 作用 | 锚点 |
|---|---|---|---|
| `showGroundAtmosphere` | WGS84 时 true | 地面大气总开关 | [L213](../packages/engine/Source/Scene/Globe.js#L213) |
| `enableLighting` | false | 地形昼夜光照（太阳方向 lambert） | [L176](../packages/engine/Source/Scene/Globe.js#L176) |
| `dynamicAtmosphereLighting` | true | 大气是否随昼夜变化 | [L195](../packages/engine/Source/Scene/Globe.js#L195) |
| `dynamicAtmosphereLightingFromSun` | false | 用太阳方向而非 scene.light | [L205](../packages/engine/Source/Scene/Globe.js#L205) |
| `lightingFadeOutDistance/InDistance` | 10e6 / π·b | 光照淡出/淡入（远距离回退到无光照） | [L272](../packages/engine/Source/Scene/Globe.js#L272)/[L282](../packages/engine/Source/Scene/Globe.js#L282) |
| `nightFadeOutDistance/InDistance` | — | **夜半球边缘**的暗色淡入淡出（晨昏线软化） | [L292](../packages/engine/Source/Scene/Globe.js#L292)/[L302](../packages/engine/Source/Scene/Globe.js#L302) |
| `atmosphereLightIntensity` 及 6 个散射参数 | 同 §3.2 | 地面版散射参数（独立于 scene.atmosphere） | [L221](../packages/engine/Source/Scene/Globe.js#L221)-[L263](../packages/engine/Source/Scene/Globe.js#L263) |
| `atmosphereHueShift` 等 3 个 | 0.0 | 地面大气颜色偏移 | [L344](../packages/engine/Source/Scene/Globe.js#L344)-[L360](../packages/engine/Source/Scene/Globe.js#L360) |

这些字段不是自己消费的：[`Globe.beginFrame` L1043-L1069](../packages/engine/Source/Scene/Globe.js#L1043) 每帧把它们逐一同步给 `tileProvider`（[07 §三拍](07-地形系统.md) 的 beginFrame 拍），最终由 GlobeSurfaceTileProvider 的 uniform 每瓦片灌进 GroundAtmosphere 片元。**晨昏线就是这条管线的副产品**：太阳方向（§6）dot 地形法线为负的区域乘上 night 系数，四个 fade 距离控制过渡带宽度。

常见坑：`enableLighting = true` 后地形整体变暗不是 bug——那是真实的夜半球；想只要「白天更立体」不想夜晚全黑，把 `nightFadeInDistance` 调小或直接关 `dynamicAtmosphereLighting`。

## 5. 太阳与月亮

### 5.1 Sun：一个 ComputeCommand + 一个 DrawCommand

[`Sun`](../packages/engine/Source/Scene/Sun.js#L42) 只有两个成员命令（`_commands` 对象 [L56](../packages/engine/Source/Scene/Sun.js#L56)）：

1. **drawCommand**：画一个 billboard 式太阳面片。VAO/ShaderProgram 在 [`update` L115](../packages/engine/Source/Scene/Sun.js#L115) 里懒建（[`new VertexArray` L230](../packages/engine/Source/Scene/Sun.js#L230)、[`ShaderProgram.fromCache` L236](../packages/engine/Source/Scene/Sun.js#L236)，片元 [`SunFS`](../packages/engine/Source/Shaders/SunFS.glsl)）；包围球在无穷远（太阳位置 × 极大半径），所以永远不被地球深度挡住，靠 shader 里与月/大气次序控制观感。
2. **computeCommand**：生成 glow 纹理。太阳的「光晕」不是一张静态贴图，而是用 [`SunTextureFS`](../packages/engine/Source/Shaders/SunTextureFS.glsl) 在 GPU 上按 [`glowFactor`](../packages/engine/Source/Scene/Sun.js#L95)（默认 1.0，setter 会置脏 [L101-L102](../packages/engine/Source/Scene/Sun.js#L101)）**现场卷积**出来的径向渐变（[`new ComputeCommand` L177](../packages/engine/Source/Scene/Sun.js#L177)，[`_glowLengthTS`/`_radiusTS` 公式 L167-L168](../packages/engine/Source/Scene/Sun.js#L167)）。任一输入变化（视口尺寸、glowFactor、HDR 开关）才重算（脏判定 [L134-L143](../packages/engine/Source/Scene/Sun.js#L134)）。

computeCommand 的执行点在 [`executeComputeCommands` L3243-L3248](../packages/engine/Source/Scene/Scene.js#L3243)（[05 §计算旁支](05-帧更新与渲染循环.md)/[13 §ComputeCommand](13-渲染命令与着色器.md) 已述 ComputeEngine 机制）。

**sunBloom**：太阳画完后若 `scene.sunBloom` 为 true，[`renderEnvironment` L3210-L3216](../packages/engine/Source/Scene/Scene.js#L3210) 立刻执行 [`SunPostProcess`](../packages/engine/Source/Scene/SunPostProcess.js#L19)——一条 6 级后处理链（下采样亮提取 → 4 步高斯模糊金字塔 → 上采样合成，stage 组装 [L23-L96](../packages/engine/Source/Scene/SunPostProcess.js#L23)、composite [L111](../packages/engine/Source/Scene/SunPostProcess.js#L111)），最终 [`copy`](../packages/engine/Source/Scene/SunPostProcess.js#L262) 回主 FBO。链路的启停由 [`Scene` 内部 L4006-L4015](../packages/engine/Source/Scene/Scene.js#L4006) 管理：`sunBloom` 或 `sun` 存在性变化时创建/销毁整条链。

### 5.2 Moon：跟着 ICRF 转的椭球面片

[`Moon`](../packages/engine/Source/Scene/Moon.js#L32) 内部是一个贴月面纹理的椭球图元（`_ellipsoidPrimitive`，[L106](../packages/engine/Source/Scene/Moon.js#L106)）。它的趣味点在定向：[`update` L101](../packages/engine/Source/Scene/Moon.js#L101) 用 [Transforms 的 ICRF 轴](../packages/engine/Source/Core/Transforms.js)（`_axes.evaluate` [L115](../packages/engine/Source/Scene/Moon.js#L115)）与 [`Simon1994PlanetaryPositions.computeMoonPositionInEarthInertialFrame` L670](../packages/engine/Source/Core/Simon1994PlanetaryPositions.js#L670) 算出的平移（[L119](../packages/engine/Source/Scene/Moon.js#L119)）拼出模型矩阵——**月亮的姿态和位置都是天文历表算出来的**，与 §6 的太阳方向同源。

### 5.3 Simon1994PlanetaryPositions：天文历表

[`Simon1994PlanetaryPositions`](../packages/engine/Source/Core/Simon1994PlanetaryPositions.js#L638) 实现了 JPL 的行星解析历表（secular 变化率级数），对渲染有用的是两个入口：[`computeSunPositionInEarthInertialFrame` L638](../packages/engine/Source/Core/Simon1994PlanetaryPositions.js#L638)（太阳在地心惯性系的位置）与 [`computeMoonPositionInEarthInertialFrame` L670](../packages/engine/Source/Core/Simon1994PlanetaryPositions.js#L670)。传入 `frameState.time`（[10 §JulianDate](10-时间与动态属性.md)），随模拟时间流动——把 `clock.currentTime` 拨快几小时，就能看到太阳月亮晨昏线一起动。

## 6. 光照统一总线：Scene.light → czm_sunDirectionEC

Cesium 1.145 的光照源是**一个**对象：[`scene.light`](../packages/engine/Source/Scene/Scene.js#L780)，抽象基类 [`Light`](../packages/engine/Source/Scene/Light.js#L12)（只有 color/intensity 两个属性约定，[L14-L26](../packages/engine/Source/Scene/Light.js#L14)），内置唯一实现是方向光 [`SunLight`](../packages/engine/Source/Scene/SunLight.js#L14)（整个文件 31 行：`color` 默认白、`intensity` 默认 2.0）。要自定义光方向就 `scene.light = new Cesium.DirectionalLight({direction: ...})` 或换 `PointLight`（同目录 `DirectionalLight.js`/`PointLight.js`，同样 30 行级别的薄类）。

每帧的灌装链路（这是全篇最值得记住的一张图）：

```
Scene.updateFrameState（L2082: frameState.light = this.light）
        │
        ▼
UniformState.update（L1486 起）
        │
        ├─ setSunAndMoonDirections（L1375）
        │    ├─ Simon1994.computeSunPositionInEarthInertialFrame（L1380）
        │    ├─ 惯性系→固定系→normalize ⇒ _sunDirectionWC（L1388）
        │    └─ 视旋转 3x3 ⇒ _sunDirectionEC（L1391-L1396）
        │
        ├─ L1505-L1523：光方向仲裁
        │    ├─ light instanceof SunLight ⇒ 直接复用太阳方向（_lightDirectionWC/EC）
        │    └─ 否则 ⇒ light.direction 取反→normalize→转视空间
        │
        ▼
shader 里的自动 uniform（AutomaticUniforms）
  czm_sunDirectionWC（L1286）/ czm_sunDirectionEC（L1264）
  —— Globe/大气/3D Tiles/Model 的昼夜着色都 dot 这两个向量
```

**关键结论**：`SunLight` 之所以特殊，不是名字带 sun，而是它**忽略自己的 direction**、直接绑天文太阳（[L1508-L1517](../packages/engine/Source/Renderer/UniformState.js#L1508)）；换成 DirectionalLight 后太阳/月亮的位置照旧（天文历表），但地形昼夜、大气明暗、模型 PBR 光向全部跟随 `light.direction`。这就是「太阳是画出来的天体，光是着色的方向源」二者在源码层的分界。

## 7. 雾：物理与剔除的双重身份

[`Fog`](../packages/engine/Source/Scene/Fog.js#L16) 挂在 `scene.fog`，参数四个：

| 参数 | 默认 | 含义 | 锚点 |
|---|---|---|---|
| `enabled` | true | 总开关（非 WGS84 自动关，[Scene L575](../packages/engine/Source/Scene/Scene.js#L575)） | [L25](../packages/engine/Source/Scene/Fog.js#L25) |
| `renderable` | true | false 时**只保留剔除收益、不画雾色**（隐藏性能开关） | [L31](../packages/engine/Source/Scene/Fog.js#L31) 附近 |
| `density` | 0.0006 | 基础密度（越大雾越近） | [L49](../packages/engine/Source/Scene/Fog.js#L49) |
| `heightFalloff` | 0.59 | 相机离地越高雾越淡的衰减率 | [L56](../packages/engine/Source/Scene/Fog.js#L56)、getter [L99](../packages/engine/Source/Scene/Fog.js#L99) |
| `screenSpaceErrorFactor` | 2.0 | 「雾放行」SSE 增益系数 | [L82](../packages/engine/Source/Scene/Fog.js#L82) |
| `minimumBrightness` | 0.03 | 雾色下限（防全黑） | [L89](../packages/engine/Source/Scene/Fog.js#L89) |

每帧 [`Fog.update` L122](../packages/engine/Source/Scene/Fog.js#L122) 把算好的 `density`（含高度衰减）与 `sse` 写进 `frameState.fog`（执行点 [`Scene` L4591](../packages/engine/Source/Scene/Scene.js#L4591)）。消费方有两类：

1. **着色**：地形/GlobeSurf­ace 片元按 [`CesiumMath.fog(distance, density)` L1122](../packages/engine/Source/Core/Math.js#L1122)（`1 - exp(-density²·d²)` 造型）混入雾色（颜色 = 雾亮度 × 光照）。
2. **剔除放行**（[07 §SSE](07-地形系统.md) 的伏笔）：[`QuadtreePrimitive` L1290-L1292](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1290) 在瓦片**部分入雾**时给 SSE 乘 `fog × screenSpaceErrorFactor`——浓雾里的远山不需要精细瓦片，**雾成了 LOD 的免费加速器**；完全入雾的瓦片更直接不渲染（[2D 版 L1319-L1322](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1319)）。

所以 `fog.enabled = false` 常伴随瓦片数上升（[16 §调参](16-性能调试与优化.md) 速查表收录过此条）；反过来 `enabled: true + renderable: false` 是「白嫖剔除」的隐藏组合。

## 8. HDR 与后处理家族

- **HDR**：[`scene.highDynamicRange`](../packages/engine/Source/Scene/Scene.js#L1664) 默认 false。setter（[L1669-L1676](../packages/engine/Source/Scene/Scene.js#L1669)）先探能力（`depthTexture` + `colorBufferFloat/halfFloat`），能力探测也有只读镜像 [`highDynamicRangeSupported` L1686](../packages/engine/Source/Scene/Scene.js#L1686)。开启后主 FBO 与环境链改用浮点/半浮点像素格式（`_hdrDirty` 触发重建），太阳 glow 与 bloom 的动态范围才真正拉开。
- **gamma**：[`scene.gamma` L761](../packages/engine/Source/Scene/Scene.js#L761) 默认 2.2，作为后处理链末端的伽马校正指数。
- **通用后处理**：[`scene.postProcessStages`](../packages/engine/Source/Scene/Scene.js#L636) 是 [`PostProcessStageCollection`](../packages/engine/Source/Scene/PostProcessStageCollection.js#L35)——构造时预装 fxaa/ambientOcclusion/bloom/tonemapping 四个内置 stage（[L62](../packages/engine/Source/Scene/PostProcessStageCollection.js#L62)）。单个 stage 是「片元 shader + FBO 链节点」（[`PostProcessStage` L96](../packages/engine/Source/Scene/PostProcessStage.js#L96)，[`update` L876](../packages/engine/Source/Scene/PostProcessStage.js#L876)/[`execute` L952](../packages/engine/Source/Scene/PostProcessStage.js#L952)）。特效工厂在 [`PostProcessStageLibrary`](../packages/engine/Source/Scene/PostProcessStageLibrary.js)：[`createBloomStage` L388](../packages/engine/Source/Scene/PostProcessStageLibrary.js#L388)（通用泛光，与太阳专属 bloom 不同）、`createBlurStage` [L120](../packages/engine/Source/Scene/PostProcessStageLibrary.js#L120)、`createDepthOfFieldStage` [L141](../packages/engine/Source/Scene/PostProcessStageLibrary.js#L141)、`createEdgeDetectionStage` [L241](../packages/engine/Source/Scene/PostProcessStageLibrary.js#L241)、`createAmbientOcclusionStage` [L496](../packages/engine/Source/Scene/PostProcessStageLibrary.js#L496) 等。舞台的执行时机在帧尾（[`Scene` L4201](../packages/engine/Source/Scene/Scene.js#L4201) 起），叠加次序 = 集合次序，细节见 [13 §后处理变体](13-渲染命令与着色器.md)。

注意区分**两个 bloom**：`scene.sunBloom` 是太阳专属的 `SunPostProcess`（在 ENVIRONMENT pass 内、贴着太阳命令执行，§5.1）；`postProcessStages.bloom` 是全屏泛光（帧尾、对整幅亮度做 bright-pass）。前者默认开，后者默认关。

## 9. IBL：从星空盒自动生成环境光照

PBR 模型（[15 §材质](15-Model与glTF加载.md)）需要两张环境资产：漫反射用的球谐系数 `sphericalHarmonicCoefficients` 与镜面反射用的辐照 cube map `specularEnvironmentMaps`。Scene 提供两个公开入口（[`L767`](../packages/engine/Source/Scene/Scene.js#L767)/[`L773`](../packages/engine/Source/Scene/Scene.js#L773)），但**不填也有默认方案**：

[`DynamicEnvironmentMapManager`](../packages/engine/Source/Scene/DynamicEnvironmentMapManager.js#L69) 每帧 [`update` L854](../packages/engine/Source/Scene/DynamicEnvironmentMapManager.js#L854) 以 `frameState.environmentMap`（= skyBox 的 cubeMap，§2）为原料，用一组 ComputeCommand（上限 [`_maximumComputeCommandCount` L303](../packages/engine/Source/Scene/DynamicEnvironmentMapManager.js#L303)）卷积出多级辐照图 `radianceCubeMap`（getter [L264](../packages/engine/Source/Scene/DynamicEnvironmentMapManager.js#L264)）并对环境做球谐积分得 `sphericalHarmonicCoefficients`（getter [L295](../packages/engine/Source/Scene/DynamicEnvironmentMapManager.js#L295)）——**星空盒兼职 IBL 光源**。模型侧消费点在 [`ImageBasedLightingPipelineStage.process` L21](../packages/engine/Source/Scene/Model/ImageBasedLightingPipelineStage.js#L21)：显式传了 `specularEnvironmentMaps` 就用用户资产（[L31-L33](../packages/engine/Source/Scene/Model/ImageBasedLightingPipelineStage.js#L31)），否则回落到 manager 的 radianceCubeMap；球谐同理（[L35-L37](../packages/engine/Source/Scene/Model/ImageBasedLightingPipelineStage.js#L35)），最终注入 `model_sphericalHarmonicCoefficients[9]`（[L87](../packages/engine/Source/Scene/Model/ImageBasedLightingPipelineStage.js#L87)）等 uniform。

另一处容易混淆的枚举：模型渲染质量档 [`LightingModel`](../packages/engine/Source/Scene/Model/LightingModel.js#L20)（`UNLIT: 0` / `PBR: 1`，[L33](../packages/engine/Source/Scene/Model/LightingModel.js#L33)）——它管的是**模型着色模型**，不是昼夜光照；本篇的光照总线（§6）才是给 PBR 喂主光方向的通道。

## 10. 动手实验与常见坑

### 动手实验

```js
// 实验 1：拨快时间看晨昏线扫过地球（§4/§5/§6 联动）
viewer.clock.shouldAnimate = true;
viewer.clock.multiplier = 3600;            // 1 秒 = 1 小时
// 观察：太阳/月亮位置、晨昏线、夜半球亮度同时变化（全部由 JulianDate 驱动）

// 实验 2：关掉环境家族，看清每个成员的贡献（§1）
viewer.scene.skyBox = viewer.scene.skyBox && undefined;   // 星空消失
viewer.scene.skyAtmosphere.show = false;                  // 蓝色边缘辉光消失
viewer.scene.fog.enabled = false;                         // 远景雾消失 + 瓦片变多
viewer.scene.sun.show = false;                            // 太阳光斑消失

// 实验 3：自定义光方向（§6）——倾斜光下的长影子感
viewer.scene.globe.enableLighting = true;
viewer.scene.light = new Cesium.DirectionalLight({
  direction: new Cesium.Cartesian3(-0.5, 0.5, -0.8),
});

// 实验 4：雾的隐藏性能组合（§7）
viewer.scene.fog.enabled = true;
viewer.scene.fog.renderable = false;       // 只留剔除收益，画面无雾

// 实验 5：手动指定 IBL（§9）
viewer.scene.sphericalHarmonicCoefficients = shCoefficients; // 9 个 Cartesian3
viewer.scene.specularEnvironmentMaps = "./env.ktx2";
```

### 常见坑

| 坑 | 真相 | 对策 |
|---|---|---|
| 自定义椭球（非 WGS84）下没星空/大气/雾 | CesiumWidget 默认装配只在 WGS84 生效（[L383-L404](../packages/engine/Source/Widget/CesiumWidget.js#L383)） | 手动 `new SkyAtmosphere(ellipsoid)` 挂上去 |
| `skyAtmosphere` 时有时无闪烁 | `isReadyForAtmosphere` 闸门：首批地形瓦片渲染前不显示（[Scene L3778](../packages/engine/Source/Scene/Scene.js#L3778)） | 正常现象；急查就先关地形 `globe.show = false` 复现对比 |
| 改了 `SunLight.color/intensity` 地形没变化 | 地形昼夜管线主要消费**方向**；颜色/强度主要进 PBR 与太阳 glow | 想改地球观感用 `scene.atmosphere` / `globe.atmosphere*` 参数 |
| 开 HDR 黑屏/无效 | 浮点颜色缓冲能力不足，setter 静默回落 false（[L1669](../packages/engine/Source/Scene/Scene.js#L1669)） | 先查 `scene.highDynamicRangeSupported` |
| 雾调浓后远处瓦片「消失」 | 完全入雾的瓦片被整体跳过（§7 剔除） | 调低 `density` 或 `screenSpaceErrorFactor` |
| `sunBloom` 关了还是有光晕 | glow 纹理本体仍在（§5.1 的 ComputeCommand 产物） | `scene.sun.glowFactor = 0` 才是彻底关光晕 |
| 夜半球全黑没细节 | `nightFade*` 距离把暗区拉满 | 调大 `globe.nightFadeInDistance` 或关 `dynamicAtmosphereLighting` |
