## 0. 全景：拾取不是射线求交，而是「重画一遍」

Cesium 的拾取核心思想：**把整个场景用「每个对象唯一的 pickColor」重画一遍到离屏 framebuffer，再读回那一像素的颜色反查对象**。没有空间索引、没有 CPU 求交——GPU 什么顺序画出来的，拾取就什么顺序拿回来。

一次 `scene.pick(windowPosition)` 的 GPU 往返：

```
JS 主线程
 scene.pick(windowPosition)                      Scene.js#L4833
  └─ picking.pick(scene, pos, w, h, limit)       Picking.js#L419
      ├─ pickBegin(...)                          Picking.js#L283
      │   ├─ 像素 → drawingBuffer 坐标，默认框 3×3（y 翻转）
      │   ├─ cullingVolume 收窄成「以像素为中心的小视锥」
      │   ├─ frameState.passes.pick = true      ← 整条渲染管线知道这是一次拾取
      │   └─ updateAndExecuteCommands(...)       重建一遍 scene（跳过环境/OIT/后处理）
      │       └─ executeCommand: 命令换成 pickCommand 变体   Scene.js#L2353
      ├─ pickFramebuffer.end(rect, limit)        PickFramebuffer.js#L198
      │   ├─ readPixels(rect)                    ← 同步读回（GPU 往返的停顿点）
      │   └─ pickObjectsFromPixels(...)          螺旋遍历像素 → pickColor → 对象
      └─ pickEnd(scene)                          context.endFrame()
```

三个高频入口的分工：

| [`scene.pick(pos)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4833) | L4833 | `{primitive, id}` 或 `undefined` | 颜色编码 |

## 1. 门面与编排器：Scene → Picking 的两层结构

[`Scene.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js) 构造函数里
[`this._picking = new Picking(this)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L754)
（经 [`scene.picking`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L1103) 暴露），
所有 `Scene.prototype.*` 拾取方法都是一行转发——例如
[`Scene.prototype.pick`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4833)
就是 `return this._picking.pick(this, windowPosition, width, height, 1)[0]`。

[`function Picking(scene)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L46)
持有三件私货：

- **pickRenderStateCache**：按 renderState.id 缓存的 pick 专用渲染状态（§4）；
- **_pickPositionCache**：`pickPosition` 的逐坐标缓存，每帧被
  [`Picking.prototype.update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L67)
  置脏（由 [`prePassesUpdate`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4532) 在
  [L4544](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4544) 调用）——**同一帧内反复 pickPosition 同一点只读一次 GPU**；
- **_pickOffscreenView**：一台 0.1 米宽正交相机的离屏 View（§8 射线拾取用）。

## 2. pickBegin：为拾取重建一帧

真正的拾取流程从导出函数 [`pickBegin`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L283)
开始（1.145 把它做成可复用导出，供 Snapping 吸附共用同一套离屏 pick 渲染），逐行拆解：

1. **坐标换算**：[`SceneTransforms.transformWindowToDrawingBuffer`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/SceneTransforms.js#L376)
   把 CSS 像素换成绘图缓冲坐标；再由
   [`computePickingDrawingBufferRectangle`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L252)
   生成拾取矩形——**默认 3×3 像素**（容忍手抖/抗锯齿），注意 y 轴翻转（GL 原点在左下）；
2. **剔除收窄**：[`getPickCullingVolume`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L198)
   按当前相机模式（透视走 [`getPickPerspectiveCullingVolume`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L149)、
   正交走 [`getPickOrthographicCullingVolume`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L87)）
   反推出一个**只罩住拾取矩形的小视锥**——绝大多数瓦片/图元在 CPU 剔除阶段就被跳过，pick pass 的实际绘制量很小；
3. **打标记**：`frameState.passes.pick = true`、`tilesetPassState = pickTilesetPassState`（3D Tiles 也进 pick 专用 pass）、
   [`jobScheduler.disableThisFrame()`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L1164)（拾取期间不发新任务，避免瓦片状态变化）；
4. **渲染**：[`scene.updateAndExecuteCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3391)
   把全部 Primitive 的 update 走一遍并按多视锥提交命令，最终落
   [`resolveFramebuffers`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4158)；
   最后 [`pickEnd`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L350) 调 `context.endFrame()` 收尾。

pick pass 与正常渲染帧的差异（全部由 `passes.pick` 驱动）：

| 环节 | 正常帧 | pick pass |
|---|---|---|
| 环境渲染（天空盒/大气） | [`renderEnvironment`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2811) 前执行 | 跳过（见 [executeCommands L2811](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2811) 的 `picking` 判断） |
| 每条 DrawCommand | 原 shader | 换 pickCommand 派生变体（§4） |
| OIT/MSAA/后处理 | [`updateAndClearFramebuffers`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3989) 走全流程 | L3996 的 `picking` 分支跳过 |
| 渲染目标 | scene/globe framebuffer | pick framebuffer + scissor 只裁拾取矩形 |

## 3. PickId：pickColor ↔ primitive 的注册表

「一个像素颜色查回一个 JS 对象」靠的是 Context 里的一张 Map：

- [`Context.prototype.createPickId`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1698)
  每次分配一个自增 `Uint32` key，把 `key→object` 存进 `_pickObjects`，并用
  [`Color.fromRgba(key)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1719)
  生成与 key 双向可逆的颜色——**RGBA 四字节恰好编码一个 uint32，颜色即 ID**；
- 返回的 [`PickId`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/PickId.js#L12)
  是个瘦壳：[`key`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/PickId.js#L24)/[`color`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/PickId.js#L27)
  只读字段 + 经 `_pickObjects` 间接读写的 `object` getter/setter（[L30](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/PickId.js#L30)），
  [`destroy`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/PickId.js#L41) 就是把自己从 Map 里删掉；
- 反查入口 [`Context.prototype.getObjectByPickColor`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1673)。

谁去注册？每个可拾取图元在创建命令时领号：例如 [`Primitive.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js)
为**每个 GeometryInstance** 领一个（[L650](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L650)，
所以 `scene.pick(...).id` 能精确到 entity，呼应 [03 §7](03-Entity数据体系.md)）；
3D Tiles 则按 feature 批表逐 feature 分配。WebGL 里 32 位颜色约 1677 万个不重复 ID，溢出会抛
`Out of unique Pick IDs`（[L1711](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js#L1711)）。

## 4. 派生命令：一条 DrawCommand 的 pick 变体

pick pass 里每个图元画的还是同一份几何，但 shader 输出被整体改写。枢纽在
[`updateDerivedCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L1814)：
它给每条命令预生成若干「变体」（logDepth/HDR/pick/…），pick 时
[`DerivedCommand.createPickDerivedCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L315)
产出的 `pickCommand` 由 [`executeCommand`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2291)
在 [`passes.pick` 分支](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2323) 替身上场。

两件改写（均在 [DerivedCommand.js](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js)）：

- **shader**：[`getPickShaderProgram`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L253)
  把片元 main 改名为 `czm_non_pick_main`，再拼一个新 main：原片元 alpha 为 0 直接 `discard`，否则**输出整个替换为 pickId 颜色**
  （即 `command.pickId` 指向的 varying，如 Primitive 的 `v_pickColor`，见
  [Primitive.js L2056](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L2056)）。
  结果缓存在 `shaderCache` 的派生槽里（同 shader 只编译一次）；
- **renderState**：[`getPickRenderState`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/DerivedCommand.js#L293)
  关混合、开 depthMask——**半透明对象在 pick pass 里也写深度**，保证被挡住的透明体不会被「隔空」拾取到。

**地形的特殊待遇**：globe 没有 v_pickColor varying（裸地形本来就不可拾取）。
pick pass 时 [`QuadtreePrimitive.update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/QuadtreePrimitive.js#L316)
在 [L387](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/QuadtreePrimitive.js#L387) 走
[`GlobeSurfaceTileProvider.updateForPick`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L648)
——**直接复用上一帧画过的瓦片命令**（不再重选瓦片），并把命令的 pick 派生缓存标记失效（L656）。
贴在地形上的矢量（ draped vectors）才有 pickId：
[addDrawCommandsForTile](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L2528)
里 [`command.pickId = "vectorPickColorOver(vec4(0.0))"`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L3304)
——矢量像素返回矢量颜色、其余像素返回 0（不可拾取）。

## 5. readPixel 与螺旋遍历：PickFramebuffer

[`PickFramebuffer`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickFramebuffer.js#L15)
挂在 View 上（[`View.js` L65](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L65)，
同村的还有 [pickDepthFramebuffer L67](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L67) 和
[pickDepths L80](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/View.js#L80)）：

- [`begin`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickFramebuffer.js#L101)：
  建带 depthStencil 的离屏 framebuffer，开 scissor 只许画拾取矩形，关混合（passState 在构造函数里预置）；
- [`end`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickFramebuffer.js#L198)：
  [`context.readPixels`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Context.js)
  同步读回矩形 → [`pickObjectsFromPixels`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickFramebuffer.js#L45)；
- [`endAsync`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickFramebuffer.js#L134)：
  WebGL2 下走 PBO + fence Sync，把「等 GPU」摊到 `frameState.afterRender` 回调里，不卡主线程（供
  [`Picking.prototype.pickAsync`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L370)）。

`pickObjectsFromPixels` 最有意思的是**螺旋遍历**：从矩形中心像素出发，按 `→↑←↓` 方向一圈圈向外旋转访问，
每读到一个非零 pickColor 就 `getObjectByPickColor` 记入 Set，凑够 `limit` 个即停。
注释里说明这是「在所有浏览器都能读深度缓冲之前」的 workaround——**用「离中心近≈离眼睛近」近似深度排序**，
所以 3×3 矩形下 `pick` 返回的第一个对象基本就是最上面的那个。

## 6. pickPosition：从深度缓冲复原世界坐标

「点到了谁」用颜色，「点到了哪」用深度。前提两个开关：
[`scene.useDepthPicking`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L917)（默认 true）
和 WebGL 深度纹理支持（能力探测即 `pickPositionSupported`，无深度纹理时
[`pickPositionWorldCoordinates`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L691) 直接抛错）。

深度从哪来？每次 pick pass（以及正常帧）里，[`executeCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L2796)
**逐视锥**把 globeDepth 深度纹理拷进 [`PickDepth`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickDepth.js#L13)：
[Scene.js L3128-L3133](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L3128) 调
[`pickDepth.update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickDepth.js#L65) +
[`executeCopyDepth`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickDepth.js#L107)，
拷贝 shader（[`updateCopyCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickDepth.js#L33)）
把深度值 **RGBA 打包**进颜色纹理（普通 FBO 读像素只有 RGBA 可读）；读回时
[`getDepth`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickDepth.js#L88)
按 1/255、1/65025、1/16581375 的尺度点积**解包**回 [0,1] 深度。

有了每视锥的深度，[`pickPositionWorldCoordinates`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L691)
（[`Picking.prototype.pickPosition`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L802)
再处理 2D/CV 模式的坐标轴换序与反投影）从近到远扫视锥：

1. [`getPickDepth(scene, i)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L71).getDepth 读 1 像素深度；
2. `depth ∈ (0,1)` 才有效——重建该视锥的 near/far（非首视锥 near 乘
   `scene.opaqueFrustumNearOffset`，与 [06 §多视锥](06-相机系统与视角控制.md) 的切片规则一致）并 `uniformState.updateFrustum`；
3. [`SceneTransforms.drawingBufferToWorldCoordinates`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/SceneTransforms.js#L397)
   用「该视锥的 view·projection 逆矩阵」把像素+深度反解成 ECEF 世界坐标——**这正是深度的精度随视锥近远比恶化、必须多视锥切片的原因**。

**限制与增强**：

- 拷深度时机在半透明 pass 之后、但**默认不渲染半透明的深度**——`pickPosition` 默认打在不透明面上；
  想让半透明体也产生深度，开 [`scene.pickTranslucentDepth`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L917)，
  由 [`renderTranslucentDepthForPick`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L645)
  额外渲染一趟（写 [PickDepthFramebuffer](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PickDepthFramebuffer.js#L46)，代价 = 再画一遍场景）；
- 结果按窗口坐标缓存（§1 的 `_pickPositionCache`），同一帧多次调用同一点零额外开销。

## 7. drillPick：剥洋葱式逐层拾取

「这一像素从近到远叠了什么」= 反复 pick + 隐藏上一次的结果。核心是
[`Picking.prototype.drillPick`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L943)
包出来的 [`drillPick(pickCallback, limit)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L895) 循环：
每轮 `pickCallback(limit - results.length)` 拿到一批结果，交给
[`addDrillPickedResults`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L827)
记账并**按精度从细到粗隐藏**：

| 拾取对象形态 | 隐藏手段 | 恢复 |
|---|---|---|
| Primitive 的某个 instance | `primitive.getGeometryInstanceAttributes(id).show = false`（[L855](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L855)） | 写回 true |
| [`Cesium3DTileFeature`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Cesium3DTileFeature.js) | `feature.show = false`（[L866](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L866)） | 写回 true |
| 其他整体 primitive | `primitive.show = false`（[L874](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L874)） | 写回 true |

全部轮次结束后统一还原，再返回由近及远的对象数组。注意：**每钻一层就是一次完整的 pick pass GPU 往返**，
`limit` 不给默认 `Number.MAX_VALUE`（钻到没有为止）——重叠严重时记得给上限。

## 8. 射线拾取家族与「地形拾取考古」

[`scene.pickFromRay`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L5184)
（以及 sampleHeight/clampToHeight 系列）不走屏幕像素，而是把射线变成一个**离屏小相机**：
[`updateOffscreenCameraFromRay`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L984)
让 0.1 米宽的正交相机趴在射线上，[`getRayIntersection`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L1113)
渲染 1×1 像素的 pick/depth 后反算交点。`*MostDetailed` 版本
（[`updateMostDetailedRayPicks`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L1039)、
[`MostDetailedRayPick`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L971)）
允许 3D Tiles 在多帧里持续细化到最精再返回（Promise）。

**版本考古**：老版本 Cesium 的地形坐标拾取走 CPU——`GlobeSurfaceTileProvider.pick → pickTerrain → pickTriangle`
对 quantized-mesh 逐三角形求交。**1.145 里这条链路已整体移除**（grep 全库无 `pickTriangle`），
地形拾取只剩两条路：屏幕拾取走本文 §6 的深度复原；射线拾取走上述离屏相机。
顺带一提：`globe` 裸地表没有 pickId（§4），所以 **`scene.pick` 点在纯地形上返回 `undefined`，`scene.pickPosition` 才拿得到位置**。

## 9. 与 05 §5 的关系：pick pass 在多视锥编排中的位置

pick pass 复用 [05 §5](05-帧更新与渲染循环.md) 讲的整条 `executeCommands` 管线：
同样的「远→近逐视锥、每视锥清深度、Globe→…→OPAQUE→TRANSLUCENT 的 Pass 顺序」，
区别只在每个环节被 `passes.pick` 分流（环境不画、命令换变体、OIT/后处理跳过、末尾多一步拷深度）。
所以读源码时你会看到 `executeCommands` 里到处是 `picking` 判断——它不是另一套渲染器，而是**同一台渲染器的拾取模式**。
这也是为什么每次 pick 的成本 ≈ 一次「阉割版」渲染：别在 mousemove 里无节制地 `drillPick`。

## 10. 动手实验（Sandcastle 控制台）

```js
const handler = new Cesium.ScreenSpaceEventHandler(viewer.canvas);

// 1) 基本拾取：先加一个矩形 entity，然后点它
handler.setInputAction((movement) => {
  const picked = viewer.scene.pick(movement.position);
  console.log("picked:", picked);            // {primitive, id} —— id 就是 Entity
  console.log("position:", viewer.scene.pickPosition(movement.position));
}, Cesium.ScreenSpaceEventType.LEFT_CLICK);

// 2) 宽矩形拾取：拖一个框拿多对象
// scene.pick(windowPos, 20, 20) 返回数组？——注意 pick 只取第一个，
// 多对象用 scene.drillPick(windowPos, 10, 20, 20)

// 3) 钻取：叠三个矩形看穿透
viewer.scene.drillPick(new Cesium.Cartesian2(300, 300), 5);

// 4) 半透明深度：放一个半透明盒子，对比开/关后的 pickPosition
viewer.scene.pickTranslucentDepth = true;

// 5) 地形高度采样（离屏射线路线）
Cesium.sampleTerrainMostDetailed(viewer.terrainProvider, [
  Cesium.Cartographic.fromDegrees(116.39, 39.9),
]).then((r) => console.log(r[0].height));

// 6) 感受 pick 的 GPU 停顿：拖动地图时连续 pick，Profile 里找长任务
```

## 11. 常见坑

- **`scene.pick` 点在裸地形/无对象处返回 `undefined`**——先判空再用 `.id`；地形坐标请配合 [`pickPosition`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L5103)；
- **`pickPosition` 返回 `undefined` 的高频原因**：浏览器不支持深度纹理（查 `scene.pickPositionSupported`）、`useDepthPicking` 被关、点在半透明体上而 `pickTranslucentDepth` 未开、或点在天空（深度=1）；
- **鼠标移动事件里高频 `pick`/`drillPick` 会掉帧**——每次都是一趟 GPU 往返，`drillPick` 还是 N 趟；高频场景改用 [`pickAsync`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4896) 或节流；
- **pick 返回的对象结构随类型变化**：Entity 图元是 `{primitive, id}`，3D Tiles 是 [`Cesium3DTileFeature`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Cesium3DTileFeature.js)，矢量要素是 feature 对象——写通用代码时用 `picked.id ?? picked` 两手准备；
- **2D 模式的 `pickPositionWorldCoordinates`** 会做坐标轴换序（[L802-L817](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L802)）再反投影，直接拿原始返回值当 ECEF 用会偏出一个轴；
- **别在 pick 期间修改场景**：pickBegin 到 pickEnd 之间 JobScheduler 被禁用（[L337](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L337)），同步 pick 是「读旧世界」的快照语义。

## 12. 小结与下一篇

拾取 = **颜色编码（pickId↔uint32）+ 深度复原（多视锥逐层解包）+ 钻取循环（逐级隐藏）**，全部复用 05 的渲染管线；
1.145 的新结构是 `Scene`（门面）→ [`Picking`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L46)（编排）两层拆分，老的 CPU `pickTriangle` 已成历史。
