# 14 · 向量数据源：GeoJSON / KML / Custom 与集合、聚合全景

> 阅读前提：读过 [03-Entity数据体系.md](03-Entity数据体系.md)（Entity/Property/Visualizer 三层模型）与 [01-Viewer创建与场景初始化.md](01-Viewer创建与场景初始化.md)（Viewer 接线）。
> 一句话：向量数据源 = 「把外部格式（GeoJSON/KML/GPX/CZML）翻译成 Entity 集合」的适配器；本篇讲清 load 管线、格式分支、容器次序与点聚合。

**本文讲什么**：

- DataSource 接口契约与 `load()` 通用管线（Promise、name/credit 归一、线程模型实测）
- [`DataSourceCollection.js`](../packages/engine/Source/DataSources/DataSourceCollection.js) 容器语义（add 的 Promise 透传、raise/lower 渲染次序）
- [`GeoJsonDataSource.js`](../packages/engine/Source/DataSources/GeoJsonDataSource.js)：load 主入口、crs 坐标系分支、process* 系列、TopoJSON 展开、simplestyle 翻译
- [`KmlDataSource.js`](../packages/engine/Source/DataSources/KmlDataSource.js)：KMZ 解包、样式系统、NetworkLink 三种刷新模式、DeferredLoading 时间片

- 与 [`DataSourceDisplay.js`](../packages/engine/Source/DataSources/DataSourceDisplay.js)、Viewer 的接线（[03](03-Entity数据体系.md) 交叉）

## 1. DataSource 接口契约：五个属性 + 四个事件 + 一个 update

所有数据源共同实现的最小契约定义在 [`DataSource.js`](../packages/engine/Source/DataSources/DataSource.js)（构造 [`L13`](../packages/engine/Source/DataSources/DataSource.js#L13)）：`name / show / entities / clock / clustering` 五个属性，
`changedEvent / errorEvent / loadingEvent` 三个事件（KML 另加 `refreshEvent / unsupportedNodeEvent`），以及可选的 [`update(time)`](../packages/engine/Source/DataSources/DataSource.js#L103)
——**它由 [`DataSourceDisplay.update`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L311) 每帧调用**，是「时间驱动型」数据源（CZML/KML NetworkLink）的钩子；
静态型数据源（GeoJSON/Custom）不实现或恒返回 true。加载态由静态助手 [`DataSource.setLoading`](../packages/engine/Source/DataSources/DataSource.js#L110) 统一翻转 `isLoading` 并派发 `loadingEvent`。

### load 通用管线（四个数据源同构）

```
StaticDataSource.load(data, options)
  └─ new XxxDataSource() → instance.load(data, options)
       ├─ setLoading(true)                      // loadingEvent
       ├─ data 是 string/Resource？→ Resource.createIfNeeded + fetch*  // 网络层
       ├─ credit 字符串 → Credit；resource.credits 累积               // 版权归一
       ├─ 格式解析（JSON.parse / DOMParser / zip 解包）                // 各自分支
       ├─ 遍历要素 → EntityCollection.add(entity)                     // 见 §3/§5
       └─ Promise.all(挂起的子 promise) → setLoading(false) → resolve(this)
```

| 数据源 | 静态 load | 实例 load | 网络取数 | 解析线程 |
|---|---|---|---|---|
| GeoJSON | [`L614`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L614) | [`L892`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L892) | [`fetchJson`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L929) | **主线程**（JSON.parse + 同步遍历） |
| KML/KMZ | [`L3603`](../packages/engine/Source/DataSources/KmlDataSource.js#L3603) | [`L3745`](../packages/engine/Source/DataSources/KmlDataSource.js#L3745) | [`fetchBlob`](../packages/engine/Source/DataSources/KmlDataSource.js#L3361) | 主线程 DOMParser；**KMZ 压缩走 zip.js worker（wasm）** [`L3299-L3302`](../packages/engine/Source/DataSources/KmlDataSource.js#L3299-L3302) |
| CZML | [`L4868`](../packages/engine/Source/DataSources/CzmlDataSource.js#L4868) | [`L5077`](../packages/engine/Source/DataSources/CzmlDataSource.js#L5077) | fetchJson | 主线程（详见 [10](10-时间与动态属性.md)） |
| GPX | [`L774`](../packages/engine/Source/DataSources/GpxDataSource.js#L774) | [`L942`](../packages/engine/Source/DataSources/GpxDataSource.js#L942) | fetchXml | 主线程 DOMParser |

**线程模型结论（本地 grep 实测）**：DataSources 目录下没有任何 [`TaskProcessor`](../packages/engine/Source/Core/TaskProcessor.js) 引用；
数据源解析全在主线程，唯一的 worker 是 KMZ 解压（zip.js 自带 worker + wasm，不走 Cesium 的 TaskProcessor 体系）。
对比：地形网格解码是正经 worker 管线——[`HeightmapTerrainData.js`](../packages/engine/Source/Core/HeightmapTerrainData.js#L173) 预建两个
`TaskProcessor`（[`L173-L174`](../packages/engine/Source/Core/HeightmapTerrainData.js#L173-L174)），见 [07-地形系统.md](07-地形系统.md)。
**含义：超大 GeoJSON 会阻塞主线程，没有隐藏的后台解析可用**（常见坑见 §9）。

## 2. DataSourceCollection：容器、Promise 透传与渲染次序

[`DataSourceCollection`](../packages/engine/Source/DataSources/DataSourceCollection.js#L16) 是纯数组容器 + 三个事件
（[`dataSourceAdded / dataSourceRemoved / dataSourceMoved`](../packages/engine/Source/DataSources/DataSourceCollection.js#L18-L20)），
自身不碰渲染——**渲染反应发生在 DataSourceDisplay 的事件订阅里**（§3）。

- **[`add`](../packages/engine/Source/DataSources/DataSourceCollection.js#L84) 接受 `DataSource | Promise<DataSource>`**：先 `Promise.resolve(dataSource)`，resolve 后才真正入列并广播。所以 `viewer.dataSources.add(GeoJsonDataSource.load(url))` 这一惯用写法里，
  下载/解析期间集合中**没有**该源；若中途 `removeAll`，[`dataSources === that._dataSources`](../packages/engine/Source/DataSources/DataSourceCollection.js#L97) 守卫会丢弃迟到结果（防僵尸源复活）。
- **[`remove(ds, destroy)`](../packages/engine/Source/DataSources/DataSourceCollection.js#L114)**：先广播 `dataSourceRemoved`（DataSourceDisplay 借此销毁 visualizers），`destroy=true` 时再销毁源对象——这是标准清理姿势。
- **次序 API**：[`raise`](../packages/engine/Source/DataSources/DataSourceCollection.js#L253) / [`lower`](../packages/engine/Source/DataSources/DataSourceCollection.js#L266)（±1 位）、
  [`raiseToTop`](../packages/engine/Source/DataSources/DataSourceCollection.js#L279) / [`lowerToBottom`](../packages/engine/Source/DataSources/DataSourceCollection.js#L302)。数组索引即 z 序：
  索引大的源画在上面（DataSourceDisplay 把每个源的 PrimitiveCollection 按同序摆放，见 §3）。
- [`getByName`](../packages/engine/Source/DataSources/DataSourceCollection.js#L198) 按名取（名字不唯一，返回数组）。

## 3. 与 DataSourceDisplay / Viewer 的接线（01/03 交叉）

[03 §4/§5](03-Entity数据体系.md) 已拆过 Visualizer 层，这里补数据源维度的挂载链：

1. **构造**：[`CesiumWidget`](../packages/engine/Source/Widget/CesiumWidget.js#L476) 自建 `DataSourceCollection`（可由 `options.dataSources` 注入共享集合），
   再 [`new DataSourceDisplay({scene, dataSourceCollection})`](../packages/engine/Source/Widget/CesiumWidget.js#L483-L487)。
2. **事件订阅**：[`DataSourceDisplay` 构造器](../packages/engine/Source/DataSources/DataSourceDisplay.js#L59-L76) 用 EventHelper 挂上集合三大事件 + `scene.postRender`。
3. **加源** [`_onDataSourceAdded`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L476)：每个源分得**自己的**子 `PrimitiveCollection` 与 `OrderedGroundPrimitiveCollection`；
   调 [`entityCluster._initialize(scene)`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L494) 并把 cluster 挂进该子集合（[`L496`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L496)）；
   最后用 [`visualizersCallback`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L500) 为该源创建全套 Visualizer（默认清单见 [`defaultVisualizersCallback`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L169)，即 [03 §4](03-Entity数据体系.md) 的那八类）。
4. **不入列的 defaultDataSource**：[`new CustomDataSource()`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L105) 直接挂在 display 上——`viewer.entities` 的真身（getter [`CesiumWidget L681`](../packages/engine/Source/Widget/CesiumWidget.js#L681)）。
5. **移序** [`_onDataSourceMoved`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L533)：同步 raise/lower 该源的子 PrimitiveCollection；
   `newIndex===0` 时先 `lowerToBottom` 再 `raise` 回一位——**index 0 恒留给 defaultDataSource**，防止 `viewer.entities` 被压底。
6. **每帧驱动**：`CesiumWidget._onTick` 里 [`dataSourceDisplay.update(time)`](../packages/engine/Source/Widget/CesiumWidget.js#L1208)（三层循环见 [03 §5](03-Entity数据体系.md)：先 `dataSource.update(time)`（NetworkLink 刷新就在这里），再逐 visualizer 差量同步）；
   帧尾 [`_postRender`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L361) 聚合各源 `_credit/_resourceCredits` 添到屏幕版权。
7. **Viewer 侧**：[`Viewer.js L946-L973`](../packages/widgets/Source/Viewer/Viewer.js#L946-L973) 订阅 `dataSourceAdded` 跟踪各源 clock 变化（`automaticallyTrackDataSourceClocks`）；`viewer.dataSources` getter 在 [`Viewer.js L1251`](../packages/widgets/Source/Viewer/Viewer.js#L1251)。

## 4. GeoJsonDataSource：load → crs → process* 三段式

### 4.1 入口与 preload

- 实例 [`load`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L892)（清空再装）与 [`process`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L904)（增量追加）共用内部 [`preload`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L908)，只差 `clear` 布尔——**增量大文件的正确姿势是 `process` 分批喂**。
- preload 做四件事：`setLoading(true)`；credit 归一（字符串→`Credit`，[`L917-L923`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L917-L923)）；
  URL→[`fetchJson`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L929)（对象直接透传，已是 JSON 就零 IO）；
  把 marker/stroke/fill/clampToGround 等散选项预组装成 Property 形态（[`L943-L955`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L943-L955)，全局默认值定义在 [`L41-L47`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L41-L47)，marker 48px / stroke 宽 2 / 黄色 10% 透明填充）。
- 真正的装载 [`load（模块内函数）L984`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L984)：name 从 URL 文件名归一（[`L985-L991`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L985-L991)）→ 类型查表 → crs 解析 → 遍历 → 等 `_promises` 全清（PinBuilder 画 pin 是异步 canvas，见 §4.4）。

### 4.2 crs 坐标系分支（旧版 GeoJSON 遗产）

crs 解析在 [`L999-L1040`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L999-L1040)，三种形态：

| crs.type | 分支 | 行号 |
|---|---|---|
| `name` | 查 [`crsNames`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L33)（内置 `CRS84`/`EPSG:4326` → [`defaultCrsFunction`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L29)） | [`L1010-L1016`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L1010-L1016) |
| `link` | 先 [`crsLinkHrefs`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L39) 再 [`crsLinkTypes`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L40)，handler 返回 **Promise<函数>**（可在线拉取投影定义） | [`L1017-L1030`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L1017-L1030) |
| `EPSG` | 拼 `EPSG:${code}` 再查 crsNames | [`L1031-L1035`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L1031-L1035) |

两个关键细节：**`crs: null` 是合法值但整个装载变 no-op**（[`L1047-L1049`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L1047-L1049)，坐标语义未知时拒绝瞎猜）；
crsFunction 是「坐标数组 → [`Cartesian3`](../packages/engine/Source/Core/Cartesian3.js#L20)」的纯函数（默认实现经 `fromDegrees`，坐标系语义见 [11 §2](11-坐标变换.md)），每个坐标点都会过它
（[`coordinatesArrayToCartesianArray`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L181)）。

### 4.3 process* 系列：类型查表 + Entity 组装

两级查表：顶层对象 [`geoJsonObjectTypes`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L189)（Feature/FeatureCollection/各 geometry/Topology），
Feature 内部几何 [`geometryTypes`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L202)。
`Feature` 分发器 [`processFeature L214`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L214)：有 geometry 走几何 handler，否则仍造 Entity（挂 properties/name/description）；
`GeometryCollection`（[`L246`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L246)）对每个成员几何**复用同一个 feature 上下文**——一个 Feature 可裂成多个 Entity 但共享 id/属性。

所有 Entity 出自 [`createObject L113`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L113)：

- **id**：无 id 或非 Feature → `createGuid()`；重复 id 自动加后缀 `_2/_3`（[`L118-L126`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L118-L126)）；
- **name**：simplestyle `title` 优先，否则四级回退（精确 title → 精确 name → 含 title → 含 name，[`L133-L160`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L133-L160)）；
- **description**：无显式 description 时由 [`defaultDescribe L68`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L68) 把 properties 拼成 InfoBox 表格 HTML（嵌套对象递归展开；simplestyle 字段被 [`simpleStyleIdentifiers L55`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L55) 排除）。

几何工厂三兄弟（全部尊重 [simplestyle](https://github.com/mapbox/simplestyle-spec) 属性覆盖默认值）：

| 工厂 | 行号 | 关键行为 |
|---|---|---|
| [`createPoint`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L265) | L265-L331 | `marker-color/size/symbol` 覆盖；symbol 单字符→文字 pin，否则 Maki 图标；无高度且 clampToGround → `HeightReference.CLAMP_TO_GROUND`（[`L307-L309`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L307-L309)）；**pin 画布是异步 promise**，收进 `dataSource._promises`（[`L323-L330`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L323-L330)）由 load 统一等待 |
| [`createLineString`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L349) | L349-L398 | `stroke/stroke-width/stroke-opacity` 覆盖；`clampToGround` 直通 PolylineGraphics（贴地画线）；arcType 固定 **RHUMB**（恒向线，[`L397`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L397)） |
| [`createPolygon`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L429) | L429-L517 | 首环为外边界，其余环全部进 `PolygonHierarchy.holes`（[`L484-L491`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L484-L491)）；坐标带第三维 → `perPositionHeight=true`，否则非贴地时 height=0（[`L515-L518`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L515-L518)）；arcType 同样 RHUMB（[`L477`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L477)） |

Multi\* 系列只是循环调单数版（MultiPoint [`L336`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L336)、MultiLineString [`L416`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L416)、MultiPolygon [`L528`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L528)）。

### 4.4 TopoJSON：先展开再复用

[`processTopology L541`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L541) 对 `geometry.objects` 的每个成员调

### 4.5 构造器与聚合挂点

[`GeoJsonDataSource(name)` L592`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L592) 持有 `_promises`（PinBuilder 异步）、`_pinBuilder`、`_entityCluster`（[`L600-L603`](../packages/engine/Source/DataSources/GeoJsonDataSource.js#L600-L603)）；

## 5. KmlDataSource：二进制嗅探、样式解析与 NetworkLink

KML 是四个数据源里最重的一个（4221 行）：XML 解析、样式系统、KMZ 解包、NetworkLink 刷新、Tour/ScreenOverlay 一应俱全。

### 5.1 load 主链与 KMZ 解包

[`load（模块内）L3351`](../packages/engine/Source/DataSources/KmlDataSource.js#L3351) 的格式判定不是看后缀而是**嗅探**：URL 一律 `fetchBlob`，再由
[`isZipFile L320`](../packages/engine/Source/DataSources/KmlDataSource.js#L320)（读文件头魔数 `PK`）分流：

- **KML 文本**：`readBlobAsText` → [`insertNamespaces L349`](../packages/engine/Source/DataSources/KmlDataSource.js#L349)（补默认 kml/atom/gx 命名空间，容错省 xmlns 的手写文件）→ [`removeDuplicateNamespaces L376`](../packages/engine/Source/DataSources/KmlDataSource.js#L376) → DOMParser（[`L3406`](../packages/engine/Source/DataSources/KmlDataSource.js#L3406)）→ [`loadKml L3217`](../packages/engine/Source/DataSources/KmlDataSource.js#L3217)。
- **KMZ**：[`loadKmz L3290`](../packages/engine/Source/DataSources/KmlDataSource.js#L3290) 配置 zip.js 的 worker/wasm URI（[`L3299-L3302`](../packages/engine/Source/DataSources/KmlDataSource.js#L3299-L3302)），
  `ZipReader.getEntries()` 枚举条目：**doc.kml 的选取规则是「第一个 .kml，但根目录下的 .kml 优先」**（兼容 GE 写法，[`L3310-L3330`](../packages/engine/Source/DataSources/KmlDataSource.js#L3310-L3330)）；
  其余条目全部经 [`loadDataUriFromZip L404`](../packages/engine/Source/DataSources/KmlDataSource.js#L404) 转成 data URI 塞进 `uriResolver`——**图片/模型等嵌入资源靠它离线解析**；doc 本身走 [`loadXmlFromZip L397`](../packages/engine/Source/DataSources/KmlDataSource.js#L397)。找不到 .kml 直接抛错（[`L3338`](../packages/engine/Source/DataSources/KmlDataSource.js#L3338)）。

### 5.2 文档遍历：Feature 树 + DeferredLoading 时间片

- 节点类型查表 [`featureTypes L183`](../packages/engine/Source/DataSources/KmlDataSource.js#L183)（Document/Folder/Placemark/NetworkLink/ScreenOverlay/Tour…），几何类型 [`geometryTypes L1979`](../packages/engine/Source/DataSources/KmlDataSource.js#L1979)。
- [`processFeature L2220`](../packages/engine/Source/DataSources/KmlDataSource.js#L2220) 是所有 Feature 型节点的公共段：造 Entity（[`createEntity L447`](../packages/engine/Source/DataSources/KmlDataSource.js#L447) 把 atom 作者/链接/地址等非图形元数据挂进 `entity.kml` PropertyBag）；
  TimeStamp/TimeSpan → availability 并与父级求交（[`mergeAvailabilityWithParent L3973`](../packages/engine/Source/DataSources/KmlDataSource.js#L3973)）；
  **可见性沿祖先链递归判定**（「A Feature is visible only if it and all its ancestors are visible」，[`L2251-L2263`](../packages/engine/Source/DataSources/KmlDataSource.js#L2251-L2263)）。
- [`processFolder L2321`](../packages/engine/Source/DataSources/KmlDataSource.js#L2321) 先把 Folder 自身当 Feature 处理，再以它为 `parentEntity` 递归 Document——**KML 层级 = Entity.parent 链**（[03 §2](03-Entity数据体系.md) 的父子语义）。
- [`processPlacemark L2329`](../packages/engine/Source/DataSources/KmlDataSource.js#L2329)：找**第一个**认识的几何子节点处理；纯样式无几何的 Placemark 直接 `entity.merge(styleEntity)`。
- **[`DeferredLoading L194`](../packages/engine/Source/DataSources/KmlDataSource.js#L194)**：DOM 遍历器内部是个栈机器（`addNodes/process/wait`），**每处理 1 秒（首轮）/50ms（后续）主动 `setTimeout(0)` 让出主线程**（[`_giveUpTime L264`](../packages/engine/Source/DataSources/KmlDataSource.js#L264)），保证大 KML 不冻结页面——这是主线程解析器里的「手动协程」，GeoJSON 侧没有对应机制。
- 坐标解析 [`readCoordinate L480`](../packages/engine/Source/DataSources/KmlDataSource.js#L480)：KML 文本是 `lon,lat[,alt]` 十进制度字符串，逐点 `fromDegrees`；altitudeMode（clampToGround/relative/absolute）在 [`heightReferenceFromAltitudeMode L1351`](../packages/engine/Source/DataSources/KmlDataSource.js#L1351) 翻译成 HeightReference。

### 5.3 样式系统：三级解析

[`processStyles L1214`](../packages/engine/Source/DataSources/KmlDataSource.js#L1214) 先把文档内（与 [`<StyleMap>`](../packages/engine/Source/DataSources/KmlDataSource.js#L1116) 引用的）所有 `<Style>` 解析成一个 **styleCollection（伪 EntityCollection）**；
[`computeFinalStyle L1116`](../packages/engine/Source/DataSources/KmlDataSource.js#L1116) 为每个 Placemark 合成最终样式（inline style > 引用 style，normal/highlight 双态只取 normal），
外链 styleUrl 走 [`processExternalStyles L1204`](../packages/engine/Source/DataSources/KmlDataSource.js#L1204) 递归抓取；最后 [`applyStyle L1010`](../packages/engine/Source/DataSources/KmlDataSource.js#L1010) 把样式 Entity merge 进图形 Entity（[03 §3](03-Entity数据体系.md) 的 merge 机制）。

### 5.4 NetworkLink：三种刷新模式 + 相机驱动查询

NetworkLink 是 KML 独有的「动态数据源」能力，两段式实现：

1. **装载期** [`processNetworkLink L2996`](../packages/engine/Source/DataSources/KmlDataSource.js#L2996)：解析 `<Link>/<Url>` 的 href、`viewRefreshMode`（onStop/onRegion，**onRegion 不支持**只告警 [`L3033-L3039`](../packages/engine/Source/DataSources/KmlDataSource.js#L3033-L3039)）、
   `viewBoundScale`（视口 bbox 缩放系数）；onStop 模式默认注入 `BBOX=[west],[south],[east],[north]` 查询串（[`L3041-L3046`](../packages/engine/Source/DataSources/KmlDataSource.js#L3041-L3046)）；
   `viewFormat/httpQuery` 自定义参数经 [`processNetworkLinkQueryString L2816`](../packages/engine/Source/DataSources/KmlDataSource.js#L2816) 写入 Resource（含 canvas 尺寸/相机中心/lookAt 参数）。
   首次加载装进**独立 EntityCollection**，成功后以 `context = networkEntity.id` 合入主集合（子 KML 的重复 id 在同 context 下安全去重）。刷新配置记入 `_networkLinks`（AssociativeArray）。
2. **运行期** [`update(time) L3843`](../packages/engine/Source/DataSources/KmlDataSource.js#L3843)：被 DataSourceDisplay 每帧调用（§3）。
   [`RefreshMode L2792`](../packages/engine/Source/DataSources/KmlDataSource.js#L2792-L2795) 三态：
   - **INTERVAL**：`now - lastUpdated > interval` 即重拉（[`L3907-L3913`](../packages/engine/Source/DataSources/KmlDataSource.js#L3907-L3913)）；
   - **EXPIRE**：NetworkLinkControl 的 `<expires>` 给绝对时刻，过期重拉；
   - **STOP**：相机位姿变化超 `EPSILON7` 置 `needsUpdate`，**静置 time 秒后才拉**（防拖动风暴，[`L3919-L3927`](../packages/engine/Source/DataSources/KmlDataSource.js#L3919-L3927)）；
     相机状态快照存于构造器的 `_lastCameraView`（[`L3570-L3582`](../packages/engine/Source/DataSources/KmlDataSource.js#L3570-L3582)）。
   刷新结果替换旧子树（递归忽略子实体，[`L3902-L3906`](../packages/engine/Source/DataSources/KmlDataSource.js#L3902-L3906)），故**构造 KmlDataSource 必须传 camera/canvas**（[`ctor L3524`](../packages/engine/Source/DataSources/KmlDataSource.js#L3524) 的 options，`canvas` 供查询参数、`camera` 供 onStop），否则动态语义失效。
   实例 [`load L3745`](../packages/engine/Source/DataSources/KmlDataSource.js#L3745) 尾段把全源 availability 收敛成 DataSourceClock——与 CZML/GPX 同型（[10 §2](10-时间与动态属性.md) 的 updateClock 类比）。

其他特性一句话收束：Tour（[`processTour L2370`](../packages/engine/Source/DataSources/KmlDataSource.js#L2370) + [`KmlTour.js`](../packages/engine/Source/DataSources/KmlTour.js)）、
ScreenOverlay（[`processScreenOverlay L2466`](../packages/engine/Source/DataSources/KmlDataSource.js#L2466) 塞进 `screenOverlayContainer` DOM 容器，销毁时逆序弹出 [`L3831-L3832`](../packages/engine/Source/DataSources/KmlDataSource.js#L3831-L3832)）。
注：KML 无「featureByEntity 反查」API——想从 Entity 回查 KML 元数据，读 `entity.kml` PropertyBag 即可（装载期就写进了 Entity）。

## 6. CustomDataSource 与 GPX

- [`CustomDataSource L35`](../packages/engine/Source/DataSources/CustomDataSource.js#L35)：182 行的「空壳数据源」——构造即可用，`entities` 直通内部 EntityCollection，
  [`update L178`](../packages/engine/Source/DataSources/CustomDataSource.js#L178) 恒 true。两大用途：**手写数据分组**（`new CustomDataSource('名字')` 给一组手造 Entity 一个可 raise/lower 的壳）与 **defaultDataSource**（§3 第 4 点，`viewer.entities` 本体）。收编散 Entity 进集合，是它最被低估的用法。
- [`GpxDataSource`](../packages/engine/Source/DataSources/GpxDataSource.js#L774)：GPS 轨迹（wpt 航点/rte 航线/trk 航迹）→ Entity；[`loadGpx L554`](../packages/engine/Source/DataSources/GpxDataSource.js#L554) 同样以 `computeAvailability` 收敛出 DataSourceClock（[`L586-L600`](../packages/engine/Source/DataSources/GpxDataSource.js#L586-L600)），轨迹天然是时间序列（trkpt 带 `<time>`，喂给 [SampledPositionProperty](10-时间与动态属性.md)）。

## 7. EntityCluster 点聚合

### 7.1 配置面与触发机制

[`EntityCluster L35`](../packages/engine/Source/DataSources/EntityCluster.js#L35) 默认 `pixelRange=80`、`minimumClusterSize=2`（[`L38-L40`](../packages/engine/Source/DataSources/EntityCluster.js#L38-L40)）；
配置属性 [`enabled L522`](../packages/engine/Source/DataSources/EntityCluster.js#L522)（置位标脏 `_enabledDirty`）、
[`pixelRange L536`](../packages/engine/Source/DataSources/EntityCluster.js#L536)、[`minimumClusterSize L550`](../packages/engine/Source/DataSources/EntityCluster.js#L550)、
[`clusterBillboards/Labels/Points L570-L602`](../packages/engine/Source/DataSources/EntityCluster.js#L570-L602)（三类图元分别开关），任一改动只置 `_clusterDirty`，**不立即重算**。

**触发机制（与直觉不同）**：不在 update 里轮询，而是 [`_initialize L508`](../packages/engine/Source/DataSources/EntityCluster.js#L508) 由 DataSourceDisplay 在加源时调用
（§3 第 3 点），把聚合回调挂到 **[`scene.camera.changed`](../packages/engine/Source/DataSources/EntityCluster.js#L513) 事件**上——相机百分比变化超阈值才触发一次重聚
（回调首行 [`amount < 0.05 直接返回`](../packages/engine/Source/DataSources/EntityCluster.js#L225)，`Camera.changed` 的 percentageChanged 默认 0.5，见 [06 §5](06-相机系统与视角控制.md)）。
与 `scene.preUpdate/postRender` 的关系：聚合本体不直接订这两个事件，但 `Camera.changed` 由 Scene 帧循环在相机变化时派发（[05 §2](05-帧更新与渲染循环.md)），等效于「帧驱动的相机变化监听」。

### 7.2 聚合算法（declutter 回调）

[`createDeclutterCallback L223`](../packages/engine/Source/DataSources/EntityCluster.js#L223) 的单趟算法：

1. **收集屏幕坐标** [`getScreenSpacePositions L171`](../packages/engine/Source/DataSources/EntityCluster.js#L171)：遍历 label/billboard/point 三个集合，逐项算窗口坐标，全部先置 `clusterShow=false`（[`L182`](../packages/engine/Source/DataSources/EntityCluster.js#L182)）；
   3D 模式用 `EllipsoidalOccluder` 剔除**地平线背面**的点（[`L191-L196`](../packages/engine/Source/DataSources/EntityCluster.js#L191-L196)，椭球遮挡见 [11 §3](11-坐标变换.md)）。
   「label+billboard 同实体」的重复点位会在收集阶段跳一份，避免一物双算。
2. **包围盒扩张找邻居**：每个点建屏幕 bbox 并四向外扩 `pixelRange`（[`expandBoundingBox L79`](../packages/engine/Source/DataSources/EntityCluster.js#L79)、[`getBoundingBox L88`](../packages/engine/Source/DataSources/EntityCluster.js#L88)），
   邻居计数 ≥ `minimumClusterSize` 即成簇（[`L388`](../packages/engine/Source/DataSources/EntityCluster.js#L388)、[`L464`](../packages/engine/Source/DataSources/EntityCluster.js#L464)），成员标 `clustered` 防重入。
3. **出簇** [`addCluster L143`](../packages/engine/Source/DataSources/EntityCluster.js#L143)：同时造 label/billboard/point 三件套（默认只显示 label 显示计数），raise
   [`clusterEvent L160`](../packages/engine/Source/DataSources/EntityCluster.js#L160)——**业务代码在这个事件里改簇样式**（换图标/文字），参数是 `(clusteredEntities, cluster)`；未成簇的散点经 [`addNonClusteredItem L127`](../packages/engine/Source/DataSources/EntityCluster.js#L127) 恢复 `clusterShow=true`。
4. 相机高度未变（`_previousHeight` 相同）则跳过整套重算——聚合是高度敏感的，纯平移不重聚。

### 7.3 与 Visualizer 的接缝

数据通路：[`BillboardVisualizer ctor L61`](../packages/engine/Source/DataSources/BillboardVisualizer.js#L61) 接收该源的 EntityCluster，
造 billboard 时调 [`cluster.getBillboard(entity) L141`](../packages/engine/Source/DataSources/BillboardVisualizer.js#L141)——
[`getBillboard L755`](../packages/engine/Source/DataSources/EntityCluster.js#L755)/[`getLabel L709`](../packages/engine/Source/DataSources/EntityCluster.js#L709)/[`getPoint L801`](../packages/engine/Source/DataSources/EntityCluster.js#L801)
按 entity id 记账式取件（[`createGetEntity L634`](../packages/engine/Source/DataSources/EntityCluster.js#L634)），label/point Visualizer 同构。
**也就是说 Entity billboard 的真实宿主是 EntityCluster 内部的三个 PrimitiveCollection**，cluster 通过 `clusterShow` 单一开关控制成员显隐（不销毁不重建，数据仍在原地）——这就是 [03 §6](03-Entity数据体系.md) 里 BillboardCollection 直连路线与 Visualizer 路线的汇合点。

```js
// 标准用法（Sandcastle clustering 范式）
const ds = await Cesium.GeoJsonDataSource.load("points.geojson", { clampToGround: true });
await viewer.dataSources.add(ds);
ds.clustering.enabled = true;
ds.clustering.pixelRange = 30;          // 30px 内的点聚为一簇
ds.clustering.minimumClusterSize = 4;
ds.clustering.clusterEvent.addEventListener((entities, cluster) => {
  cluster.label.text = String(entities.length);   // 簇样式在这里改
  cluster.label.show = true; cluster.billboard.show = cluster.point.show = false;
});
```

## 9. 常见坑与动手实验

- **GeoJSON 大文件卡顿**：解析与 crsFunction 逐点换算全在主线程（§1），数万 Feature 会掉帧到白屏。对策：`process` 分片喂入、上游简化几何（turf simplify）、或转 3D Tiles（[04](04-3DTiles加载与LOD.md) 的海量路线）。
- **`crs: null` 静默空场景**：装载成功但一个 Entity 都没有（§4.2 no-op 分支），先看数据头的 crs。
- **polygon 顶点带高程却不立体**：GeoJSON 第三维存在时自动 `perPositionHeight`（§4.3），但如果想要统一 extrude 高度，需自己改 `entity.polygon.extrudedHeight`（[09 §3](09-几何图元与材质.md)）。
- **KML 不动是因为没传 camera**：NetworkLink 的 onStop/相机参数依赖构造时的 `{camera, canvas}`（§5.4）。
- **cluster 样式不生效**：`clusterEvent` 监听要在 `add` 之后（源被 `_initialize` 才有触发链路），且簇三件套默认只显示 label（§7.2）。
- **聚合后拾取**：簇 label 的 `id` 是成员 Entity id 数组（[`addCluster L158`](../packages/engine/Source/DataSources/EntityCluster.js#L158)），拾取到簇后可展开成员（拾取链路见 [08 §7](08-拾取系统.md)）。
- **实验**：同一份点数据分别用 GeoJSON 与手写 CustomDataSource 装载，开 `clustering` 拖动相机，在 `clusterEvent` 里 `console.log(entities.length)` 观察成簇粒度随 `pixelRange` 变化；再用 `raise/lower` 验证两源的遮挡次序翻转（§2）。
