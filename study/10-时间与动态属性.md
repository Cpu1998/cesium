# 10 · 时间与动态属性

> 阅读前提：读完 [03-Entity数据体系.md](03-Entity数据体系.md) §2（Property 初步）与 §6（时间轴驱动）——那两节从「Entity 被渲染」的视角带过 Property；本文换**时间视角**系统重讲：`clock.tick` 是引擎的心跳，Property 体系是「随时间变化的血肉」，两者在 `DataSourceDisplay.update(time)` 处汇合（03 §4）。
> 一句话：Cesium 不只是三维引擎，还是一台**时间机器**——场景里一切「会动的东西」，本质都是某个 Property 在回答「时刻 t 你是什么值」。

本文的主战场文件：

- [`JulianDate.js`](../packages/engine/Source/Core/JulianDate.js) —— 天文儒略日：时间的统一表示
- [`Clock.js`](../packages/engine/Source/Core/Clock.js) / [`ClockStep.js`](../packages/engine/Source/Core/ClockStep.js) / [`ClockRange.js`](../packages/engine/Source/Core/ClockRange.js) —— 心跳发生器与边界策略
- [`Timeline.js`](../packages/widgets/Source/Timeline/Timeline.js) —— 时间轴控件（`onTick` 的消费者）
- Property 家族（`packages/engine/Source/DataSources/`）—— [`Property.js`](../packages/engine/Source/DataSources/Property.js)、[`SampledProperty.js`](../packages/engine/Source/DataSources/SampledProperty.js)、[`SampledPositionProperty.js`](../packages/engine/Source/DataSources/SampledPositionProperty.js) 等

## 0. 全景：一帧里的时间从哪来

回看 [05 §4](05-帧更新与渲染循环.md) 的每帧骨架，时间就藏在 [`CesiumWidget.prototype.render`](../packages/engine/Source/Widget/CesiumWidget.js#L1140) 的三行里：

```
rAF 回调
 └─ CesiumWidget.render()                     CesiumWidget.js#L1140
     ├─ scene.initializeFrame()
     ├─ currentTime = this._clock.tick()      ← 心跳：算出新时刻，广播 onTick
     └─ scene.render(currentTime)             ← 时刻作为 frameState.time 贯穿整帧
```

`clock.tick()` 内部最后一句 [`this.onTick.raiseEvent(this)`](../packages/engine/Source/Core/Clock.js#L313) 会同步触发所有订阅者，其中最关键的是 CesiumWidget 在构造时挂上的 [`_onTick`](../packages/engine/Source/Widget/CesiumWidget.js#L1201)（订阅现场在 [L499](../packages/engine/Source/Widget/CesiumWidget.js#L499)）：

```js
// CesiumWidget.js L1201 起（【导读】已有中文注释）
_onTick(clock) {
  const time = clock.currentTime;
  const isUpdated = this._dataSourceDisplay.update(time);  // Entity→Primitive 差量同步（03 §4）
  ...
  entityView && entityView.update(time, ...);              // 跟踪实体的相机跟随
}
```

于是**时间流与渲染流在这里汇合**：`tick` 算时间 → `onTick` 驱动数据同步 → `scene.render(time)` 把时刻带给所有 `update(frameState)` 的模块。注意 `requestRenderMode` 下 rAF 与 `tick` 仍每帧执行（【导读】[L1140](../packages/engine/Source/Widget/CesiumWidget.js#L1141) 注释），省的只是真正画帧。

## 1. JulianDate：dayNumber + secondsOfDay 的 TAI 双字段拆分

[`class JulianDate`](../packages/engine/Source/Core/JulianDate.js#L199)（构造函数 [L205](../packages/engine/Source/Core/JulianDate.js#L205)）表示**天文儒略日**：公元前 4713 年 1 月 1 日正午起的天数。设计要点有三：

1. **双字段拆精度**：[`dayNumber`](../packages/engine/Source/Core/JulianDate.js#L66)（整天数）+ [`secondsOfDay`](../packages/engine/Source/Core/JulianDate.js#L72)（秒，支持小数/负数/超一天，[`setComponents` L114](../packages/engine/Source/Core/JulianDate.js#L114) 负责归一化）。单个 double 表示全天数会丢精度，拆开后 `secondsDifference` 才够准。
2. **内部永远存 TAI**（国际原子时，[`TimeStandard.TAI`](../packages/engine/Source/Core/TimeStandard.js#L30)）：TAI 没有闰秒、单调均匀，算术安全；对外可用 [`TimeStandard.UTC`](../packages/engine/Source/Core/TimeStandard.js#L21) 构造/读取，闰秒换算走 [`leapSeconds` 表 L1201](../packages/engine/Source/Core/JulianDate.js#L1201) 与 [`computeTaiMinusUtc` L983](../packages/engine/Source/Core/JulianDate.js#L983)。
3. **不可变风格**：所有运算都返回新实例（或写入调用者给的 `result`），配合模块级 scratch 变量做到零分配热路径。

高频静态方法速查（全部本地 grep 定义行）：

| 类别 | 方法 | 定义行 |
|---|---|---|
| 构造/解析 | [`fromIso8601`](../packages/engine/Source/Core/JulianDate.js#L312) / [`fromDate`](../packages/engine/Source/Core/JulianDate.js#L277) / [`now`](../packages/engine/Source/Core/JulianDate.js#L615) | 字符串/JS Date → JulianDate |
| 输出 | [`toDate`](../packages/engine/Source/Core/JulianDate.js#L717) / [`toIso8601`](../packages/engine/Source/Core/JulianDate.js#L749) / [`toGregorianDate`](../packages/engine/Source/Core/JulianDate.js#L626) | 注意 `toIso8601` 默认保留 3 位小数（毫秒） |
| 运算 | [`addSeconds` L1009](../packages/engine/Source/Core/JulianDate.js#L1009) / `addMinutes` [L1037](../packages/engine/Source/Core/JulianDate.js#L1037) / `addHours` [L1063](../packages/engine/Source/Core/JulianDate.js#L1063) / `addDays` [L1089](../packages/engine/Source/Core/JulianDate.js#L1089) | 都是「加到 TAI 秒上再归一化」 |
| 差值 | [`secondsDifference` L939](../packages/engine/Source/Core/JulianDate.js#L939) / [`daysDifference` L961](../packages/engine/Source/Core/JulianDate.js#L961) / [`totalDays` L920](../packages/engine/Source/Core/JulianDate.js#L920) | 差值是普通 number，可放心乘除 |
| 比较 | [`compare` L858](../packages/engine/Source/Core/JulianDate.js#L858) / [`equalsEpsilon` L903](../packages/engine/Source/Core/JulianDate.js#L903) / `lessThan` [L1113](../packages/engine/Source/Core/JulianDate.js#L1113) 系 | `equalsEpsilon` 是判等首选 |

**坑**：`new Date(ms)` 的毫秒时间戳别直接当秒用；`JulianDate.secondsDifference(a, b)` 是 `a − b`（左减右），符号别记反。

## 2. Clock：一个自带策略的秒表

[`function Clock`](../packages/engine/Source/Core/Clock.js#L43) 只做一件事：每次 [`tick()`](../packages/engine/Source/Core/Clock.js#L258) 把 `currentTime` 往前推一截并广播 `onTick`。但它有**两组策略开关**决定「推多少、越界怎么办」：

### 2.1 双闸门：canAnimate × shouldAnimate

`tick` 第一行判断 [`if (this.canAnimate && this._shouldAnimate)`](../packages/engine/Source/Core/Clock.js#L262)：两票都为真时间才前进。`shouldAnimate`（getter/setter [L233](../packages/engine/Source/Core/Clock.js#L233)）是用户意图（「播放/暂停」按钮），`canAnimate` 是系统许可——典型场景：`CesiumWidget` 的 `_canAnimateUpdateCallback` 在 `DataSourceDisplay.update` 返回 false（几何还在异步算）时暂停动画（[CesiumWidget.js L1193](../packages/engine/Source/Widget/CesiumWidget.js#L1193)，对应构造参数 `allowDataSourcesToSuspendAnimation`）。

### 2.2 ClockStep：推多少

| 值 | 定义行 | 语义 |
|---|---|---|
| `TICK_DEPENDENT` | [ClockStep.js L20](../packages/engine/Source/Core/ClockStep.js#L20) | 每帧固定加 `multiplier` 秒——帧率越高跑得越快，只适合步进调试 |
| `SYSTEM_CLOCK_MULTIPLIER`（默认） | [ClockStep.js L29](../packages/engine/Source/Core/ClockStep.js#L29) | 加「真实流逝秒 × [`multiplier`](../packages/engine/Source/Core/Clock.js#L183)」——帧率无关，动画标准档 |
| `SYSTEM_CLOCK` | [ClockStep.js L38](../packages/engine/Source/Core/ClockStep.js#L38) | 直接贴真实系统时间（multiplier 被忽略并重置为 1） |

### 2.3 ClockRange：越界怎么办

| 值 | 定义行 | 越界行为（[`tick` L285–L307](../packages/engine/Source/Core/Clock.js#L285)） |
|---|---|---|
| `UNBOUNDED`（默认） | [ClockRange.js L19](../packages/engine/Source/Core/ClockRange.js#L19) | 不管，随便跑出 `[startTime, stopTime]` |
| `CLAMPED` | [ClockRange.js L28](../packages/engine/Source/Core/ClockRange.js#L28) | 钳在 stopTime，触发一次 [`onStop`](../packages/engine/Source/Core/Clock.js#L126) |
| `LOOP_STOP` | [ClockRange.js L39](../packages/engine/Source/Core/ClockRange.js#L39) | 超出的秒数折回 startTime 继续（循环），每次回绕也发 `onStop` |

三个事件都挂在构造函数里：[`onTick` L121](../packages/engine/Source/Core/Clock.js#L121)（每帧必发）、`onStop`（[L126](../packages/engine/Source/Core/Clock.js#L126)）、`onStart`——**`onTick` 是同步广播，订阅者里别做重活**，否则拖慢整个 rAF。

### 2.4 Viewer 里的时钟链

```
Viewer 构造                    Viewer.js（packages/widgets/Source/Viewer）L519 起
 └─ new ClockViewModel(clock)  widgets/Source/ClockViewModel.js#L19   控件与 Clock 之间的 VM
     ├─ Animation 控件          Viewer.js#L821                        播放/倍速/日期 UI
     └─ new Timeline(...)       Viewer.js#L837                        时间轴（§3）
CesiumWidget 构造时兜底 new Clock()（[L333](../packages/engine/Source/Widget/CesiumWidget.js#L333)），
并订阅 onTick（[L499](../packages/engine/Source/Widget/CesiumWidget.js#L499)）
```

还有一个「声明式时钟」[`DataSourceClock`](../packages/engine/Source/DataSources/DataSourceClock.js#L15)：它是数据源带的时钟参数包（`startTime/stopTime/multiplier` 等全是 [`createRawPropertyDescriptor`](../packages/engine/Source/DataSources/DataSourceClock.js#L45) 包装的可写属性，`multiplier` 在 [L85](../packages/engine/Source/DataSources/DataSourceClock.js#L85)），Viewer 跟踪某个 DataSource 时会把它的 `clock` 字段克隆到 `viewer.clock`（入口即 03 §6 讲过的 `_clockTrackedDataSource` setter）。

## 3. Timeline 控件与 onTick 事件流

[`function Timeline`](../packages/widgets/Source/Timeline/Timeline.js#L103)（widgets 包）是纯展示/交互控件：构造时 [`clock.onTick.addEventListener(this.updateFromClock, this)`](../packages/widgets/Source/Timeline/Timeline.js#L188)，每帧 [`updateFromClock`](../packages/widgets/Source/Timeline/Timeline.js#L701) 重绘刻度与游标；用户拖拽/缩放（[`zoomTo` L273](../packages/widgets/Source/Timeline/Timeline.js#L273)）则反向写 `clock.currentTime`。容器尺寸变了记得 [`resize()` L989](../packages/widgets/Source/Timeline/Timeline.js#L989)。

把 §0–§3 连起来，一条完整的时间事件流：

```
rAF ─→ CesiumWidget.render ─→ clock.tick()                    Core/Clock.js#L258
                                 │ 推进 currentTime（双闸门+ClockStep+ClockRange）
                                 ├─→ onStop.raiseEvent（越界时）   Clock.js#L293/#L305
                                 └─→ onTick.raiseEvent            Clock.js#L313
                                      ├─→ Timeline.updateFromClock  重绘时间轴
                                      └─→ CesiumWidget._onTick      CesiumWidget.js#L1201
                                           └─→ DataSourceDisplay.update(time)   §7
       scene.render(currentTime) ─→ frameState.time 交给渲染侧（07 §3 的第③拍等消费者）
```

## 4. Property 体系：随时间变化的值的统一接口

[03 §2](03-Entity数据体系.md) 讲过「Entity 的每个字段都是 Property」；这里补全体系图。约定接口极简：`getValue(time, result)` 返回该时刻的值，`isConstant` 告诉消费方能否缓存，`definitionChanged`（Event）在定义变化时通知（Visualizer 差量同步的依据，见 [03 §5](03-Entity数据体系.md)）。[`Property.js`](../packages/engine/Source/DataSources/Property.js) 本体只有静态工具：[`equals` L73](../packages/engine/Source/DataSources/Property.js#L73)、[`arrayEquals` L80](../packages/engine/Source/DataSources/Property.js#L80)、[`isConstant` L99](../packages/engine/Source/DataSources/Property.js#L99)。

全家福（值属性；位置属性是带参考系特化版）：

| Property | 定义行 | `getValue(time)` 行为 | 典型用途 |
|---|---|---|---|
| [`ConstantProperty`](../packages/engine/Source/DataSources/ConstantProperty.js#L14) | 常量 | 直接返回存的值（[L57](../packages/engine/Source/DataSources/ConstantProperty.js#L57)） | 90% 的 entity 字段 |
| [`SampledProperty`](../packages/engine/Source/DataSources/SampledProperty.js#L158) | 采样序列 | **插值**（§5） | 时间序列数据 |
| [`TimeIntervalCollectionProperty`](../packages/engine/Source/DataSources/TimeIntervalCollectionProperty.js#L43) | 分段常量 | 查 `time` 落在哪个 interval，取该段 data（[L103](../packages/engine/Source/DataSources/TimeIntervalCollectionProperty.js#L103)） | 阶梯状态（可见性、离散档位） |
| [`CompositeProperty`](../packages/engine/Source/DataSources/CompositeProperty.js#L55) | 分段拼装 | 按时间把内层 property「缝」起来（[L115](../packages/engine/Source/DataSources/CompositeProperty.js#L115)） | 前半段插值、后半段常量 |
| [`CallbackProperty`](../packages/engine/Source/DataSources/CallbackProperty.js#L15) | 函数 | 调用回调（[L59](../packages/engine/Source/DataSources/CallbackProperty.js#L59)） | 程序化动画、联动 UI |
| [`ReferenceProperty`](../packages/engine/Source/DataSources/ReferenceProperty.js#L90) | 引用 | 转发到目标 Entity 的属性（[L267](../packages/engine/Source/DataSources/ReferenceProperty.js#L267)） | B 的值 = A 的值 |
| [`PropertyBag`](../packages/engine/Source/DataSources/PropertyBag.js#L19) | 动态键值袋 | 逐键求值打包成对象（[L171](../packages/engine/Source/DataSources/PropertyBag.js#L171)） | `entity.customProperties`、不规则扩展字段 |

**位置特化系**：[`SampledPositionProperty`](../packages/engine/Source/DataSources/SampledPositionProperty.js#L21) = SampledProperty + 参考系（[`ReferenceFrame.FIXED/INERTIAL`](../packages/engine/Source/Core/ReferenceFrame.js#L8)，`getValue` 直接转发 [`getValueInReferenceFrame` L205](../packages/engine/Source/DataSources/SampledPositionProperty.js#L205)）；同族还有 `ConstantPositionProperty`、`CompositePositionProperty`、`TimeIntervalCollectionPositionProperty`、`CallbackPositionProperty`（继承 [`PositionProperty`](../packages/engine/Source/DataSources/PositionProperty.js#L23)）。

赋值魔法回顾：Entity 字段 setter 由 [`createPropertyDescriptor`](../packages/engine/Source/DataSources/createPropertyDescriptor.js#L72) 生成——传普通值自动包成 ConstantProperty，传 Property 原样收下（内层 [`createProperty` L9](../packages/engine/Source/DataSources/createPropertyDescriptor.js#L9)）。这就是 `entity.point.color = 'red'` 和 `= new CallbackProperty(...)` 都能工作的原因。

## 5. SampledProperty：从采样到插值的完整旅程

SampledProperty 是动态属性的心脏，值得逐段精读。

**① 喂数据**：[`addSample` L578](../packages/engine/Source/DataSources/SampledProperty.js#L578)（单点）/ [`addSamples` L622](../packages/engine/Source/DataSources/SampledProperty.js#L622)（批量）/ [`addSamplesPackedArray` L703](../packages/engine/Source/DataSources/SampledProperty.js#L703)（CZML 的 `[t0,v0,t1,v1,...]` 扁平数组）。内部是按时间排序的两个平行数组 `_times/_values`，每类值用 Packable 协议（`packedLength/pack/unpack`）拍平存储——任意 Cartesian3/Quaternion/number 都能进同一个容器。

**② 取值**：[`getValue` L366](../packages/engine/Source/DataSources/SampledProperty.js#L366) 五步走：

1. [binarySearch](../packages/engine/Source/Core/binarySearch.js#L24) 定位 `time`；
2. 落在区间外 → 按 [`ExtrapolationType`](../packages/engine/Source/Core/ExtrapolationType.js#L18) 三选一：`NONE`（返回 undefined）、`HOLD`（[L26](../packages/engine/Source/Core/ExtrapolationType.js#L26) 夹住端点值）、`EXTRAPOLATE`（[L34](../packages/engine/Source/Core/ExtrapolationType.js#L34) 用端点附近数据外推），可配超时窗口 `forward/backwardExtrapolationDuration`；
3. [`getRequiredDataPoints`](../packages/engine/Source/DataSources/SampledProperty.js#L419) 按插值阶数决定取几个采样点，以命中点为中心滑窗（[L443–L466](../packages/engine/Source/DataSources/SampledProperty.js#L443)）；
4. 打包 xTable/yTable：x 是相对窗末点的 [`secondsDifference`](../packages/engine/Source/Core/JulianDate.js#L939)（小数好算），y 支持 `convertPackedArrayForInterpolation` 预处理；
5. 调算法的 [`interpolateOrderZero`](../packages/engine/Source/DataSources/SampledProperty.js#L499) 或 [`interpolate`](../packages/engine/Source/DataSources/SampledProperty.js#L507)（带导数阶时）。

**③ 插值算法三兄弟**（都实现 [`InterpolationAlgorithm`](../packages/engine/Source/Core/InterpolationAlgorithm.js#L14) 接口）：

| 算法 | 定义行 | 特点 |
|---|---|---|
| [`LinearApproximation`](../packages/engine/Source/Core/LinearApproximation.js#L11) | 默认（[SampledProperty L193](../packages/engine/Source/DataSources/SampledProperty.js#L193)） | 两点线性，折线 |
| [`LagrangePolynomialApproximation`](../packages/engine/Source/Core/LagrangePolynomialApproximation.js#L10) | 拉格朗日多项式 | 过点光滑，但高阶在数据稀疏处会**龙格震荡** |
| [`HermitePolynomialApproximation`](../packages/engine/Source/Core/HermitePolynomialApproximation.js#L88) | 厄米特 | 可吃**速度导数**（[`interpolate` L236](../packages/engine/Source/Core/HermitePolynomialApproximation.js#L236) 的 inputOrder），轨道场景最平滑，也是 CZML `HERMITE` 的后端 |

切换用 [`setInterpolationOptions` L539](../packages/engine/Source/DataSources/SampledProperty.js#L539)（SampledPositionProperty 同名转发在 [L235](../packages/engine/Source/DataSources/SampledPositionProperty.js#L235)）。

「一个 SampledPositionProperty 从采样到插值」全流程：

```
addSample(t, Cartesian3)                       SampledProperty.js#L578
   │ pack 拍平 + 按时间插入排序数组（_times/_values）
   ▼
每帧 CesiumWidget._onTick → DataSourceDisplay.update(time)
   │ Visualizer 拿到 entity.position（SampledPositionProperty）
   ▼
position.getValueInReferenceFrame(time, FIXED) SampledPositionProperty.js#L205
   │ 交给内层 SampledProperty 逻辑（继承）
   ▼
SampledProperty.getValue(time)                 SampledProperty.js#L366
   ├─ binarySearch 命中 t（Core/binarySearch.js#L24）
   ├─ 越界？→ ExtrapolationType NONE/HOLD/EXTRAPOLATE
   ├─ 取窗：degree+1 个相邻采样（滑窗对齐边界）
   ├─ xTable = secondsDifference(各点, 窗末点)；yTable = 拍平值
   └─ interpolationAlgorithm.interpolateOrderZero / interpolate
   ▼
interpolated Cartesian3（FIXED 系）→ billboard.position / polyline 点
```

## 6. 其余四员精读

- **TimeIntervalCollectionProperty**：数据是 [`TimeIntervalCollection`](../packages/engine/Source/Core/TimeIntervalCollection.js#L23)（有序不重叠 interval 集，[`addInterval` L310](../packages/engine/Source/Core/TimeIntervalCollection.js#L310) 插入时自动合并/裁剪，[`findIntervalContainingDate` L188](../packages/engine/Source/Core/TimeIntervalCollection.js#L188) 二分查找）。单个 [`TimeInterval`](../packages/engine/Source/Core/TimeInterval.js#L60) 自带 start/stop/data/isStartIncluded。适合「10:00–11:00 显示图标 A、11:00–12:00 换 B」这类**离散切换**。
- **CompositeProperty**：interval 挂的不是 data 而是**内层 Property**——前半段接 SampledProperty 插值、后半段接 ConstantProperty，两条时间线无缝拼接。
- **CallbackProperty**：构造时第二个参数 `isConstant` 很关键——标 `false` 才会每帧重算；标 `true` 但回调返回变化值会**骗过差量同步**导致画面不更新（高频坑）。
- **ReferenceProperty**：`ReferenceProperty.fromString(entities, 'shipA.position')`（[`fromString` L218](../packages/engine/Source/DataSources/ReferenceProperty.js#L218)）跨 Entity 取值；它监听集合增删（[`_onCollectionChanged` L352](../packages/engine/Source/DataSources/ReferenceProperty.js#L352)）和目标 Entity 的 definitionChanged（[L340](../packages/engine/Source/DataSources/ReferenceProperty.js#L340)）来转发事件。**解引用发生在 getValue 时而非构造时**，所以先建引用后建目标也能工作。
- **PropertyBag**：键不是固定字段的字典，[`addProperty` L98](../packages/engine/Source/DataSources/PropertyBag.js#L98) 动态加键，每键可独立发 definitionChanged（[L131](../packages/engine/Source/DataSources/PropertyBag.js#L131)）。

## 7. 时间如何驱动渲染：从 clock.tick 到 billboard.position

[03 §4](03-Entity数据体系.md) 讲过 [`DataSourceDisplay.update`](../packages/engine/Source/DataSources/DataSourceDisplay.js#L311) 的差量同步；这里把它和时间接起来：

```
clock.currentTime（JulianDate，每帧新值）
  │
  ▼
DataSourceDisplay.update(time)                 DataSourceDisplay.js#L311
  └─ 对每个 Visualizer 调 update(time)          （defaultVisualizersCallback L169 组装）
       └─ BillboardVisualizer.update(time)      BillboardVisualizer.js#L95
            ├─ 遍历分桶 entity：position.getValue(time)（§5 的插值链）
            ├─ 与上一帧比：变了才写 billboard.position（差量）
            └─ 新增/删除 entity → getBillboard/remove（03 §5.1）
```

**关键点**：插值发生在 CPU 侧、每帧每实体一次；`isConstant === true` 的 Property 会被 Visualizer 缓存跳过重算。这也是 CallbackProperty 的 `isConstant` 参数影响性能的原因。GeometryVisualizer（[09 §6](09-几何图元与材质.md)）更重：position 变化会触发几何重建（Updater → 异步 Worker），所以轨道动画推荐 billboard/point/_polyline_ 这类轻量 Visualizer，而不是每帧变位置的 polygon。

## 8. CzmlDataSource 的时间轴解析要点

CZML 是「带时间轴的 JSON」，[`CzmlDataSource.load` L4868](../packages/engine/Source/DataSources/CzmlDataSource.js#L4868) → [`loadCzml` L4782](../packages/engine/Source/DataSources/CzmlDataSource.js#L4782) 逐文档处理，值得看的三处：

1. **顶层 clock 包**：[`updateClock` L4664](../packages/engine/Source/DataSources/CzmlDataSource.js#L4664) 把 `{interval, currentTime, multiplier, clockRange, clockStep}` 翻成 [`DataSourceClock`](../packages/engine/Source/DataSources/DataSourceClock.js#L15)。**没写 clock 包时**它会用全体 entity 的 availability 推一个：`LOOP_STOP` 循环、`multiplier = 总时长/120`（[L4674](../packages/engine/Source/DataSources/CzmlDataSource.js#L4674)）——这就是加载 CZML 后时间轴自动循环播放的出处。
2. **interval 与 epoch**：每个属性可写 `"interval": "2012-03-15T10:00:00Z/10:30:00Z"` 限定生效时段；采样数组的时间可用 `"epoch"` 基准（[L757–L769](../packages/engine/Source/DataSources/CzmlDataSource.js#L757)）相对秒，随后 [`addSamplesPackedArray`](../packages/engine/Source/DataSources/SampledProperty.js#L703) 批量灌入。
3. **属性分派与插值声明**：[`processPacketData` L873](../packages/engine/Source/DataSources/CzmlDataSource.js#L873) 按 interval 逐段生成 Property；`cartesian` 采样 → SampledPositionProperty，带 `cartesianVelocity` 时自动升一阶导数（`numberOfDerivatives`，[L932](../packages/engine/Source/DataSources/CzmlDataSource.js#L932)）；包里的 `"interpolationAlgorithm": "HERMITE"/"LAGRANGE"/"LINEAR"` 经 [`interpolators` 映射表 L596](../packages/engine/Source/DataSources/CzmlDataSource.js#L596) + [`updateInterpolationSettings` L602](../packages/engine/Source/DataSources/CzmlDataSource.js#L602) 直达 §5 的 `setInterpolationOptions`。外推策略（`forwardExtrapolationType` 等）也在这里透传。

## 9. 动手实验（Sandcastle 控制台）

```js
// ① 感受 JulianDate 的拆分表示
const j = Cesium.JulianDate.fromIso8601("2026-11-06T00:00:00Z");
console.log(j.dayNumber, j.secondsOfDay);            // 整天数 + 当日秒
const j2 = Cesium.JulianDate.addSeconds(j, 90, new Cesium.JulianDate());
console.log(Cesium.JulianDate.secondsDifference(j2, j));   // 90

// ② 时钟策略：把 Viewer 时钟改成 10 倍速循环
const c = viewer.clock;
c.multiplier = 10; c.shouldAnimate = true;
c.clockRange = Cesium.ClockRange.LOOP_STOP;          // 撞 stopTime 回绕
c.onTick.addEventListener(x => console.log(x.currentTime.toString()));

// ③ 插值对比：同一组三点，Linear vs Hermite
const times = ["00:00:00","00:01:00","00:02:00"].map(t => Cesium.JulianDate.fromIso8601("2026-11-06T"+t+"Z"));
const prop = new Cesium.SampledPositionProperty();
times.forEach((t,i) => prop.addSample(t, Cesium.Cartesian3.fromDegrees(116, 39 + i*0.01, 100)));
prop.setInterpolationOptions({ interpolationAlgorithm: Cesium.HermitePolynomialApproximation, interpolationDegree: 2 });
const mid = Cesium.JulianDate.addSeconds(times[0], 30, new Cesium.JulianDate());
console.log(prop.getValue(mid));                     // 中点插值位置
```

## 10. 常见坑

- **`shouldAnimate` 默认 false**：`viewer.clock.shouldAnimate = true` 忘开，时间轴纹丝不动（新手第一大坑）。
- **`onTick` 里改 `currentTime`**：tick 末尾广播 → 改了会立即影响同帧后续消费者，但与下一帧的 `_lastSystemTime` 计算可能错位；要跳时间用 `clock.currentTime = ...` 在 tick 外改。
- **SampledProperty 采样乱序/重复时刻**：内部排序能容忍乱序 add，但同一时刻两个值行为未定义（查找命中不确定）。
- **拉格朗日高阶 + 稀疏数据 = 画鬼畜**：卫星轨道请用 HERMITE 并喂上速度，或把 degree 压到 1–2。
- **`equalsEpsilon` 才是时间判等**：`JulianDate.equals` 精确比对双字段，动画里比较帧时刻请用 [`equalsEpsilon` L903](../packages/engine/Source/Core/JulianDate.js#L903)。
- **CZML 没有 clock 包也「自己会动」**：是 `updateClock` 的 availability 推断在起作用（§8），别以为见鬼。

## 11. 小结与下一篇

时间体系三层楼：**JulianDate 是砖**（TAI 双字段、无闰秒死角）、**Clock 是心跳**（双闸门 × ClockStep × ClockRange，`onTick` 同步广播）、**Property 是血肉**（`getValue(time)` 统一接口，插值/分段/回调/引用可任意组合），CzmlDataSource 则是把外部时间轴翻译成这套体系的编译器。渲染侧只认一个 `time` 参数（`DataSourceDisplay.update`），数据怎么随时间来的一概不问——解耦干净利落。
