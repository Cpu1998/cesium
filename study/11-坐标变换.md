## 0. 全景：坐标系一览表

| 坐标系 | 表示 | 单位/范围 | 谁住在这里 |
|---|---|---|---|
| WGS84 经纬高 | [`Cartographic`](../packages/engine/Source/Core/Cartographic.js#L16)（lon/lat **弧度** + height 米） | 弧度、米 | 数据进口/出口（KML、GeoJSON、CZML 多用它） |
| ECEF 地心地固 | [`Cartesian3`](../packages/engine/Source/Core/Cartesian3.js#L20) | 米 | **引擎内部通用语**：`scene` 里一切世界坐标 |
| ENU 局部站心 | Cartesian3（x=东 y=北 z=天） | 米、弧度 | 建模局部姿态、heading/pitch/roll |
| WebGL 模型系 | Cartesian3 | 由 `modelMatrix` 定 | Geometry 顶点（09 §1） |
| 观察系（眼系） | Cartesian3 | 米，相机在原点 -z 朝前 | 着色器 `positionEC`、光照 |
| 裁剪系 | [`Cartesian4`](../packages/engine/Source/Core/Cartesian4.js#L18)（xyz/w 齐次） | −w..w | `gl_Position`、视锥剔除 |
| NDC | 归一化 | −1..1 | 裁剪后除以 w |
| 窗口系 | [`Cartesian2`](../packages/engine/Source/Core/Cartesian2.js#L19) | 像素，**原点左下** | 拾取（08）、屏幕覆盖物 |

**弧度是内部约定**：`Cartographic` 与 `Cartesian3.fromDegrees`（[L839](../packages/engine/Source/Core/Cartesian3.js#L839)）只差一步 [`RADIANS_PER_DEGREE`](../packages/engine/Source/Core/Math.js#L478) 换算——API 名带 `Degrees` 后缀的都替你转了，手拼 `new Cartographic(lon, lat)` 传成度数是经典事故。

## 1. 原子类型：Cartesian 系与 Cartographic

- [`Cartesian3`](../packages/engine/Source/Core/Cartesian3.js#L20)：不可变风格的向量，全家静态方法（[`magnitude` L351](../packages/engine/Source/Core/Cartesian3.js#L351)、[`distance` L366](../packages/engine/Source/Core/Cartesian3.js#L366)、[`fromDegrees` L839](../packages/engine/Source/Core/Cartesian3.js#L839)/[`fromRadians` L869](../packages/engine/Source/Core/Cartesian3.js#L869)），全部支持 `result` 复用避免 GC。
- [`Cartographic`](../packages/engine/Source/Core/Cartographic.js#L16)：三个裸字段 longitude/latitude/height；[`fromDegrees` L84](../packages/engine/Source/Core/Cartographic.js#L84)、[`fromCartesian` L105](../packages/engine/Source/Core/Cartographic.js#L105)（等价于椭球反解）。
- `Cartesian2`（屏幕/纹理 UV）与 `Cartesian4`（齐次坐标、RGBA）是同款设计。

## 2. 变换三积木：Matrix3 / Matrix4 / Quaternion

**列主序（column-major）是第一纪律**：[`Matrix4`](../packages/engine/Source/Core/Matrix4.js#L53) 的 16 个数按**列**排布（文档 [L26](../packages/engine/Source/Core/Matrix4.js#L26)、[L185](../packages/engine/Source/Core/Matrix4.js#L185)），即 `Matrix4[column*4 + row]`。平移在第 12–14 个元素（第 4 列）——与 WebGL uniformMemory 天然对齐，也是「`Matrix4` 存旋转+平移、点乘在列」的原因。

| 积木 | 定义行 | 干什么 | 高频方法 |
|---|---|---|---|
| [`Matrix3`](../packages/engine/Source/Core/Matrix3.js#L39) | 3×3 旋转/缩放 | 姿态 | [`fromQuaternion` L296](../packages/engine/Source/Core/Matrix3.js#L296)、[`multiply` L1043](../packages/engine/Source/Core/Matrix3.js#L1043)、`getColumn` [L729](../packages/engine/Source/Core/Matrix3.js#L729) |
| [`Matrix4`](../packages/engine/Source/Core/Matrix4.js#L53) | 4×4 刚体/投影 | 万物变换 | [`multiply` L1699](../packages/engine/Source/Core/Matrix4.js#L1699)、[`multiplyByPoint` L2271](../packages/engine/Source/Core/Matrix4.js#L2271)（**点**变换，w=1）、`multiplyByPointAsVector` [L2237](../packages/engine/Source/Core/Matrix4.js#L2237)（**向量**变换，忽略平移）、[`fromRotationTranslation` L375](../packages/engine/Source/Core/Matrix4.js#L375)、`getColumn` [L1251](../packages/engine/Source/Core/Matrix4.js#L1251)、`fromArray`=unpack [L3062](../packages/engine/Source/Core/Matrix4.js#L3062) |
| [`Quaternion`](../packages/engine/Source/Core/Quaternion.js#L20) | 单位四元数 | 无万向锁的姿态插值 | [`fromHeadingPitchRoll` L186](../packages/engine/Source/Core/Quaternion.js#L186)、slerp |

与姿态 [`HeadingPitchRoll`](../packages/engine/Source/Core/HeadingPitchRoll.js#L16)（heading=绕 −z 偏航、pitch=绕 −y 俯仰、roll=绕 x 横滚，弧度）的互转路径：**HPR → Quaternion → Matrix3 → Matrix4**，或直接用 §4 的 `headingPitchRollToFixedFrame` 一步到位。

**复合与拆解**是一对高频操作：拼装用 [`fromRotationTranslation` L375](../packages/engine/Source/Core/Matrix4.js#L375)（或一步到位的 `fromTranslationQuaternionRotationScale` [L439](../packages/engine/Source/Core/Matrix4.js#L439) / `fromTranslationRotationScale` [L509](../packages/engine/Source/Core/Matrix4.js#L509)，模型动画/glTF 节点用得多）；拆回原件用 [`getTranslation` L2599](../packages/engine/Source/Core/Matrix4.js#L2599) / [`getRotation` L1668](../packages/engine/Source/Core/Matrix4.js#L1668)。求逆两个版本别混：[`inverse` L2663](../packages/engine/Source/Core/Matrix4.js#L2663) 是通用伴随法；[`inverseTransformation` L2877](../packages/engine/Source/Core/Matrix4.js#L2877) 走「刚体假设」快路径（旋转部分转置 + 反平移），源码里 Model/Tileset 算 `czm_inverseModel` 全是后者。

**矩阵乘法语义**：`Matrix4.multiply(A, B)` 是 **A×B**（先作用 B 再 A）；`multiplyTransformation`（[L1882](../packages/engine/Source/Core/Matrix4.js#L1882)）与 `multiply` 数学上等价但走「假设底行是 0,0,0,1」的快路径。级联时记住读序从右往左。

## 3. Ellipsoid：WGS84 椭球与经纬高 ↔ ECEF

[`class Ellipsoid`](../packages/engine/Source/Core/Ellipsoid.js#L89) 由三个半轴初始化（[`initialize` L32](../packages/engine/Source/Core/Ellipsoid.js#L32) 预算 `_oneOverRadii/_radiiSquared` 等缓存），全局常量 [`Ellipsoid.WGS84`](../packages/engine/Source/Core/Ellipsoid.js#L762) = (6378137, 6378137, 6356752.314)。

**正解 [`cartographicToCartesian` L385`](../packages/engine/Source/Core/Ellipsoid.js#L385)** 只有三步（代码短到可以整段读）：

```js
// Ellipsoid.js L385 起（节选）
n = geodeticSurfaceNormalCartographic(cartographic, n);      // 法线 = (cosφcosλ, cosφsinλ, sinφ)
k = multiplyComponents(this._radiiSquared, n, k);            // 椭球面点（未归一化）
gamma = sqrt(dot(n, k));
divideByScalar(k, gamma, k);                                 // 归一化 → 椭球面上的点
multiplyByScalar(n, height, n);  return Cartesian3.add(k, n, result);  // 沿法线抬高 h
```

要点：**高程沿椭球面法线方向**（大地高），不是沿地心向量——两极差出最多约 21km 的概念差（地心纬度 vs 大地纬度）。**反解 [`cartesianToCartographic` L445](../packages/engine/Source/Core/Ellipsoid.js#L445)** 依赖 [`scaleToGeodeticSurface` L510](../packages/engine/Source/Core/Ellipsoid.js#L510)（迭代逼近，实现在 [`scaleToGeodeticSurface.js`](../packages/engine/Source/Core/scaleToGeodeticSurface.js) 的经典 Gramoll/远程点迭代），找到脚下椭球面点后用 [`geodeticSurfaceNormal` L350](../packages/engine/Source/Core/Ellipsoid.js#L350) 反推经纬。

**测地线 [`EllipsoidGeodesic`](../packages/engine/Source/Core/EllipsoidGeodesic.js#L285)**：椭球上两点间「贴面最短线」，构造/换端点（[`setEndPoints` L394](../packages/engine/Source/Core/EllipsoidGeodesic.js#L394)）后可取 [`surfaceDistance` L321](../packages/engine/Source/Core/EllipsoidGeodesic.js#L321)（米）和按比例插值 [`interpolateUsingFraction` L410](../packages/engine/Source/Core/EllipsoidGeodesic.js#L410)。两点之间要算**真实地面距离**用它，别用 `Cartesian3.distance`（那是穿地球的直线）。

## 4. Transforms：局部站心系 → ECEF

[`Transforms.js`](../packages/engine/Source/Core/Transforms.js) 的核心是一个**生成器**：[`localFrameToFixedFrameGenerator(firstAxis, secondAxis)` L99](../packages/engine/Source/Core/Transforms.js#L99)——你指定局部系前两根轴的方向（"east"/"north"/"up"/...），叉积定第三轴，返回「origin → ECEF」的 4×4 生成函数（按轴组合缓存，[L115](../packages/engine/Source/Core/Transforms.js#L115) 起）。两个预制品：

| 变换 | 定义行 | 局部系 | 用途 |
|---|---|---|---|
| [`eastNorthUpToFixedFrame(origin)`](../packages/engine/Source/Core/Transforms.js#L276) | L276 | x=东, y=北, z=天 | **建模标准姿势**：无人机、建筑、Entity orientation 缺省 |
| [`northEastDownToFixedFrame(origin)`](../packages/engine/Source/Core/Transforms.js#L302) | L302 | x=北, y=东, z=下 | 航空惯例（NED） |

姿态版在矩阵之上再叠 HPR（[L397–L408](../packages/engine/Source/Core/Transforms.js#L397)：先 `Quaternion.fromHeadingPitchRoll` 转 Matrix3，再 [`Matrix4.multiply`](../packages/engine/Source/Core/Matrix4.js#L1699)）：

- [`headingPitchRollToFixedFrame(origin, hpr)` L384](../packages/engine/Source/Core/Transforms.js#L384)：**ENU + 姿态** → ECEF 的 4×4（Entity/modelMatrix 常客）
- [`headingPitchRollQuaternion(origin, hpr)` L437](../packages/engine/Source/Core/Transforms.js#L437)：同上但输出四元数（`entity.orientation` 常客，默认 fixedFrameTransform 参数就是 ENU，[L396](../packages/engine/Source/Core/Transforms.js#L396)）

注意「heading 相对什么」：这些函数的 heading 是**相对局部系**（ENU）的，[06 §2](06-相机系统与视角控制.md) 相机 heading/pitch/roll 的反解走同一套 ENU 假设；想挂在别的局部系上传 `fixedFrameTransform` 参数即可（比如 NED）。

## 5. SceneTransforms：世界 → 窗口的完整链

06 §7 给过结论表，这里逐段拆 [`SceneTransforms.worldToWindowCoordinates(scene, position)`](../packages/engine/Source/Scene/SceneTransforms.js#L46)（1.145 已无 `wgs84ToWindowCoordinates`）：

```js
// SceneTransforms.js L46：入口只是薄包装
worldToWindowCoordinates(scene, position, result) {
  return SceneTransforms.worldWithEyeOffsetToWindowCoordinates(
           scene, position, Cartesian3.ZERO, result);
}
```

主干 [`worldWithEyeOffsetToWindowCoordinates` L99](../packages/engine/Source/Scene/SceneTransforms.js#L99) 分四步：

1. **换到当前场景系**：2D/CV 模式下世界坐标要先映射（`computeActualEllipsoidPosition`，[L301](../packages/engine/Source/Scene/SceneTransforms.js#L301)），3D 直通。
2. **视图投影**（[`worldToClip` L58](../packages/engine/Source/Scene/SceneTransforms.js#L58)）：`camera.viewMatrix`（getter [`Camera.js L891`](../packages/engine/Source/Scene/Camera.js#L891)，06 §1）乘出眼系坐标，再乘 `frustum.projectionMatrix`（如 [`PerspectiveFrustum.js L237`](../packages/engine/Source/Core/PerspectiveFrustum.js#L237)）得 **clip Cartesian4**；顺带处理 `eyeOffset`（billboard 沿视线前移防 z-fighting，08 用过）。
3. **clip → 窗口**（[`clipToGLWindowCoordinates` L358](../packages/engine/Source/Scene/SceneTransforms.js#L358)）：除以 w（透视除法 → NDC），再用 [`Matrix4.computeViewportTransformation` L1045](../packages/engine/Source/Core/Matrix4.js#L1045) 把 NDC 映射进视口——该矩阵本体就是对角缩放加平移（halfWidth/halfHeight、+x+halfWidth…，[L1065 起](../packages/engine/Source/Core/Matrix4.js#L1065)）。
4. **像素比换算**：`worldToDrawingBufferCoordinates`（[L282](../packages/engine/Source/Scene/SceneTransforms.js#L282)）给的是 drawing buffer 坐标；`worldToWindowCoordinates` 最终除以 CSS 像素比折回 **client 坐标**（[L267](../packages/engine/Source/Scene/SceneTransforms.js#L267) 注释：浏览器缩放/高 DPI 时两者不同，拾取与 DOM 覆盖物要用 client 版）。

**一个坐标的七级变换瀑布**（把 §0 表格串成一条线）：

```
Cartographic(lonφ, latλ, h)          —— 数据进口：弧度 + 大地高
   │  Ellipsoid.cartographicToCartesian      Ellipsoid.js#L385（法线 n·(a²,b²,c²) 归一 + 沿 n 抬 h）
   ▼
Cartesian3 ECEF (x,y,z)              —— 引擎通用语；camera.position 也在这
   │  DrawCommand.modelMatrix（若有）：模型系 → 世界系        Context.js#L1359 → czm_model
   │  camera.viewMatrix：世界 → 眼系               Camera.js#L891 → czm_view
   │  frustum.projectionMatrix：眼系 → 裁剪系      PerspectiveFrustum.js#L237 → czm_projection
   ▼                                     （GPU 上三者合一：czm_modelViewProjection）
Cartesian4 clip (x,y,z,w)            —— |x|,|y|,|z| ≤ w 才可能在屏内（视锥剔除就在判这个）
   │  透视除法 ÷w
   ▼
NDC (−1..1, −1..1)                   —— 与分辨率无关
   │  Matrix4.computeViewportTransformation  Matrix4.js#L1045（半宽半高缩放 + 平移）
   ▼
窗口像素 Cartesian2(x,y)             —— 原点左下，y 向上；DOM 事件给的是 y 向下的，记得用 canvas 高度减
```

GPU 侧同一条链的入口是 [`AutomaticUniforms.js`](../packages/engine/Source/Renderer/AutomaticUniforms.js) 的自动 uniform：[`czm_model` L264](../packages/engine/Source/Renderer/AutomaticUniforms.js#L264)、[`czm_view` L313](../packages/engine/Source/Renderer/AutomaticUniforms.js#L313)、[`czm_projection` L509](../packages/engine/Source/Renderer/AutomaticUniforms.js#L509)、[`czm_viewProjection` L728](../packages/engine/Source/Renderer/AutomaticUniforms.js#L728)、[`czm_modelViewProjection` L783](../packages/engine/Source/Renderer/AutomaticUniforms.js#L783)、[`czm_viewportTransformation` L135](../packages/engine/Source/Renderer/AutomaticUniforms.js#L135)——CPU 每帧更新于 [`UniformState.update` L1486](../packages/engine/Source/Renderer/UniformState.js#L1486)（相机与视锥部分在 `updateCamera` [L1422](../packages/engine/Source/Renderer/UniformState.js#L1422)/`updateFrustum` [L1443](../packages/engine/Source/Renderer/UniformState.js#L1443)）。

## 6. ModelMatrix：模型系 → 世界系的挂钩

[09 §3](09-几何图元与材质.md) 讲过 Geometry/GeometryInstance 三层；`modelMatrix` 的两个落点：

1. **[`Primitive.modelMatrix`](../packages/engine/Source/Scene/Primitive.js#L227)（选项文档 [L71](../packages/engine/Source/Scene/Primitive.js#L71)）**：对**整个 Primitive** 的模型系平移/旋转（典型值就是 [`Transforms.eastNorthUpToFixedFrame`](../packages/engine/Source/Core/Transforms.js#L276)，[L225](../packages/engine/Source/Scene/Primitive.js#L225) 示例）。它有两条消化路线：静态 Primitive 在 [`GeometryPipeline.transformToWorldCoordinates`](../packages/engine/Source/Core/GeometryPipeline.js#L835) 里**把变换烘进顶点**（世界系合批的前提，09 §3）；动态/异步路径则把 `modelMatrix` 传给命令（[Primitive.js L1267](../packages/engine/Source/Scene/Primitive.js#L1267)）。
2. **[`DrawCommand._modelMatrix`](../packages/engine/Source/Renderer/DrawCommand.js#L86)（class [`DrawCommand` L76](../packages/engine/Source/Renderer/DrawCommand.js#L76)，setter [L239](../packages/engine/Source/Renderer/DrawCommand.js#L239)）**：命令随帧生效的模型变换。绘制时 [`Context` 把它写进 UniformState](../packages/engine/Source/Renderer/Context.js#L1359)（`context._us.model = drawCommand._modelMatrix ?? IDENTITY`，`model` setter [`UniformState.js L267`](../packages/engine/Source/Renderer/UniformState.js#L267) 顺手逆算 `czm_inverseModel`），着色器里 `czm_model * position` 即模型系 → 世界系。**同一批顶点配不同 modelMatrix 可以复用 VA**——这正是 `PostProcess`/Globe 之外许多 Scene 图元的做法，也解释了为什么 modelMatrix 改了不用重建顶点缓冲（区别于烘顶点路线）。

与 [06](06-相机系统与视角控制.md) 的衔接：相机 `lookAtTransform` 换参考系本质是「把某 modelMatrix 的逆设为 viewMatrix」；与 [09](09-几何图元与材质.md) 的衔接：GroundPrimitive 贴地时 modelMatrix 还要参与椭球面贴合计算。

## 7. 动手实验（Sandcastle 控制台）

```js
// ① 七级瀑布手动走一遍：北京上空 100m → 屏幕像素
const carto = Cesium.Cartographic.fromDegrees(116.39, 39.9, 100);
const ecef  = Cesium.Ellipsoid.WGS84.cartographicToCartesian(carto);
console.log("ECEF", ecef);
const px = Cesium.SceneTransforms.worldToWindowCoordinates(scene, ecef);
console.log("窗口像素", px, "（原点左下）");
const back = Cesium.Ellipsoid.WGS84.cartesianToCartographic(ecef);   // 反解回来对一对
console.log(back.longitude*180/Math.PI, back.latitude*180/Math.PI, back.height);

// ② ENU 的直感：给相机脚下立一个朝东的坐标架
const m = Cesium.Transforms.eastNorthUpToFixedFrame(
  Cesium.Cartesian3.fromDegrees(116.39, 39.9));
console.log("ENU→ECEF 三根轴：");
[0,1,2].forEach(i => console.log(i, Cesium.Matrix4.getColumn(m, i, new Cesium.Cartesian4())));

// ③ 测地线 vs 直线距离
const a = Cesium.Cartesian3.fromDegrees(116.39, 39.9);
const b = Cesium.Cartesian3.fromDegrees(121.47, 31.23);
console.log("直线", Cesium.Cartesian3.distance(a,b));
const g = new Cesium.EllipsoidGeodesic(
  Cesium.Cartographic.fromDegrees(116.39,39.9),
  Cesium.Cartographic.fromDegrees(121.47,31.23));
```

## 8. 常见坑

- **经纬度传成度数**：内部全弧度；只有 API 名带 `Degrees` 的函数替你转（§0）。
- **把 `multiplyByPointAsVector` 用在点上**（或反过来）：向量版不应用平移，位移点会少走一段；移动点必须 `multiplyByPoint`。
- **列主序手写矩阵**：从数学书（行主序）抄 16 个数直接塞 `Matrix4(...)` 会得到转置；先 `Matrix4.fromArray` + `getColumn` 验证。
- **窗口 y 轴方向**：`worldToWindowCoordinates` 原点**左下**、y 向上；DOM `click.offsetY` 原点左下但事件 y 向下体系混用是高频 bug（拾取统一走 Cesium API 就没事，08 §1）。
- **高度概念的三个「h」**：`Cartographic.height` 是**大地高**（沿法线、EGM96 前提下近似海拔），不是地心距也不是离球面直线距离；`sampleHeight`（07 §3）返回的才是「贴地形高」。
- **`surfaceDistance` 不是 `distance`**：长距离场景直线穿地球，误差可达上百公里（§7 实验③亲手对比）。
- **2D/CV 模式下的 worldToWindow**：内部先做 `computeActualEllipsoidPosition` 映射，直接拿 3D 的 viewMatrix 手算会错——要复用就整体复用 SceneTransforms，别抽半条链。

## 9. 小结

坐标变换是 Cesium 的「语法」：**Cartographic 表人话、ECEF 表引擎话、ENU 表姿态话、clip/NDC/窗口表显卡话**，而 Matrix4（列主序）是唯一的语法书。读源码时抓三句：正解是「法线 × 半轴平方再归一」（§3），局部系是「两根轴叉出第三根」（§4），屏幕链是「view × projection ÷w × viewport」（§5）——七级瀑布背下来，任何坐标 bug 都能定位到其中一级。

至此本系列正篇（00–11）覆盖了从 Viewer 创建到坐标落屏的完整主干。下一篇可继续 12-事件与交互（ScreenSpaceEventHandler 事件流与相机控制器的耦合）或 13-渲染命令与着色器（DrawCommand 生命周期与 ShaderBuild）。
