# 07 · 地形系统

> 阅读前提：读完 [02-底图与影像体系.md](02-底图与影像体系.md) §3（瓦片生命周期）——那篇从影像视角讲过一遍四叉树；本文换**地形视角**重走同一条管线，并补上 02 没展开的 TerrainProvider 接口、LOD 误差公式与 quantized-mesh 格式。
> 一句话：地形是这颗星球的**骨骼**，影像是**皮肤**；骨骼的调度和皮肤共用同一棵四叉树。

本文的主战场文件：

- [`TerrainProvider.js`](../packages/engine/Source/Core/TerrainProvider.js) —— 地形数据源抽象接口
- [`GlobeSurfaceTileProvider.js`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js) —— 把「地形+影像」缝进四叉树的枢纽
- [`QuadtreePrimitive.js`](../packages/engine/Source/Scene/QuadtreePrimitive.js) —— 四叉树帧调度（SSE 选片、三优先级加载队列）
- [`GlobeSurfaceTile.js`](../packages/engine/Source/Scene/GlobeSurfaceTile.js) —— 单块瓦片的数据 + 两级状态机
- [`QuantizedMeshTerrainData.js`](../packages/engine/Source/Core/QuantizedMeshTerrainData.js) / [`HeightmapTerrainData.js`](../packages/engine/Source/Core/HeightmapTerrainData.js) —— 两种地形数据格式

## 0. 全景：地形挂在对象树的哪一节

回顾 [01 §4.4–4.7](01-Viewer创建与场景初始化.md)：CesiumWidget 建 `new Globe(ellipsoid)`，地形入口有两个（`terrain` 新式 / `terrainProvider` 旧式）。组装现场在
[`Globe.js`](../packages/engine/Source/Scene/Globe.js) 构造函数（[`function Globe`](../packages/engine/Source/Scene/Globe.js#L51)，【导读】注释在 [L52](../packages/engine/Source/Scene/Globe.js#L52)）：

```
scene.globe  = new Globe(ellipsoid)
 └─ _surface = new QuadtreePrimitive({                       Globe.js#L69
      tileProvider: new GlobeSurfaceTileProvider({           Globe.js#L70
          terrainProvider,          ← 骨骼来源（默认 EllipsoidTerrainProvider，光滑椭球）
          imageryLayers,            ← 皮肤集合（ImageryLayerCollection）
          surfaceShaderSet,         ← GlobeVS/GlobeFS 着色器组合器
          vectorProvider }) })
           │
           │ 每块瓦片 QuadtreeTile.data = GlobeSurfaceTile 实例
           ▼
      [QuadtreeTile] ←→ GlobeSurfaceTile（terrainData + mesh + imagery[] + 状态机）
```

**`scene.globe._surface` 是 QuadtreePrimitive，它自己只是调度骨架；真正"干活"的回调宿主是 GlobeSurfaceTileProvider**（文件头【导读】[L1–L9](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1)）。

## 2. 入口与切换：`Terrain` / `scene.setTerrain` / `globe.terrainProvider`

新式 [`Terrain`](../packages/engine/Source/Scene/Terrain.js#L43) 是个**异步包装器**：[`Terrain.fromWorldTerrain`](../packages/engine/Source/Scene/Terrain.js#L156) 返回包装了 Promise 的对象，
provider 就绪后写回 [`instance._provider`](../packages/engine/Source/Scene/Terrain.js#L221) 并广播 `readyEvent`。

落位链路（两式殊途同归）：

```
Viewer({terrain})                          ──┐
Viewer({terrainProvider})（旧式）            ──┤
viewer.scene.terrainProvider = p（旧式）     ──┼→ Scene.prototype.setTerrain  Scene.js#L5531
scene.setTerrain(new Terrain(...))          ──┘      │（内部 setTerrain 场景函数 Scene.js#L5487）
                                                        ▼
                                        scene.globe.terrainProvider = provider   Globe.js#L528 setter
                                                        ▼
                                        GlobeSurfaceTileProvider._terrainProvider 替换（构造时 [L149](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L149)，
                                        运行时替换在 [L330](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L330)）→ 触发全量瓦片失效重建
```

Globe 的 [`terrainProvider` setter](../packages/engine/Source/Scene/Globe.js#L528) 换人后广播 `_terrainProviderChanged`；
四叉树侧用 [`QuadtreePrimitive.prototype.invalidateAllTiles`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L211) 把缓存瓦片全部打回重载。**换地形 = 整棵树重来**，成本意识要有。

## 3. 四叉树帧调度：beginFrame / render / endFrame 三拍

四叉树自己不画东西，每帧按三拍被 Globe 牵着走（Globe 侧入口：[`beginFrame` L1003](../packages/engine/Source/Scene/Globe.js#L1003) / [`render` L1098](../packages/engine/Source/Scene/Globe.js#L1098) / [`endFrame` L1113](../packages/engine/Source/Scene/Globe.js#L1113)）：

| 拍 | QuadtreePrimitive 定义行 | 干什么 | 顺手调 tileProvider 的 |
|---|---|---|---|
| ① [`beginFrame`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L341) | 【导读】L342 | 瓦片失效重建检查、清空加载三队列、LRU 标记帧起点 | [`initialize`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L412)（推影像重投影 ComputeCommand、版权汇总） |
| ② [`render`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L371) | 【导读】L372 | [`selectTilesForRendering`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L522)（SSE 遍历选片）→ 生成渲染命令 | [`beginUpdate`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L480)/[`showTileThisFrame`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1105)/[`addDrawCommandsForTile`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L2528) |
| ③ [`endFrame`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L451) | 【导读】L452 | [`processTileLoadQueue`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1335) 时间片加载 + 高度回调 + 进度事件 | [`loadTile`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L694) |

（[`update`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L316) 是第 0 拍，只透传给 tileProvider 的 [`update`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L402) 做图层集合 `_update`。）

选片遍历（②内）：根瓦片按"离相机远→近"排序后深度优先 [`visitTile`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L734)——先判可见（含地球曲率遮挡），再算 SSE 决定**画自己还是继续细分**。待加载瓦片按三档优先级进队列
（【导读】[L91](../packages/engine/Source/Scene/QuadtreePrimitive.js#L91)）：

- **High**：挡着细分的父瓦片（不加载就永远切不下去）；
- **Medium**：本帧要画的、或相机脚下那块（供 [`updateHeight`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L284) 查高程）；
- **Low**：预取的兄弟瓦片（`preloadSiblings`）。

第③拍 [`processTileLoadQueue`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1335) 按时间片（[`_loadQueueTimeSlice` L97](../packages/engine/Source/Scene/QuadtreePrimitive.js#L97) 默认 5ms）消化队列，
网络请求再经 [`RequestScheduler`](../packages/engine/Source/Core/RequestScheduler.js) 限流（详见 [05 §6](05-帧更新与渲染循环.md)）。缓存淘汰由 [`TileReplacementQueue`](../packages/engine/Source/Scene/TileReplacementQueue.js#L10) LRU 负责，
保留量 [`tileCacheSize`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L130)（默认 100）。

## 4. LOD 心脏：几何误差 → 屏幕空间误差（SSE）

地形 LOD 的判定不是"离多远"，而是**"这块瓦片的最大误差投到屏幕上还有几个像素"**：

```
SSE = geometricError × 屏幕高 / (距离 × sseDenominator)        QuadtreePrimitive.js#L1270 起
      └── provider.getLevelMaximumGeometricError(level)
```

源码锚点：[`function screenSpaceError`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1270)（【导读】公式注释在 [L1271](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1271)）：

```js
// QuadtreePrimitive.js L1270–1288（节选）
function screenSpaceError(primitive, frameState, tile) {
  const maxGeometricError = provider.getLevelMaximumGeometricError(tile.level);
  const height = frameState.context.drawingBufferHeight;
  const distance = tile._distance;
  const sseDenominator = frameState.camera.frustum.sseDenominator;   // L1286
  let error = (maxGeometricError * height) / (distance * sseDenominator);
  error -= CesiumMath.fog(distance, frameState.fog.density) * frameState.fog.sse;  // 雾里放行更粗的瓦片
  ...
}
```

- **细分门槛** [`maximumScreenSpaceError`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L120)（默认 **2px**）：SSE > 2 就细分到子瓦片，≤ 2 就画自己。想更清晰 → 调小；卡顿 → 调大；
- **几何误差的来源**：CesiumTerrainProvider 用 [`_levelZeroMaximumGeometricError / (1 << level)`](../packages/engine/Source/Core/CesiumTerrainProvider.js#L1148)——每深一级误差减半；0 级误差可用
  [`getEstimatedLevelZeroGeometricErrorForAHeightmap`](../packages/engine/Source/Core/TerrainProvider.js#L513) 估算；
- `sseDenominator` = `2·tan(fov/2)`，来自相机 frustum（[PerspectiveFrustum L277](../packages/engine/Source/Core/PerspectiveFrustum.js#L277)，呼应 [06 §6](06-相机系统与视角控制.md)）；
- 2D 模式距离语义不同，走独立的 [`screenSpaceError2D`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L1300)；
- **同款公式也用在 3D Tiles**（[Cesium3DTile.js#L975](../packages/engine/Source/Scene/Cesium3DTile.js#L975)，见 [04 §3](04-3DTiles加载与LOD.md)）——Cesium 全家 LOD 一个心法。

## 5. 一块地形瓦片的一生（状态机全景）

瓦片对象是 [`QuadtreeTile`](../packages/engine/Source/Scene/QuadtreeTile.js#L75)（x/y/level + 邻居 + [`data`](../packages/engine/Source/Scene/QuadtreeTile.js#L180) + [`renderable`](../packages/engine/Source/Scene/QuadtreeTile.js#L162)）；
`data` 就是 [`GlobeSurfaceTile`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L100)。**两级状态机**：

- **加载层**：[`QuadtreeTileLoadState`](../packages/engine/Source/Scene/QuadtreeTileLoadState.js)（START/LOADING/DONE/FAILED）——四叉树看；
- **地形层**：[`TerrainState`](../packages/engine/Source/Scene/TerrainState.js#L7)（FAILED/UNLOADED/RECEIVING/RECEIVED/TRANSFORMING/TRANSFORMED/READY）——瓦片自己看。

每帧由 [`GlobeSurfaceTileProvider.loadTile`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L694)（【导读】L695：先地形后影像、借包围盒时 terrainOnly）驱动
静态入口 [`GlobeSurfaceTile.processStateMachine`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L253)（【导读】L255），内部走 [`initialize`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L221) → [`processTerrainStateMachine`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L723)（【导读】L724）→ [`processImagery`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L347)：

```
                    ┌────────────────── 一块地形瓦片的一生 ──────────────────┐
 出生：visitTile 判定可见/需细分
   │ queueTileLoad(三优先级队列之一)                    QuadtreePrimitive.js#L629
   ▼ endFrame 时间片轮到它 → loadTile                 GlobeSurfaceTileProvider.js#L694
   ▼ processStateMachine                             GlobeSurfaceTile.js#L253
   ├─ initialize：建 TileImagery 骨架(每层影像一格)      GlobeSurfaceTile.js#L221
   ▼

 │  UNLOADED ──requestTileGeometry──► (网络/RequestScheduler)                      │

   ▼ 下一次 render 拍被选中
```

两个容错细节：

- **upsample 兜底**：地形请求失败（404/离线）不报错给用户，而是 [`upsample`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L849) 从父瓦片插值出一块低精度补位——父也没就绪就递归先推父（状态机 L740 起的 FAILED 分支）；
- **高程查询**：`sampleTerrainMostDetailed` / 相机贴地用的是 [`updateHeight`](../packages/engine/Source/Scene/QuadtreePrimitive.js#L284) 注册的回调，瓦片数据升级时重算。

## 6. 数据格式：quantized-mesh 是主角

### 6.1 heightmap：最朴素的栅格

[`HeightmapTerrainData`](../packages/engine/Source/Core/HeightmapTerrainData.js#L96) = 规则网格高程矩阵（如 65×65）。
[`_createMeshSync`](../packages/engine/Source/Core/HeightmapTerrainData.js#L315) 在 CPU 上三角化，
[`upsample`](../packages/engine/Source/Core/HeightmapTerrainData.js#L492) 双线性插值出子瓦片。缺点：等间距采样，平原浪费、山脊丢细节。

### 6.2 quantized-mesh：TIN 三角网

ion 地形默认格式（[格式规范](https://github.com/CesiumGS/quantized-mesh)）。[`QuantizedMeshTerrainData`](../packages/engine/Source/Core/QuantizedMeshTerrainData.js#L94) 一个 .terrain 文件按序解码出：

| 段 | 内容 |
|---|---|
| header | 椭球中心点、**水平遮挡点**（horizonOcclusionPoint，跨地平线剔除用）、最小/最大高程 |
| vertices | 顶点三元组 (i,j,k)——经向/纬向/高程各 16bit **zigzag 量化** |
| indices | 三角形索引 + 四条边的邻接顶点索引表（跨瓦片缝合判定用） |
| extensions | `octvertexnormals`（八进制法线，光照）/ `watermask`（水面掩码）/ `lighting` / `metadata` |

要点：

- 顶点是**不规则三角网（TIN）**，山峰密、平原疏，同字节数表达力远超 heightmap；
- CPU 建网格不在主线程硬算：[`createMesh`](../packages/engine/Source/Core/QuantizedMeshTerrainData.js#L264) 把活儿派给 Web Worker
  [`createVerticesFromQuantizedTerrainMesh`](../packages/engine/Source/Workers/createVerticesFromQuantizedTerrainMesh.js#L26)（任务名常量在 [L240](../packages/engine/Source/Core/QuantizedMeshTerrainData.js#L240)）；
- **裙边（skirt）**：下载方给瓦片四边向下拉一圈裙边网格，高度取 `getLevelMaximumGeometricError(level) × 5`（[CesiumTerrainProvider.js#L798](../packages/engine/Source/Core/CesiumTerrainProvider.js#L798)）——邻居瓦片级别不同时，用裙边遮住接缝处的漏缝；
- 服务器选格式：[`requestTileGeometry`](../packages/engine/Source/Core/CesiumTerrainProvider.js#L851) 按 layer.json 的格式分派到
  [`createHeightmapTerrainData`](../packages/engine/Source/Core/CesiumTerrainProvider.js#L575)（[L581](../packages/engine/Source/Core/CesiumTerrainProvider.js#L581)）或
  [`createQuantizedMeshTerrainData`](../packages/engine/Source/Core/CesiumTerrainProvider.js#L596)（[L813](../packages/engine/Source/Core/CesiumTerrainProvider.js#L813)）；
- 水面效果：`requestWaterMask: true`（构造 [L63](../packages/engine/Source/Core/CesiumTerrainProvider.js#L63)）→ 瓦片侧 [`createWaterMaskTextureIfNeeded`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L1122) 建掩码纹理，GlobeFS 里做水面波光；
- 顶点属性怎么进 shader：[`TerrainEncoding`](../packages/engine/Source/Core/TerrainEncoding.js#L40) 把高程/法线打包方案抽象成编码器，[`createResources`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L1058) 按它建 VAO。

### 6.3 availability：别靠 404 试探

ion 地形带元数据 [`_availability`](../packages/engine/Source/Core/CesiumTerrainProvider.js#L520)（位图结构，哪些 (x,y,level) 存在），
[`getTileDataAvailable`](../packages/engine/Source/Core/CesiumTerrainProvider.js#L1258) O(1) 回答"这块有没有"——四叉树据此不再对不存在的瓦片发请求，也决定 upsample 兜底的时机。

## 7. 骨骼与皮肤：terrainProvider 与 imagery 的分层关系

**地形和影像是两条完全独立的数据管线，只在瓦片对象上汇合**：

```
terrainProvider ──几何──► GlobeSurfaceTile.terrainData/mesh/vertexArray   （骨骼：决定每个顶点的高度）
imageryLayers   ──纹理──► GlobeSurfaceTile.imagery[] = TileImagery[]      （皮肤：决定每个像素的颜色）
                              │
                              ▼ addDrawCommandsForTile（GlobeSurfaceTileProvider.js#L2528）
                    DrawCommand：地形 VAO + day0Texture/day1Texture… + 每层 alpha/调色 uniform
                              ▼ GlobeFS 里按 imageryLayer 自带的 shader 分支多层采样混合
```

- **一个地形瓦片可以挂 N 层影像**（底图 + 叠加层），但只有一套顶点；影像纹理被拉伸贴合到地形网格上（重投影走 ComputeCommand，见 [02 §5](02-底图与影像体系.md)）；
- **加载顺序"先地形后影像"**：地形包围盒（决定瓦片可见性）没就绪前影像不加载（terrainOnly 机制，[GlobeSurfaceTileProvider.js#L695](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L695)【导读】）；
- **渲染分桶按"就绪纹理数"**：不同瓦片就绪的影像层数不同 → 着色器里 `dayTexture` 数组长度不同 → 不同 shader 变体分桶提交（[`showTileThisFrame`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1105)，【导读】L1106）；
- 换底图不换地形、换地形必须重建瓦片（§2）——**地形变更的代价比影像大一个量级**；
- 贴地遮挡：[`globe.depthTestAgainstTerrain`](../packages/engine/Source/Scene/Globe.js#L326)（默认 false）开了之后，entity/模型才真正被山体挡住（[01 §4.7](01-Viewer创建与场景初始化.md)）。

## 8. 动手实验（Sandcastle 控制台）

```js
const globe = viewer.scene.globe;

// 1) 看当前地形是谁
console.log(globe.terrainProvider.constructor.name);   // EllipsoidTerrainProvider = 默认光滑球

// 2) 换 ion 世界地形（对比瓦片数变化）
Cesium.Terrain.fromWorldTerrain().then(t => viewer.scene.setTerrain(t));

// 3) LOD 门槛：调大省流量，调小更精细（默认 2）
globe.maximumScreenSpaceError = 4;
console.log(globe.tilesLoaded, globe._tileLoadProgressEvent);  // 观察加载进度

// 4) 缓存大小与统计
globe.tileCacheSize = 200;
console.log(globe.tileLoadProgressEvent, viewer.scene.globe._surface._tilesToRender.length);

// 5) 高程采样走的就是瓦片数据
const carto = new Cesium.Cartographic(Cesium.Math.toRadians(116.39), Cesium.Math.toRadians(39.9));
Cesium.sampleTerrainMostDetailed(viewer.terrainProvider, [carto]).then(([c]) => console.log(c.height));
```

## 9. 常见坑

- **换了 `terrainProvider` 却不生效**：新式 API 要走 [`scene.setTerrain`](../packages/engine/Source/Scene/Scene.js#L5531)（异步就绪后自动落位），老式 `scene.terrainProvider = await ...` 也行但两入口互斥（[01 §4.7](01-Viewer创建与场景初始化.md)）；
- **`sampleTerrain` 返回的高度"不对"**：椭球地形恒为 0；数据没加载完时返回的是父级低精度值——要"最精细"用 `sampleTerrainMostDetailed`；
- **SSE 调小后卡爆**：maximumScreenSpaceError 从 2 → 1 瓦片数近似翻倍，内存与请求量都跟着涨，先看 `tileCacheSize` 与网络；
- **地形接缝漏缝**：自家切片没做裙边（skirtHeight=5×geometricError 是 CesiumTerrainProvider 的约定），或邻瓦片 availability 声明不一致；
- **tilingScheme 不匹配**：地形与影像的瓦片网格可以不同（影像会重采样/重投影贴到地形网格），但地形自身换 provider 时若 tilingScheme 变了会触发全量失效，闪烁一下是正常现象；
- **depthTestAgainstTerrain = true 后 entity 消失**：不是 bug，是被山体正确遮挡了；只想贴地不想被挡就保持 false + `heightReference`。

## 10. 小结与下一篇

地形 = **TerrainProvider 出几何（quantized-mesh/heightmap）+ GlobeSurfaceTile 状态机装配（TerrainData→Mesh→VAO）+ QuadtreePrimitive 按 SSE 选片调度**；影像是同一条调度管线上的另一层皮肤。
LOD 心法一句：`SSE = 几何误差 × 屏高 / (距离 × sseDenominator)`，门槛 2px——和 3D Tiles（[04](04-3DTiles加载与LOD.md)）完全同构。
