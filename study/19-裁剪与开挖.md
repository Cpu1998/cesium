# 19 · 裁剪与开挖——ClippingPlanes / ClippingPolygons 的引擎侧真相

> 阅读前提：建议先读 [07-地形系统.md](07-地形系统.md)（GlobeSurfaceTileProvider 与四叉树）与 [04-3DTiles加载与LOD.md](04-3DTiles加载与LOD.md)（瓦片遍历），配 [15-Model与glTF加载.md](15-Model与glTF加载.md) 食用更佳。

## 1. 三概念辨析：裁剪 vs 开挖 vs 贴地压平

业务方口中的词和引擎 API 从来不是一一对应，先对齐词汇表：

| 业务说法 | 引擎真实机制 | 作用对象 | 形状 | 数据被改了吗 | 关键 API |
|---|---|---|---|---|---|
| **裁剪/剖切**（切一刀看断面） | `ClippingPlaneCollection`：平面外/内的片元 `discard` | Globe / Tileset / Model | 无限平面（可多张组合） | 否，**只是不画**，顶点仍在 GPU | `globe.clippingPlanes`、`tileset.clippingPlanes` |
| **开挖/挖洞**（挖个坑/湖） | 平面族或多边形族裁掉地表 + **自己补坑壁**（Entity/Model 放填充体）+ 地下可见性配合 | 主要是 Globe | 有限区域（多边形更顺手） | 否 | `globe.clippingPolygons`（1.145 新 API） |
| **贴地压平/场地平整** | 不属于裁剪体系：贴地分类多边形盖在影像上"看起来平" | 贴地图元 | 多边形 | 否 | 09 篇的 GroundPrimitive 路线（[09-几何图元与材质.md](09-几何图元与材质.md)） |
| **限定渲染范围**（只画某经纬度框） | `cartographicLimitRectangle`：纹理坐标越界即 `discard`，与裁剪共用思想但独立实现 | Globe | 矩形 | 否 | [`Globe.cartographicLimitRectangle`](../packages/engine/Source/Scene/Globe.js#L493) |

三个易混点：

- **"开挖"没有原生 API**：引擎只负责"这块不渲染"，坑壁、深度感、回填土是业务层自己加几何。裁掉地形后想看到地心方向的地形背面，需要配合地下模式（§5 的 [`isUndergroundVisible`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1606)，相机入地或半透明 Globe 时背面不剔除）。
- **裁剪是"渲染期"行为**：拾取、深度、阴影都会重算——被裁区域**拾取不到、不投影**（见 §8 阴影联动），这是它和"透明材质遮挡"的本质区别。
- **平面 vs 多边形是两套独立实现**：平面走"浮点纹理存平面方程"路线，多边形在 1.145 走"矢量边纹理 + 射线奇偶"路线（旧版是 SDF 距离场，已弃用），互不复用代码。

## 2. ClippingPlane：一个会"自我举报"的平面

[`ClippingPlane`](../packages/engine/Source/Scene/ClippingPlane.js#L19) 就是 Hessian 法式平面 `(normal, distance)`，数学上与 [`Plane`](../packages/engine/Source/Core/Plane.js) 兼容（[`fromPlane`](../packages/engine/Source/Scene/ClippingPlane.js#L89) 可互转）。它的特别之处是**变更通知**：

- [`distance`](../packages/engine/Source/Scene/ClippingPlane.js#L42) 与 [`normal`](../packages/engine/Source/Scene/ClippingPlane.js#L62) 的 setter 里，若值变化就调用 `onChangeCallback(index)`——这个回调在 [`add`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L280) 进集合时被挂上，指向集合的 [`setIndexDirty`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L260)。
- 更狠的是 [`UpdateChangedCartesian3`](../packages/engine/Source/Scene/ClippingPlane.js#L126)：`normal` 属性返回的其实是个包装对象，`clippingPlane.normal.z = -1` 这种**成员级赋值**也会逐分量触发回调（x/y/z 各有独立 setter）。

**所以拖动平面（改 `distance`）是廉价操作**：集合只标记单个平面脏，GPU 纹理只重传 1-2 个像素（§3）。这是官方 Sandcastle 里"鼠标拖裁剪面"流畅的底层原因。

## 3. ClippingPlaneCollection：容器、脏追踪与纹理打包

[`ClippingPlaneCollection`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L68) 构造选项五行读懂：`planes`（平面数组）、`enabled`、`modelMatrix`（相对宿主坐标系再叠加的变换，**平面坐标默认相对宿主**）、`unionClippingRegions`、`edgeColor/edgeWidth`（断面描边）。

### 3.1 并集/交集语义（最容易写反的一个开关）

[`unionClippingRegions`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L179) 默认 `false`：

- `false`（默认，"交集裁"）：区域在**所有**平面同侧（都出界）才被裁——多平面围出一个"盒子内保留"的效果，挖方井/长方体开挖就用它。
- `true`（"并集裁"）：区域在**任一**平面外侧即被裁——适合"多刀任意一刀都切掉"。

CPU 侧对应 [`unionIntersectFunction`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L146)（OUTSIDE 即裁）与 [`defaultIntersectFunction`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L150)（INSIDE 才保留），供 [`computeIntersectionWithBoundingVolume`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L617) 在整瓦剔除时复用同一套判定。

### 3.2 独占所有权：一个集合只能挂一个宿主

[`ClippingPlaneCollection.setOwner`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L661)：挂载时若已有 `_owner` 直接抛 `DeveloperError`。3D Tiles 的特殊玩法是**集合 owner 归 tileset**，成百上千个瓦片模型共享同一集合——所以只有 owner 才有权 `update`/`destroy` 它（构造器注释 L122 明说）。给 `tileset.clippingPlanes` 赋值即通过 setter 换主，旧集合自动销毁。

### 3.3 脏追踪：单平面脏 vs 全量脏

- `add`/平面成员赋值 → `setIndexDirty(index)`；若脏的**是不同下标**，`_multipleDirtyPlanes` 置真（两次脏不同平面 = 只能全量重传）。
- `remove`/[`removeAll`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L347)（L386）必然全量（后面的平面在纹理里要挪位置）。

### 3.4 update：把平面方程装进一张纹理

[`update`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L467) 每帧由宿主调用（Globe 在 `beginUpdate`，Tileset 在 `prePassesUpdate`，Model 在自身 `update`），干三件事：

1. **选格式**：[`useFloatTexture`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L692) 问 context 支不支持浮点纹理（WebGL2 基本都支持）。
2. **算分辨率/扩容**：[`computeTextureResolution`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L452)——float 格式每平面占 **1 像素**（RGBA=xyz+distance），uint8 格式每平面占 **2 像素**（法线经 [`oct32` 八面体编码](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L404) 1 像素 + [`packFloat`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L434) 编码的 distance 1 像素）。纹理高度按需 `*2` 预分配；超过 4 倍冗余则销毁重建（动态数组的摊还策略）。
3. **按脏范围上传**：单平面脏 → [`packPlanesAsFloats`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L434)(i, i+1) 后 `copyFrom` 只写 1 像素（uint8 是 2 像素宽条带）；多平面脏 → 全量打包全量传。

**一句话：平面集合在 CPU 侧的全部成本 ≈ 一张几十字节的小纹理 + 剔除时的几次平面求交。**

## 4. GPU 侧：一个裁剪平面从定义到像素的链路

平面真正"吃掉"片元发生在片元着色器。GLSL 函数不是手写死的，而是 [`getClippingFunction`](../packages/engine/Source/Scene/getClippingFunction.js#L14) 按当前集合**现场生成字符串**：

- 取数函数二选一：[`getClippingPlaneFloat`](../packages/engine/Source/Scene/getClippingFunction.js#L98)（纹理直读 vec4）或 [`getClippingPlaneUint8`](../packages/engine/Source/Scene/getClippingFunction.js#L124)（`*255` 还原 + `czm_octDecode` 解法线 + `czm_unpackFloat` 解距离），尾部都过 `czm_transformPlane` 把平面变换到眼坐标系。
- 判定函数二选一：[`clippingFunctionUnion`](../packages/engine/Source/Scene/getClippingFunction.js#L40)（任一 `amount<=0` → `breakAndDiscard`）或 [`clippingFunctionIntersect`](../packages/engine/Source/Scene/getClippingFunction.js#L71)（全部 `<=0` 才 `discard`）。注意 union 版先 `break` 再统一 `discard` 的写法是绕 ANGLE/HLSL 编译器 bug（源码注释原文）。
- 核心三行：`position = czm_windowToEyeCoordinates(fragCoord)` → `amount = dot(normal, pos - clipPosition) / czm_metersPerPixel(position)` → 距离按**像素宽**归一。返回的 `clipAmount` 留给描边：小于 `edgeWidth` 像素的片元染成 `edgeColor`。

```
业务代码                          CPU（每帧 update）                GPU（每个片元）
─────────                        ──────────────────                ──────────────
new ClippingPlane(n, d) ──┐
collection.add(plane)     │→ setIndexDirty(i)
                          │
globe.clippingPlanes = c  │→ setOwner(globe 侧 tileProvider)
                          │
每帧 beginUpdate:         └→ collection.update(frameState)
                                ├ float? 1 px/平面 else 2 px
                                ├ 单脏: copyFrom 1px ──────────→ 采样 getClippingPlane()
                                └ 全脏: 全量 copyFrom                │ czm_transformPlane
                                                                    ↓
                              shader 变体(ShaderSet 缓存):        clip(fragCoord,…)
                              ENABLE_CLIPPING_PLANES 定义            ├ amount = dot(n, p-p0)/metersPerPixel
                              + 注入 getClippingFunction 字符串       ├ ≤0 且满足 union/intersect → discard
                                                                    └ clipAmount < edgeWidth → 描边色
```

（Globe 侧注入点见 §5；Model 侧等价物是 [`ModelClippingPlanesStageFS.glsl`](../packages/engine/Source/Shaders/Model/ModelClippingPlanesStageFS.glsl) 的 [`clip`](../packages/engine/Source/Shaders/Model/ModelClippingPlanesStageFS.glsl#L39)，逻辑同源但写成静态 .glsl 由管线注入。）

## 5. Globe 挂点：地形裁剪的完整时序（"开挖"的引擎侧）

### 5.1 属性转发与每帧更新

[`Globe.clippingPlanes`](../packages/engine/Source/Scene/Globe.js#L463) / [`Globe.clippingPolygons`](../packages/engine/Source/Scene/Globe.js#L477) 只是转发给 `tileProvider` 的 getter/setter（[`GlobeSurfaceTileProvider.clippingPlanes`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L349)）。四叉树每帧 [`beginUpdate`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L480) 里 L491-502 依次 `clippingPlanes.update(frameState)`、`clippingPolygons.update(frameState)`——**这就是纹理上传的固定时机**（07 篇三拍调度的第一拍前奏）。

### 5.2 两级剔除的第一级：整瓦不画

[`computeTileVisibility`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L768) 里：

- **平面**（L849-858）：[`computeIntersectionWithBoundingVolume`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L617) 返回 `OUTSIDE` → 整瓦 `Visibility.NONE`，连 DrawCommand 都不建；`INTERSECTING` → 标 `tile.isClipped`，交给 GPU 精裁。
- **多边形**（L861-872）：[`ClippingPolygonCollection.computeIntersectionWithBoundingVolume`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L597) 用的是**外接矩形粗判**（`Rectangle.intersection`），只能标"相交/不相交"，不能断言整瓦被裁——精确剔除靠 §6 的 inverse 整瓦跳过补回。

### 5.3 shader 变体：裁剪状态进 flags 缓存键

地形着色器按"贴图数 × 各种开关"缓存变体（13 篇 ShaderCache 思想的地形版）。[`GlobeSurfaceShaderSet`](../packages/engine/Source/Scene/GlobeSurfaceShaderSet.js#L29) 把 `enableClippingPlanes`/`enableClippingPolygons` 编进 flags 位（L202-203），`clippingPlanesState`（平面数×union×enabled 的组合值，[`ClippingPlaneCollection.clippingPlanesState`](../packages/engine/Source/Scene/ClippingPlaneCollection.js#L251)）编进缓存键（L246-248）。缓存未命中时：L272-274 把 `getClippingFunction` 的字符串 **unshift 到 sources 最前面**（必须在 GlobeFS 之前），L368/372/374 压 `ENABLE_CLIPPING_PLANES` / `ENABLE_CLIPPING_POLYGONS` / `CLIPPING_INVERSE` 定义。

uniform 三件套在 [`GlobeSurfaceTileProvider`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L2067) L2067-2095：`u_clippingPlanes`（纹理）、`u_clippingPlanesMatrix`（`inverseTranspose(view * modelMatrix)`——shader 里 `czm_transformPlane` 用的正是它）、`u_clippingPlanesEdgeStyle`（RGB=edgeColor、A=edgeWidth）。

### 5.4 片元终审：GlobeFS 里的三处丢弃

[`GlobeFS.glsl`](../packages/engine/Source/Shaders/GlobeFS.glsl) 统一声明 L75-77；

- L327-332：`TILE_LIMIT_RECTANGLE`——经纬度框限定的 `discard`（§1 辨析表第 4 行的实现）；
- L335：`clip(gl_FragCoord, u_clippingPlanes, u_clippingPlanesMatrix)`——平面裁剪；L443-450 用返回的 `clipDistance` 给断面描边；
- L453-462：`vectorClip(v_textureCoordinates.xy)`——**多边形裁剪复用贴图自己的 UV**（地形网格 UV 即经纬度归一化，天然就是多边形判定坐标系），`CLIPPING_INVERSE` 时反转内外。

### 5.5 "看到坑里"：地下可见性

裁掉地表只是第一步，想从上往下看进坑还得让地形背面/坑壁可见：[`isUndergroundVisible`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1606) 在相机入地、Globe 半透明（`globe.translucency`）、背剔除关闭、**或启用了裁剪**（L1619-1630：有 clippingPlanes/clippingPolygons 就返回 true）时放行背面渲染——引擎作者显然知道"裁剪多半为了往里看"。业务上的坑壁填充体（DXApp 的 ExcavateTerrainTool 之类）引擎不管，自己用 Entity/Primitive 补。

## 6. ClippingPolygon 家族：1.145 的 SDF→矢量大换血

### 6.1 ClippingPolygon：不可变多边形

[`ClippingPolygon`](../packages/engine/Source/Scene/ClippingPolygon.js#L65)：构造时拷贝并**深冻结** [`positions`](../packages/engine/Source/Scene/ClippingPolygon.js#L243) 与 [`holes`](../packages/engine/Source/Scene/ClippingPolygon.js#L255)（改形状 = 移除再加一个）；构造时一次算好外接 [`rectangle`](../packages/engine/Source/Scene/ClippingPolygon.js#L281) 供粗剔除用。与 ClippingPlane 的"成员级自我举报"完全相反——**不可变才不需要脏通知**。

### 6.2 集合：BufferPolygonCollection 镜像 + 弃用痕迹

[`ClippingPolygonCollection`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L80) 三个硬事实：

1. **WebGL2 限定**：[`isSupported`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L744) 检查 `context.webgl2`，`update` 在 WebGL1 下直接抛 `RuntimeError`。
2. **SDF 已死**：`quality` 与 `debugShowDistanceTexture` 选项在 1.145 打了弃用警告（L248/L223，注释明言 1.147 移除）——旧"带符号距离场纹理"方案被**矢量裁剪**替代，`quality` 现在是空操作。读旧博客/Sandcastle 时注意分辨。
3. **内部镜像**：集合内部维护一个 `show:false / allowPicking:false` 的 [`BufferPolygonCollection`](../packages/engine/Source/Scene/BufferPolygonCollection.js#L101)（L108-124 预分配 2 倍容量）；[`add`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L436) 走 [`packClippingPolygon`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L308)（外环+洞拍平成 Float64Array）入镜像；[`remove`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L510) 因镜像不支持删除而只 [`hideBufferPolygon`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L395)；容量不够时 [`reserveBufferCapacity`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L346) 按 2 的幂整体搬家。

[`update`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L561) 只做一件事：`VectorPipeline.packPolygonCollectionData` 把镜像集合投影到椭球、存成 CPU 侧缓存（版本号跳过无变化重建）。

### 6.3 每瓦片烘焙：requestRectangleData 四步

与平面族"一张全局小纹理"不同，多边形族是**按瓦片烘焙**的。Globe 侧在 [`endUpdate`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L516) 的渲染循环里对每个将画瓦片调 [`updateTileClippingPolygonData`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1485)（只对 `isClipped` 且尚无数据的瓦片），进入 [`ClippingPolygonCollection.requestRectangleData`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L691)：

1. [`VectorPipeline.packPolygonRings`](../packages/engine/Source/Core/VectorPipeline.js#L429)：把所有环投影到该瓦片的 UV 空间并**裁剪到瓦片矩形**（跨瓦多边形被切成瓦内片段）；
2. [`packPolygonGrid`](../packages/engine/Source/Core/VectorPipeline.js#L511)：建空间网格加速结构（每 cell 目标 16 段边，常量 `GRID_TARGET_SEGMENTS_PER_CELL`）；
3. [`packPolygonTextures`](../packages/engine/Source/Core/VectorPipeline.js#L736)：上传三张浮点纹理——`polygonEdgeTexture`（边段坐标+图元号）、`polygonEdgePrimitiveIndicesTexture`、`polygonGridCellIndicesTexture`；
4. 若环为空（瓦片不与任何多边形相交）→ 返回空数据，调用方可整段跳过。

数据挂在瓦片上（[`GlobeSurfaceTile.clippingPolygonData`](../packages/engine/Source/Scene/GlobeSurfaceTile.js#L84)，销毁时 L188-190 释放），集合增删多边形 → `polygonAdded/Removed` 事件 → tileProvider 标脏 → [`endUpdate`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L608) 里 [`releaseClippingPolygonData`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1458) 逐瓦释放重烘焙。整条链路画出来：

```
ClippingPolygon（不可变环）
   │ add()
   ▼
ClippingPolygonCollection
   ├─ 镜像层: BufferPolygonCollection (show:false, 2 的幂扩容, remove=hide)
   │    └─ update() → VectorPipeline.packPolygonCollectionData   ← 集合级缓存(带版本号)
   │
   ├─【Globe 路线】endUpdate 每瓦片:
   │    updateTileClippingPolygonData(tile)  ← 仅 isClipped 且无缓存时
   │      └─ requestRectangleData(tile.rectangle)
   │           ├─ ① packPolygonRings      环→瓦片 UV 空间并裁到瓦片矩形
   │           ├─ ② packPolygonGrid       网格加速结构(每 cell ~16 段)
   │           ├─ ③ packPolygonTextures   3 张浮点纹理上传 GPU
   │           └─ 环空 → 空数据(跳过渲染步骤)
   │    瓦片持 clippingPolygonData ←→ 多边形增删时全量释放重烘焙
   │
   └─【Model 路线】updateClippingPolygons(model)
        └─ requestRectangleData(model.getRectangle())
             └─ VS 算高精度 v_clippingUv → FS vectorClip() → discard
```

### 6.4 GPU：射线奇偶 + inverse 的整瓦跳过

片元判定在共享的 [`vectorClip`](../packages/engine/Source/Shaders/VectorCommon.glsl#L271)：从片元 UV 向外射线，[`vectorEdgeCrossesRay`](../packages/engine/Source/Shaders/VectorCommon.glsl#L200) 数穿过的边数（奇偶定内外），网格 cell 先缩小扫描范围，按"图元号分组"逐组判奇偶（洞自然生效）。这套函数同时服务贴地矢量表渲染与裁剪——**1.145 让裁剪搭上了矢量渲染的便车**。

CPU 侧 inverse 补偿：[`isTileClippedAwayByInversePolygons`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1516) 判定"inverse 模式下瓦片与所有多边形都不相交 → 整瓦都在'外面'该被裁"，[`addDrawCommandsForTile`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L2528) L2531 直接 return。uniform 注入见 L3253-3260（`clippingEdgeTexture` 等三张纹理）。

### 6.5 Model 侧的多边形裁剪：高精度 UV 是主角

[`ModelClippingPolygonsPipelineStage.process`](../packages/engine/Source/Scene/Model/ModelClippingPolygonsPipelineStage.js#L43)：VS 注入 [`ModelClippingPolygonsStageVS.glsl`](../packages/engine/Source/Shaders/Model/ModelClippingPolygonsStageVS.glsl#L15)，FS 注入 [`ModelClippingPolygonsStageFS.glsl`](../packages/engine/Source/Shaders/Model/ModelClippingPolygonsStageFS.glsl#L1)。顶点着色器注释值得精读：**不能用 `v_positionWC` 算经纬度**（32 位浮点精度不够大坐标），改用 `czm_eyeToCartographicDelta(v_positionEC)` 求相机→顶点的测地增量，加上 CPU 侧双精度算好的 `u_clippingCameraUv`——越放大越精确。FS 里同一句 `vectorClip(v_clippingUv)` + `discard`，与 Globe 殊途同归。

## 7. Cesium3DTileset 挂点：共享集合与原点矩阵

先把三宿主摆一张表，四个维度一目了然：

| 维度 | Globe | Cesium3DTileset | Model |
|---|---|---|---|
| 平面坐标系 | 相对地球（`modelMatrix` 叠加世界系） | 相对 [`clippingPlanesOriginMatrix`](../packages/engine/Source/Scene/Cesium3DTileset.js#L1831)（根球心 ENU） | 相对模型 referenceMatrix（tileset 场景下被改写，§7） |
| 集合 update 时机 | [`beginUpdate`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L480) L491 | [`prePassesUpdate`](../packages/engine/Source/Scene/Cesium3DTileset.js#L2807) L2817 | [`updateClippingPlanes`](../packages/engine/Source/Scene/Model/Model.js#L2289) |
| CPU 整瓦剔除 | [`computeTileVisibility`](../packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L768) L849 | [`Cesium3DTile.visibility`](../packages/engine/Source/Scene/Cesium3DTile.js#L1599) L1607 | 无（Model 粒度小，直接 GPU 裁） |
| 多边形数据粒度 | 每地形瓦片一份烘焙 | 每内容 Model 一份（rebake 广播） | 每模型一份 [`requestRectangleData`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L691) |

- **挂载**：构造选项 L116-117；[`clippingPlanes`](../packages/engine/Source/Scene/Cesium3DTileset.js#L1223) / [`clippingPolygons`](../packages/engine/Source/Scene/Cesium3DTileset.js#L1239) 属性赋值时换主销毁旧集合。
- **原点矩阵**：瓦片集的平面坐标不是相对世界原点，而是相对 [`clippingPlanesOriginMatrix`](../packages/engine/Source/Scene/Cesium3DTileset.js#L1831)：装载时取根包围球中心，若在地面上方还自动猜一个 ENU 朝向（L2344-2367）；运行时再叠 root 的 `computedTransform`。**给 BIM 模型写平面参数时，先想清楚这个局部系**。
- **每帧**：[`prePassesUpdate`](../packages/engine/Source/Scene/Cesium3DTileset.js#L2807) L2817-2827 更新两个集合（纹理上传）；L2832-2837 监听多边形增删（[`updateTilesetClippingPolygonListeners`](../packages/engine/Source/Scene/Cesium3DTileset.js#L2780)），把"需要重烘焙"广播到所有已载瓦片（`tile.clippingPolygonsNeedRebake`）。
- **瓦片剔除**：[`Cesium3DTile.prototype.visibility`](../packages/engine/Source/Scene/Cesium3DTile.js#L1599) L1607-1627 与 Globe 同构：平面可整瓦 `MASK_OUTSIDE`，多边形只能标 `_isClippedByPolygon`。
- **下钻到内容**：[`Model3DTileContent.update`](../packages/engine/Source/Scene/Model/Model3DTileContent.js#L249) L272-320 把 tileset 的集合**借**给每个瓦片的 Model（不动 owner），`referenceMatrix` 直接设成 `clippingPlanesOriginMatrix`（L273）；瓦片级 dirty/state 变化时清 Model 的着色器状态强制重跑管线。

## 8. Model 挂点（15 交叉）：状态机驱动重编译

- **挂载**：构造 L392-416；属性 [`clippingPlanes`](../packages/engine/Source/Scene/Model/Model.js#L1386) / [`clippingPolygons`](../packages/engine/Source/Scene/Model/Model.js#L1406)。
- **每帧**：`update` 里 [`updateClippingPlanes`](../packages/engine/Source/Scene/Model/Model.js#L2289) / [`updateClippingPolygons`](../packages/engine/Source/Scene/Model/Model.js#L2328)。两个函数都是**状态对比→重跑管线**的模式，但粒度不同：`clippingPlanesState` 变化（enabled/union/平面数）→ `resetDrawCommands()` 重编着色器；多边形只是增删/rebake → 只重烘焙纹理（便宜得多），仅当"裁↔不裁"翻转才重跑管线。
- **矩阵**：[`updateReferenceMatrices`](../packages/engine/Source/Scene/Model/Model.js#L2657) L2685-2695 预算 `_clippingPlanesMatrix = inverseTranspose(referenceMatrix * planes.modelMatrix)`；uniform 里再乘 `transpose(inverseView3D)`——拆成"视图无关 + 视图相关"两半，阴影 pass 里 `inverseView3D` 是灯光视角，裁剪在阴影里依然正确（管线注释原文，关联 [`ShadowMapShader.hasClippingForShadowCast`](../packages/engine/Source/Scene/ShadowMapShader.js#L23)：着色器带裁剪定义时，阴影投射 pass 必须跑原始 main 让**被裁片元不投影**）。
- **着色器注入**：[`ModelClippingPlanesPipelineStage.process`](../packages/engine/Source/Scene/Model/ModelClippingPlanesPipelineStage.js#L42) 压 `HAS_CLIPPING_PLANES`/`CLIPPING_PLANES_LENGTH`/`UNION_CLIPPING_REGIONS` 等定义 + 三个 `model_clippingPlanes*` uniform + 注入 [`ModelClippingPlanesStageFS.glsl`](../packages/engine/Source/Shaders/Model/ModelClippingPlanesStageFS.glsl)（[`modelClippingPlanesStage`](../packages/engine/Source/Shaders/Model/ModelClippingPlanesStageFS.glsl#L78) 挂进 Model 的片元函数链，15 篇 §渲染管线）。注意它的描边条件多了 `clipDistance > 0`，与 Globe 版（L443-450）细微不同。
- **Entity 入口**：[`ModelGraphics.clippingPlanes`](../packages/engine/Source/DataSources/ModelGraphics.js#L346) 是标准 Property，走 03 篇的可视化管线最终传给 Model。
- **旧点云旁支**：`TimeDynamicPointCloud` 路线的 [`PointCloud.js`](../packages/engine/Source/Scene/PointCloud.js#L1122) 用 [`getClipAndStyleCode`](../packages/engine/Source/Scene/getClipAndStyleCode.js#L12) 拼裁剪+样式代码——18 篇的旧路径仍在用，读源码别混淆。

## 9. 性能与内存账（16 交叉）

- **平面族几乎免费**：CPU 一张极小纹理 + 每瓦几次平面求交；GPU 每片元多几次采样和点积。但注意 GLSL `clip()` 的循环按平面数展开，指令数与平面数线性相关，`clippingPlanesState` 变化（增删平面/切 union）会触发地形与模型 shader 变体**重编译**——**运行时反复增删平面比拖动平面贵得多**，能预估就一次给够。
- **多边形族的账在烘焙**：每地形瓦片三张浮点纹理 + UV 投影，瓦片越多内存越大；换来的是 O(网格 cell) 的片元判定而非 O(总边数)。**频繁增删多边形 = 所有受影响瓦片重烘焙**，适合“初始化定界、运行中不动”的场景；要动态拖拽区域，优先用平面的 `modelMatrix`/`distance`。
- **裁剪对缓存/LOD 的影响**：裁剪不参与瓦片卸载决策（瓦片仍按 SSE/相机正常调度），被整瓦裁掉的瓦片只是不出现在命令列表里，缓存账（16 篇 tileCacheSize）照记——大范围裁剪不能容灾替代 `tileset.cacheBytes` 控制。
- **阴影双重成本**：开了裁剪的着色器，阴影投射 pass 也要跑裁剪逻辑（§8），阴影贴图分辨率为半时成本约 ×1.5。

## 10. 动手实验（Sandcastle 五连）

1. **最小地形开挖**：`viewer.scene.globe.clippingPlanes = new Cesium.ClippingPlaneCollection({ planes: [ new Cesium.ClippingPlane(new Cesium.Cartesian3(1,0,0), 0) ], edgeWidth: 2 })`——垂直一刀切开地球；把 `distance` 从 0 拖到 ±几百万，观察剖面前后移动（§2 的单像素更新）。
2. **长方体坑**：六张平面 `unionClippingRegions:false` 围盒，每 100ms 微调一张平面距离，看断面连续变化；再切 `unionClippingRegions:true`，理解"盒子保留"变"六刀全裁"（§3.1）。
3. **多边形湖**：`ClippingPolygon` + `globe.clippingPolygons`，`inverse:false` 挖内圈；`inverse:true` 只画圈内（整瓦跳过生效，性能反而更稳）。**前提浏览器 WebGL2**，WebGL1 会抛错（§6.2）。
4. **共享集合**：同一个 collection 赋给两个 tileset 试试——第二个赋值会因 owner 独占抛 DeveloperError（§3.2）；正确姿势是每 tileset 各建一份，或挂在 tileset 上让所有瓦片共享。
5. **阴影验证**：给带 castShadow 的 Model 挂平面裁掉一半，开启 `viewer.shadows`，确认被裁半边不投影（§8）。

## 11. 常见坑

| 坑 | 现象 | 解法/锚点 |
|---|---|---|
| 平面方向不对 | 想挖坑结果裁掉了全世界 | 平面裁的是 **normal 背面**一侧；distance 正负+法线方向二试一调（§2） |
| `ClippingPolygon` 在旧设备白屏/抛错 | WebGL1 不支持 | [`isSupported`](../packages/engine/Source/Scene/ClippingPolygonCollection.js#L744) 先查，降级用多平面拼 |
| 改了 `quality` 没反应 | 1.145 已弃用（SDF→矢量） | 删掉该选项，行为不再受它影响（§6.2） |
| tileset 平面坐标"飘" | 平面位置和模型对不上 | 坐标相对 [`clippingPlanesOriginMatrix`](../packages/engine/Source/Scene/Cesium3DTileset.js#L1831)（根包围球中心的 ENU），不是世界系（§7） |
| 同一集合挂两处抛错 | DeveloperError: only be assigned to one object | 独占所有权，每宿主一份（§3.2） |
| 裁剪后拾取"还能点到" | 空洞处仍拾取到对象 | 裁剪在片元级生效，拾取 pass 同样 discard，通常是被**其他未裁对象**（贴地图元/地下网格）命中；用 08 篇 drillPick 分层排查 |
| 裁剪后描边不显示 | edgeWidth 默认 0 | 显式设 `edgeWidth`（像素），`edgeColor` 默认白（§3 构造选项） |
| 旧 `Primitive` 挂 clippingPlanes 没这属性 | API 文档查不到 | 1.145 的 [`Primitive.js`](../packages/engine/Source/Scene/Primitive.js) 已无此属性，裁剪只支持 Globe/Tileset/Model 三宿主（§1） |
| 裁了地形后看到“黑面”而不是坑壁 | 背面渲染的是地形反面 | 引擎只负责不画，坑壁需业务自建几何；配合 §5.5 地下可见性 |
| tileset 的 clippingPolygons 增删后没生效 | 本帧标脏下帧才重烘 | rebake 是逐帧去重广播（§7），连续操作合并到下一帧属正常，不要重复 add/remove 抖动 |

**本篇速记**：平面族=「自举报的平面 → 单纹理增量更新 → 生成式 GLSL `clip()`」；多边形族=「不可变环 → 按瓦烘焙三张矢量纹理 → 共享 `vectorClip` 射线奇偶」；CPU 整瓦剔除两级（平面可断言 OUTSIDE、多边形靠 inverse 补偿）；"开挖"=裁剪 + 地下可见性 + 业务自填坑壁。下一篇 [20-实战速查.md](20-实战速查.md) 把全书 00-19 收进一张菜谱索引。
