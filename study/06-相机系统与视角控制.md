# 06 · 相机系统与视角控制

> 阅读前提：读完 [00-总览](00-总览-架构与目录地图.md) §3 对象树与 [05-帧更新与渲染循环.md](05-帧更新与渲染循环.md) §1–§2（知道一帧里 `initializeFrame → render` 的节奏）。
> 本文拆解相机是谁、姿态怎么表示、`setView/lookAt/flyTo` 如何落笔，以及世界坐标和屏幕坐标怎么互转。

本文的主战场文件：

- [`Camera.js`](../packages/engine/Source/Scene/Camera.js) —— 相机本体：位姿、变换、`setView/lookAt/flyTo` 全在这

- [`PerspectiveFrustum.js`](../packages/engine/Source/Core/PerspectiveFrustum.js) / [`OrthographicFrustum.js`](../packages/engine/Source/Core/OrthographicFrustum.js) —— 视锥体（投影）

## 0. 全景：相机在场景里的位置

```
CesiumWidget (每帧)
 └─ scene.initializeFrame()                       Scene.js#L4459
     ├─ scene._screenSpaceCameraController.update()   交互层：把累计的手势增量喂给相机
     └─ scene.camera.update(mode)                     相机层：归一化方向、按 SceneMode 换 frustum
 └─ scene.render(time)
     └─ executeCommands... → camera.frustumCommandsList  视锥层：多视锥切片逐个提交命令
```

相机创建于 [`Scene.js`](../packages/engine/Source/Scene/Scene.js) 构造函数（[`const camera = new Camera(this)`](../packages/engine/Source/Scene/Scene.js#L733)），
随即包进一个 **View**：[`this._defaultView = new View(this, camera, viewport)`](../packages/engine/Source/Scene/Scene.js#L755)。
[`View.js`](../packages/engine/Source/Scene/View.js) 的 [`function View`](../packages/engine/Source/Scene/View.js#L42)
= 一台相机 + 一个 viewport（[`passState.viewport`](../packages/engine/Source/Scene/View.js#L56)）+ 该视口的多视锥命令列表；
[`scene.camera`](../packages/engine/Source/Scene/Scene.js#L1052) / [`scene.view`](../packages/engine/Source/Scene/Scene.js#L1071)
其实都是转发到当前 `_view` 的语法糖——这就是引擎里的「视口（multi-view）」抽象层，早期多视口/VR 立体渲染 API 已随 1.145 移除，只剩 View 这层骨架。

## 1. 数据模型：可写的四元组 + 一个参考系

[`function Camera(scene)`](../packages/engine/Source/Scene/Camera.js#L82) 构造出的相机有五个**公开可写字段**：

| 字段 | 定义行 | 含义 |
|---|---|---|
| `position` | [L101](../packages/engine/Source/Scene/Camera.js#L101) | 相机在**参考系内**的位置（默认参考系=世界系） |
| `direction` | [L134](../packages/engine/Source/Scene/Camera.js#L134) | 视线方向（指向画面里侧） |
| `up` | [L143](../packages/engine/Source/Scene/Camera.js#L143) | 头顶方向 |
| `right` | [L152](../packages/engine/Source/Scene/Camera.js#L152) | 右手方向 |
| `frustum` | [L166](../packages/engine/Source/Scene/Camera.js#L166) | 视锥体，默认 `PerspectiveFrustum`，fov 60° |

**关键结论：相机内部没有存 heading/pitch/roll，也没有存四元数——「真身」就是 position+direction+up+right 四个 `Cartesian3`**。
你随手改这四个字段是合法操作（下一帧生效），因为每帧 [`Scene.prototype.initializeFrame`](../packages/engine/Source/Scene/Scene.js#L4459) 都会调
[`Camera.prototype.update`](../packages/engine/Source/Scene/Camera.js#L1120)，内部经
[`updateMembers`](../packages/engine/Source/Scene/Camera.js#L657)
做三件事：**归一化 direction/up/right、缓存"上一帧值"用于变化检测、按 SceneMode 换算 frustum**（2D 强制正交）。

### 1.1 参考系 transform：position 和 positionWC 的区别

相机还有一个 4×4 **参考系** [`_transform`](../packages/engine/Source/Scene/Camera.js#L860)（默认 `Matrix4.IDENTITY`）：

```
position/direction/up/right      ——在参考系内表达（局部）
        │  transform(4×4)  ↕ 投影
positionWC/directionWC/upWC/rightWC ——世界坐标（ECEF）下的真身
```

- [`positionWC`](../packages/engine/Source/Scene/Camera.js#L938)、[`positionCartographic`](../packages/engine/Source/Scene/Camera.js#L924)、`directionWC/upWC/rightWC`（[L952](../packages/engine/Source/Scene/Camera.js#L952)/[L966](../packages/engine/Source/Scene/Camera.js#L966)/[L980](../packages/engine/Source/Scene/Camera.js#L980)）都是只读 getter；
- 视图矩阵 [`viewMatrix`](../packages/engine/Source/Scene/Camera.js#L891) 及其逆 [`inverseViewMatrix`](../packages/engine/Source/Scene/Camera.js#L907) 由
  [`updateViewMatrix`](../packages/engine/Source/Scene/Camera.js#L316) 每次位姿变化时重算——渲染用 view·projection 把世界点搬进裁剪空间；
- [`_setTransform`](../packages/engine/Source/Scene/Camera.js#L1179) 切参考系时**不动 position 字段**，只重投影 WC 派生量——`lookAt` 全靠它（§4）。

典型参考系是 [`Transforms.eastNorthUpToFixedFrame`](../packages/engine/Source/Core/Transforms.js#L276)（某点的东北天局部系）或
[`Transforms.headingPitchRollToFixedFrame`](../packages/engine/Source/Core/Transforms.js#L384)。

## 2. heading / pitch / roll：算出来的派生量

[`heading`](../packages/engine/Source/Scene/Camera.js#L994)、[`pitch`](../packages/engine/Source/Scene/Camera.js#L1025)、[`roll`](../packages/engine/Source/Scene/Camera.js#L1056)
是**只读计算属性**，没有内部存储。以 heading getter 为例，它干的事：

1. 临时把参考系换成「相机当前所在点的 ENU 局部系」（[`eastNorthUpToFixedFrame`](../packages/engine/Source/Core/Transforms.js#L276)）；
2. 在这个局部系里用 [`getHeading`](../packages/engine/Source/Scene/Camera.js#L818)/[`getPitch`](../packages/engine/Source/Scene/Camera.js#L831)/[`getRoll`](../packages/engine/Source/Scene/Camera.js#L835) 从 direction/up/right 反解三个角；
3. 换回原参考系。

**所以 HPR 的语义永远是「相对于相机脚下那块地面的东北天方向」**——这解释了为什么贴地飞行时 heading 始终有定义。反过来，`setView/flyTo` 接受 `{heading, pitch, roll}` 时，也是先经
[`directionUpToHeadingPitchRoll`](../packages/engine/Source/Scene/Camera.js#L1391) 换算成 direction/up 再写进相机。

变化事件：[`moveStart`](../packages/engine/Source/Scene/Camera.js#L1086)/[`moveEnd`](../packages/engine/Source/Scene/Camera.js#L1098) 报告运动起止（flyTo 与交互都会触发）；
[`changed`](../packages/engine/Source/Scene/Camera.js#L1110) 按 [`percentageChanged`](../packages/engine/Source/Scene/Camera.js#L89)（默认 0.5）阈值报告"相机变了多少"，给拾取缓存失效这类场景用。

## 3. setView：瞬移（无动画）

[`Camera.prototype.setView`](../packages/engine/Source/Scene/Camera.js#L1488) 是所有落笔动作的地基，参数两件套：`destination` + `orientation`。流程：

```
setView(options)
 ├─ endTransform? → _setTransform(先切参考系)
 ├─ destination 是 Rectangle? → getRectangleCameraCoordinates 换成"矩形中心上空"的 Cartesian3
 │    （默认矩形 = Camera.DEFAULT_VIEW_RECTANGLE，Cesium 默认给的是美洲那格，
 │      国内应用常改成中国范围）
 ├─ orientation 给了 direction/up? → directionUpToHeadingPitchRoll 换算成 HPR
 ├─ HPR 缺省值：heading 0 / pitch -90°(正下看) / roll 0
 └─ 按 SceneMode 分派：
     SCENE3D → setView3D      Camera.js#L1268
     SCENE2D → setView2D      Camera.js#L1338   （正交贴图视角，忽略 heading/roll）
     COLUMBUS → setViewCV     Camera.js#L1303
```

- [`getRectangleCameraCoordinates`](../packages/engine/Source/Scene/Camera.js#L2879)：给定 [`Rectangle`](../packages/engine/Source/Core/Rectangle.js#L35)，算出"恰好俯视装下这个矩形"的相机位置；
- 反向 API 是 [`computeViewRectangle`](../packages/engine/Source/Scene/Camera.js#L3883)：用视锥
  [`computeCullingVolume`](../packages/engine/Source/Core/PerspectiveFrustum.js#L318) 对椭球求交，返回**当前视野**覆盖的经纬矩形；
- 默认主视图由 [`Camera.DEFAULT_VIEW_RECTANGLE`](../packages/engine/Source/Scene/Camera.js#L291)（默认 95°W–70°W、20°S–90°N，覆盖美洲那块）与
  [`DEFAULT_VIEW_FACTOR`](../packages/engine/Source/Scene/Camera.js#L304)（再往外退 50%）决定；[`flyHome`](../packages/engine/Source/Scene/Camera.js#L1544) 就是飞回它。

## 4. lookAt / lookAtTransform：换参考系围着一个点看

[`Camera.prototype.lookAt`](../packages/engine/Source/Scene/Camera.js#L2331) = 两步：

1. 在 target 处建 ENU 参考系：[`Transforms.eastNorthUpToFixedFrame(target)`](../packages/engine/Source/Core/Transforms.js#L276)；
2. 调 [`lookAtTransform`](../packages/engine/Source/Scene/Camera.js#L2419)，把相机放进该参考系并用 offset 定位。

offset 支持两种写法：`Cartesian3`（参考系内的局部偏移）；或 `HeadingPitchRange`，由
[`offsetFromHeadingPitchRange`](../packages/engine/Source/Scene/Camera.js#L2360) 用两个四元数（绕 Y 的 pitch、绕 Z 的 heading）旋出方位再乘 range。

**注意参考系副作用**：`lookAt` 之后 position 的语义变成"参考系内坐标"，直接 `camera.position = new Cartesian3(...)` 会得到出乎意料的结果；
想回世界系要 [`_setTransform(Matrix4.IDENTITY)`](../packages/engine/Source/Scene/Camera.js#L1179)——对外惯用手法是 `camera.lookAtTransform(Matrix4.IDENTITY)`。

## 5. flyTo：一次飞行的完整调用链

「飞过去」本质是**一条 tween 动画，每帧回调里反复调 setView**。全景时序：

```
camera.flyTo({destination, orientation, duration, easingFunction, complete, cancel})
│ Camera.js#L3425
├─ MORPHING 中? → 直接 return（ morph 动画优先）
├─ cancelFlight()                     Camera.js#L3335   先掐掉在飞的旧 tween
├─ destination 是 Rectangle?
│    └─ getRectangleCameraCoordinates 求出终点 Cartesian3
├─ orientation.direction? → directionUpToHeadingPitchRoll 换 HPR
├─ duration ≤ 0（或没给且两点重合）?
│    └─ 立即 setView + 同步 complete()      ——「瞬移模式」
└─ 否则：
     CameraFlightPath.createTween(scene, {...})      CameraFlightPath.js#L406
     │  ├─ 求起终点 Cartographic（fromDegreesGIK? → ellipsoid.cartesianToCartographic）
     │  ├─ 3D: createUpdate3D      CameraFlightPath.js#L219
     │  │    ├─ createHeightFunction  L75   高度包络线（先爬升后俯冲，跨 0.5 圈取最长路径 useLongestFlight L199）
     │  │    ├─ createPitchFunction  L45    中途自动压 pitch（pitchAdjustHeight）
     │  │    └─ update(time) 每帧：lerp 经纬度 + 高度函数 + HPR → camera.setView   L321
     │  ├─ 2D: createUpdate2D      L334（平移 + zoom 出正交范围）
     │  └─ CV: createUpdateCV      L150
     └─ scene.tweens.add(tweenOptions)   Camera.js#L3510
          └─ TweenCollection 每帧驱动 → setView → moveEnd 时 complete()
```

要点：

- **duration 不传时按"最长的距离×比例"自动估算**，估算在 [`createTween`](../packages/engine/Source/Scene/CameraFlightPath.js#L406) 内完成；
- 每帧回调最终都落到 [`camera.setView`](../packages/engine/Source/Scene/Camera.js#L1488)——**飞行没有独立的状态机，就是一串连续 setView**（3D 分支见 [CameraFlightPath.js L321](../packages/engine/Source/Scene/CameraFlightPath.js#L321)）；
- tween 宿主是 [`scene._tweens = new TweenCollection()`](../packages/engine/Source/Scene/Scene.js#L208)，[`TweenCollection.prototype.add`](../packages/engine/Source/Scene/TweenCollection.js#L214) 在每帧 `initializeFrame` 阶段推进；
- [`flyToBoundingSphere`](../packages/engine/Source/Scene/Camera.js#L3660)：算出能装下包围球的距离（球面点 → [`offsetFromHeadingPitchRange`](../packages/engine/Source/Scene/Camera.js#L2360) 定位），最终仍转手 `flyTo`；
- 掐断飞行统一走 [`cancelFlight`](../packages/engine/Source/Scene/Camera.js#L3335)（用户一拖动，交互层就会替你调它）。

## 6. frustum 体系：投影 + 多视锥切片

单个视锥是「投影参数包」：fov/aspectRatio + 派生的投影矩阵和剔除体。

| 类 | 定义 | 投影矩阵 | 特点 |
|---|---|---|---|
| [`PerspectiveFrustum`](../packages/engine/Source/Core/PerspectiveFrustum.js#L35) | 透视，对称 | [projectionMatrix L240](../packages/engine/Source/Core/PerspectiveFrustum.js#L240) | 内部委托给 [`PerspectiveOffCenterFrustum`](../packages/engine/Source/Core/PerspectiveFrustum.js#L38)；[`sseDenominator`](../packages/engine/Source/Core/PerspectiveFrustum.js#L277) 供 LOD 公式用（[04 §3](04-3DTiles加载与LOD.md)） |
| [`OrthographicFrustum`](../packages/engine/Source/Core/OrthographicFrustum.js#L30) | 正交，对称 | [projectionMatrix L184](../packages/engine/Source/Core/OrthographicFrustum.js#L184) | 2D 模式必用；缩放=改 frustum 宽度而非 position.z |
| [`PerspectiveOffCenterFrustum`](../packages/engine/Source/Core/PerspectiveOffCenterFrustum.js) / OrthographicOffCenter | 非对称变体 | —— | 视锥切片/阴影相机等内部用途 |

- 切透视/正交有现成开关：[`switchToPerspectiveFrustum`](../packages/engine/Source/Scene/Camera.js#L3985) / [`switchToOrthographicFrustum`](../packages/engine/Source/Scene/Camera.js#L4009)（2D 永远正交）；
- 剔除体由 [`computeCullingVolume`](../packages/engine/Source/Core/PerspectiveFrustum.js#L318) 生成，被 [`computeViewRectangle`](../packages/engine/Source/Scene/Camera.js#L3883) 和全局剔除共用（详见 [05 §5](05-帧更新与渲染循环.md)）；
- 像素尺寸换算 [`getPixelDimensions`](../packages/engine/Source/Core/PerspectiveFrustum.js#L359)。

### 6.1 多视锥（multi-frustum）：一帧被切成 N 段深度

地球场景近平面 1 米、远平面 6.3e6 米，单个 float 深度缓冲扛不住。Cesium 的解法：**一帧内按深度从远到近切成多个视锥，每个视锥单独 clearDepth+draw**。源码锚点：

- 设计注释直读 [`Scene.js`](../packages/engine/Source/Scene/Scene.js#L95)（【导读】注释解释了动机）；
- 视锥-命令对 [`FrustumCommands(near, far)`](../packages/engine/Source/Scene/FrustumCommands.js#L13) 存在 View 里；
- [`scene.frustumCommandsList`](../packages/engine/Source/Scene/Scene.js#L1510)（长度=视锥个数 [numFrustums](../packages/engine/Source/Scene/Scene.js#L1525)）；
- 每帧由 [`View.checkForCameraUpdates`](../packages/engine/Source/Scene/View.js#L131) 依据相机 near/far 重切视锥，命令灌入后逐视锥执行（[`Scene.js#L2833`](../packages/engine/Source/Scene/Scene.js#L2833) 起）。

这与拾取、logDepth 的取舍见 [05 §5](05-帧更新与渲染循环.md)；**换视锥不会换相机**——一台 `Camera` 只有一个 frustum 字段，多视锥是渲染管线概念，逐段克隆出临时 offCenter 视锥而已。

## 7. SceneTransforms：世界坐标 ↔ 屏幕坐标

「经纬度点 → 屏幕像素」是弹窗、标注、追踪框的刚需，全部经 [`SceneTransforms.js`](../packages/engine/Source/Scene/SceneTransforms.js)：

```
Cartesian3（世界/ECEF）
   │ worldToWindowCoordinates(scene, position)          L46
   ▼
worldWithEyeOffsetToWindowCoordinates                   L99
   ├─ 2D 模式先纠偏：computeActualEllipsoidPosition      L301
   ├─ worldToClip：CV/3D 分支 + eyeOffset(眼睛偏移，避免重叠 billboard 闪面) L58
   └─ clipToGLWindowCoordinates：裁剪空间 → 窗口像素      L358
   ▼
Cartesian2 {x, y}（CSS 像素）
   │ transformWindowToDrawingBuffer                       L376  ×devicePixelRatio
   ▼
worldToDrawingBufferCoordinates(scene, position)         L282   ——画到 canvas 上用这个
```

- **旧名 `wgs84ToWindowCoordinates` 在 1.145 已移除**，统一为 [`worldToWindowCoordinates`](../packages/engine/Source/Scene/SceneTransforms.js#L46)；
- 返回的 CSS 像素与 [`drawingBufferToWorldCoordinates`](../packages/engine/Source/Scene/SceneTransforms.js#L397)（逆变换）在**浏览器缩放≠100% 或高分屏**下会有差，那时用 [`worldToDrawingBufferCoordinates`](../packages/engine/Source/Scene/SceneTransforms.js#L282)；
- 眼睛偏移（eyeOffset）在这里参与矩阵乘，billboard 负 z 偏移防 z-fighting 的效果就来自 [worldToClip](../packages/engine/Source/Scene/SceneTransforms.js#L58)；
- 注意：此变换**只看主相机视锥、逐视锥原点不一致时以第一个视锥为准**，跨越多视锥接缝的物体在屏幕坐标上是近似值。

## 8. 交互层：ScreenSpaceCameraController

鼠标滚轮/拖拽不直接写相机，而是由 [`ScreenSpaceCameraController`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L35) 翻译。每帧
[`scene.initializeFrame`](../packages/engine/Source/Scene/Scene.js#L4459) 里 [`controller.update()`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L3010) 先于
[`camera.update`](../packages/engine/Source/Scene/Scene.js#L4500) 执行（顺序很关键：先让交互层写完位姿，再让相机归一化）。

常用开关速查：

| 需求 | 字段（均在 [构造器](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L35) 里初始化） |
|---|---|
| 禁掉全部交互 | `enableInputs` |
| 禁旋转/平移/缩放/倾斜 | `enableRotate`（[L74](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L74)）/ `enableTranslate` / `enableZoom` / `enableTilt` |
| 惯性手感 | `inertiaSpin`（[L96](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L96)，0~1，越大越"滑"）等 inertia* 家族 |
| 卡进地面/飞出太空 | `minimumZoomDistance`（[L132](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L132)）/ `maximumZoomDistance` |
| 想穿地 | `enableCollisionDetection = false` |

交互层最终调的仍是 §3–§5 那些 API（rotate→[`rotate`](../packages/engine/Source/Scene/Camera.js#L2028)、拖拽中键 tilt→[`look`](../packages/engine/Source/Scene/Camera.js#L1966)、滚轮→[`zoomIn`](../packages/engine/Source/Scene/Camera.js#L2255)/[`zoomOut`](../packages/engine/Source/Scene/Camera.js#L2272)、平移→[`move`](../packages/engine/Source/Scene/Camera.js#L1777) 家族）。
**一次拖拽会打断 flyTo**，因为交互层更新前先调 [`cancelFlight`](../packages/engine/Source/Scene/Camera.js#L3335)。

## 9. 动手实验（复制进 Sandcastle 控制台）

```js
const cam = viewer.camera;

// 1) 直接写字段合法：每帧 updateMembers 会归一化
cam.position.z *= 0.5;

// 2) HPR 是派生量：direction 稍微一歪，heading 立刻跳变
console.log(cam.heading, cam.pitch, cam.roll);

// 3) 飞行=连续 setView：观察 moveStart/moveEnd 只报一次
cam.moveStart.addEventListener(() => console.log("start"));
cam.moveEnd.addEventListener(() => console.log("end"));
cam.flyTo({ destination: Cartesian3.fromDegrees(116.39, 39.9, 5000) });

// 4) 多视锥切片：放大到贴地，数一下切了几段
console.log(viewer.scene.frustumCommandsList.length, viewer.scene.numberOfFrustums);

// 5) 世界→屏幕：给天安门上钉一个像素
const p = Cesium.SceneTransforms.worldToWindowCoordinates(
  viewer.scene, Cesium.Cartesian3.fromDegrees(116.3912, 39.9075, 46));
console.log(p);   // 打开 F12 看 CSS 像素坐标

// 6) lookAt 之后 position 语义变了，注意还原
cam.lookAt(Cartesian3.fromDegrees(116.39, 39.9), new Cesium.HeadingPitchRange(0, -0.5, 2000));
cam.lookAtTransform(Cesium.Matrix4.IDENTITY);   // 还回世界系
```

## 10. 常见坑

- **`camera.position` 不是经纬度也不是米高**——它是 ECEF 直角坐标（参考系=IDENTITY 时）。取高度用 [`positionCartographic.height`](../packages/engine/Source/Scene/Camera.js#L924)；
- **2D 模式下 heading/roll 大多被忽略**、frustum 被换成正交（见 [`update`](../packages/engine/Source/Scene/Camera.js#L1120) 内 2D 分支），别在 2D 里调 HPR 动画；
- **`flyTo` 的 duration≤0 不是"最快飞过去"而是瞬移**，且不会触发 moveStart；
- **`wgs84ToWindowCoordinates` 已不存在**（1.145 移除），迁移到 [`worldToWindowCoordinates`](../packages/engine/Source/Scene/SceneTransforms.js#L46)；高分屏/浏览器缩放异常时改用 drawingBuffer 版本；
- **lookAt/lookAtTransform 之后忘了复位参考系**，后续所有 setView/position 都在局部系里，位置"乱飞"——用 `lookAtTransform(Matrix4.IDENTITY)` 收尾；
- **改 `camera.frustum.fov` 只影响当前 frustum 实例**；2D↔3D morph、`switchTo*` 会整个换掉 frustum 对象（[L3997](../packages/engine/Source/Scene/Camera.js#L3997)），fov 设置需要在切换后重打。

## 11. 小结与下一篇

相机 = **可写四元组（position/direction/up/right）+ 参考系 transform + frustum**；HPR 是投影出来的派生量；
一切"落笔"（setView/lookAt/flyTo/交互）最终都收敛到 setView；一帧多视锥切片解决深度精度。
