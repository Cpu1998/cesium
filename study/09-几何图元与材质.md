## 0. 全景：一个 `entity.rectangle` 到 DrawCommand 的管线

```
Entity.rectangle（声明式，随时间变化的 Property）
  │ RectangleGeometryUpdater（差量观察几何/材质属性）        DataSources/RectangleGeometryUpdater.js#L55
  ▼
GeometryVisualizer（Entity 集合 → 桶式合批）                DataSources/GeometryVisualizer.js#L40
  │ 静态桶 StaticGeometryColorBatch / PerMaterialBatch …    每桶一个 Primitive
  ▼
GeometryInstance = Geometry + modelMatrix + color/show 实例属性   Core/GeometryInstance.js#L51
  │ Primitive.loadSynchronous / loadAsynchronous
  │   ├─ createGeometry（Worker）：工厂算顶点 → Geometry         RectangleGeometry.createGeometry
  │   └─ PrimitivePipeline.combineGeometry：世界坐标变换+合批+法线/压缩  Core/GeometryPipeline.js
  ▼
createVertexArray：VAO/VBO/IBO 上传 GPU                    Scene/Primitive.js#L1622
  │ createShaderProgram：Appearance/Material 的 GLSL 拼装       Scene/Primitive.js#L1724
  ▼
createCommands + updateAndQueueCommands → colorCommands     Scene/Primitive.js#L1842/L1997
  （每条命令带 pickId="v_pickColor" → 08 §4 的 pick 变体）
```

**记忆锚点**：`Geometry` 是「一份顶点数据」，`GeometryInstance` 是「这份顶点数据的一次摆放+一组实例常量」，
`Primitive` 是「N 个 instance 合批后的一次提交」，`Appearance/Material` 决定「这批 instance 怎么着色」。

## 1. 三层数据模型：Geometry / GeometryAttribute / GeometryInstance

[`function Geometry(options)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Geometry.js#L67)
就是一个**纯数据包**，四个字段：

| 字段 | 行 | 说明 |
|---|---|---|
| `attributes` | [L118](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Geometry.js#L118) | `GeometryAttributes` 字典；**非交错存储**（每个属性一块独立 typed array） |
| `indices` | [L128](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Geometry.js#L128) | 索引数组（`Uint16/Uint32` 由 `IndexDatatype.createTypedArray` 按需选择） |
| `primitiveType` | [L138](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Geometry.js#L138) | TRIANGLES / LINES / … 默认三角形 |
| `boundingSphere` | [L148](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Geometry.js#L148) | 包围球（CPU 剔除用，呼应 [05 §5](05-帧更新与渲染循环.md)） |

属性名是保留字语义的（详见 [L74-L117 的文档注释](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Geometry.js#L74)）：
`position/normal/st/tangent/bitangent` 由工厂按 [`VertexFormat`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/VertexFormat.js#L25) 决定要不要算；
而 `position3DHigh/position3DLow`（GC 编码保精度）、`color`、`pickColor` 是后处理阶段由 GeometryPipeline/Primitive **加进去**的。
单个属性由 [`GeometryAttribute`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryAttribute.js#L40) 描述：
`componentDatatype`（FLOAT/UNSIGNED_BYTE…）+ `componentsPerAttribute`（2/3/4）+ `values`（typed array）。

[`function GeometryInstance(options)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryInstance.js#L51)
给 Geometry 加三样东西：

- [`modelMatrix`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryInstance.js#L78)：模型→世界变换（默认 IDENTITIY=直接在世界系；典型值是 [`Transforms.eastNorthUpToFixedFrame`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Transforms.js#L276)）；
- [`id`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryInstance.js#L90)：拾取时原样返回的用户对象（`scene.pick(...).id === entity` 的出处，见 [08 §3](08-拾取系统.md)）；
- [`attributes`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryInstance.js#L107)：**实例级常量属性**——
  [`ColorGeometryInstanceAttribute`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ColorGeometryInstanceAttribute.js#L34)（一个 instance 一种色）、
  [`ShowGeometryInstanceInstanceAttribute`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ShowGeometryInstanceAttribute.js#L32)（显隐，08 §7 drillPick 靠它隐藏单个 instance）。
  与顶点属性的区别：**顶点属性逐顶点变化，实例属性整个 instance 一个值**，合批后进 batch table 纹理按 instance 索引取样。

## 2. 几何工厂四代表：顶点布局怎么算

所有工厂长一个样：构造函数只存参数，真正的顶点计算在静态方法 `XxxGeometry.createGeometry(xxxGeometry)` 里
（这样它才能被序列化后丢进 Web Worker 执行，见 §3）。

**① [`BoxGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/BoxGeometry.js#L42)（最简，看结构）**
min/max 盒子，[`fromDimensions`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/BoxGeometry.js#L90) 换算成 ±dim/2；
[`createGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/BoxGeometry.js#L246)
输出 24 顶点（每面 4 顶点独立、法线即面法线）+ 36 索引，**没有细分**——盒子是平直的，granularity 无意义。

**② [`RectangleGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/RectangleGeometry.js#L1016)（经纬网格采样）**
[`granularity`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/RectangleGeometry.js#L1035)
（弧度步长，默认 1°）把矩形切成 **rows×cols 网格**：
[`constructRectangle`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/RectangleGeometry.js#L220)
逐行逐列采样 `ellipsoid.geodeticSurfaceNormal` 抬到椭球面（Float64 position + Float32 st），
两极封帽行（northCap/southCap）特殊处理；顶点属性里法线/切线是事后由
[`calculateAttributes`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/RectangleGeometry.js#L72)
按相邻顶点差分补算的。挤出（height/extrudedHeight）时上下两面+四条裙边墙。

**③ [`EllipseGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EllipseGeometry.js#L920)（象限对称扇形）**
细分粒度换算在 [`EllipseGeometryLibrary.computeEllipsePositions`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EllipseGeometryLibrary.js#L113)：
`numPts = 1 + ceil((π/2)/granularity×8)`，只算**一个象限**的点，四象限对称展开；
[`computeEllipse`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EllipseGeometry.js#L417)
产顶面 + [`topIndices`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EllipseGeometry.js#L314)
用「扇形索引」（`12·numPts·(numPts+1)−6` 条）连三角形；挤出时另有
[`computeWallAttributes`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EllipseGeometry.js#L450) 侧墙。

**④ [`PolygonGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/PolygonGeometry.js#L668)（先三角化再细分）**
与前面两家的「规则网格」不同，多边形是任意的：
[`PolygonGeometryLibrary.createGeometryFromPositions`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/PolygonGeometryLibrary.js#L965)
先把多边形投到切平面（2D），用
[`PolygonPipeline.triangulate`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/PolygonPipeline.js#L67)
做**耳切三角化**（第三方库 [earcut](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/PolygonPipeline.js#L1)，支持 holes 岛屿），
再把大三角形按 granularity **细分并抬回椭球面**（弧线在球面上是弯的，直线三角形必须切碎）；
ArcType 还区分 GEODESIC（大圆）/RHUMB（恒向线）走不同的细分路径。
挤出体由 [`createGeometryFromPositionsExtruded`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/PolygonGeometry.js#L428) 生成侧墙。

| 工厂 | 顶点来源 | 索引方式 | 细分控制 |
|---|---|---|---|
| Box | 6 面拼装 | 固定 36 | 无 |
| Rectangle | 经纬网格采样 | 网格三角条带化 | granularity |
| Ellipse | 单象限采样×4 对称 | 扇形索引 | granularity×8 |
| Polygon | 切平面耳切+细分回弹 | earcut 输出 | granularity / ArcType |

## 3. Primitive：从 `GeometryInstance[]` 到 GPU

[`function Primitive(options)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L154)
的 [`update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L2079)
是一个小状态机（READY→CREATING→COMBINING→COMPLETE），两条加载路径：

- **异步（默认）** [`loadAsynchronous`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1149)：
  把每个 instance 的几何打包成 subTask 丢给 `createGeometry` Web Worker 池（按 `_workerName` 路由到各工厂的 worker 版），
  再用 `PrimitivePipeline.combineGeometry` 在 worker 里做完下述后处理——**主线程不卡**；
- **同步** [`loadSynchronous`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1309)：同一条链在主线程跑。

combine 阶段（[`GeometryPipeline`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js) 干活）依次：

1. [`transformToWorldCoordinates`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js#L835)：把各 instance 的 modelMatrix 烘进顶点（世界系合批的前提）；
2. [`combineInstances`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js#L1101)：同 primitiveType 的几何拼成大顶点缓冲；
3. [`computeNormal`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js#L1162)（需要时补法线）、
   [`encodeAttribute`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js#L727)
   （position 拆 high/low 双精度）、[`projectTo2D`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js#L616)（2D/CV 模式坐标）、
   [`compressVertices`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeometryPipeline.js#L1480)（normal/st 压成单个 float）。

完成后 [`createVertexArray`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1622)
调用 [`VertexArray.fromGeometry`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/VertexArray.js#L575)：
每个属性一个 [`Buffer.createVertexBuffer`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Buffer.js#L135)（STATIC_DRAW）、
索引走 [`createIndexBuffer`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Buffer.js#L194)，
绑定成 VAO 存进 `primitive._va`；然后 `releaseGeometryInstances` 生效时**CPU 侧几何数组被丢弃**（内存只留 GPU 侧）。
渲染命令在 [`createCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1842)：
每个 geometry 一条 colorCommand（半透明时再乘 2 次 twoPasses），由
[`updateAndQueueCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1997)
按视锥可见性推进 frameState.commandList——并给每条命令打上
[`colorCommand.pickId = "v_pickColor"`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L2056)（08 §4 pick 变体的钩子）。
实例属性（color/show/pickColor）不进 VBO，进 [`createBatchTable`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L538)
的**批表纹理**，shader 里按 `gl_InstanceID` 式索引取样——这是「一次 draw 画 N 个不同颜色的 instance」的关键。
[`getGeometryInstanceAttributes`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L2367)
暴露的 setter 直写批表纹理，所以运行期改色/显隐不用重建几何。

## 4. Appearance：接口与三个常用实现

外观 = **shader + 渲染状态 + （可选）材质**。接口契约见
[`function Appearance`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Appearance.js#L33)
（`translucent`/`closed`/`material`/`vertexShaderSource`/`fragmentShaderSource`/`renderState`）：

| 实现 | 行 | 语义 | 着色来源 |
|---|---|---|---|
| [`MaterialAppearance`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/MaterialAppearance.js#L49) | L49 | 通用：任意 [`Material`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L273) | material 的 fabric GLSL（§5） |
| [`PerInstanceColorAppearance`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PerInstanceColorAppearance.js#L70) | L70 | 每 instance 纯色 | 批表里的 `color` 实例属性 |
| [`PolylineColorAppearance`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PolylineColorAppearance.js#L47) | L47 | 折线逐顶点色 | 顶点属性 `color` |

[`PerInstanceColorAppearance`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PerInstanceColorAppearance.js#L70)
两个开关：`flat`（不用法线、无光照，配套
[`FLAT_VERTEX_FORMAT`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PerInstanceColorAppearance.js#L261)=POSITION_ONLY，
省掉 §2 的法线计算）与 `translucent`（决定 renderState 开不开混合、是否两趟渲染）。
**Appearance 决定了它需要什么 VertexFormat**（[`VERTEX_FORMAT`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/PerInstanceColorAppearance.js#L250)=POSITION_AND_NORMAL），
GeometryVisualizer 建桶时会把「外观需要的顶点格式」反向喂给几何工厂——**外观与几何是双向耦合的**。
shader 的最终拼装在 [`createShaderProgram`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Primitive.js#L1724)：
顶点=外观模板 + 批表取样声明，片元=外观模板 + material 的 `czm_getMaterial`（下一节）。

## 5. Material 与 Fabric：JSON 描述 → GLSL

[`Material`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L273)
用 **fabric**——一个 JSON 小 DSL——描述表面外观，两种形态：

```js
// 组件式：每个分量是一句 GLSL 表达式
const m = new Cesium.Material({
  fabric: {
    type: "MyColor",                       // 注册进缓存可复用
    uniforms: { u_color: new Cesium.Color(0, 1, 0, 1) },
    components: { diffuse: "u_color.rgb", alpha: "u_color.a" },
  },
});
// 或直接给 source：一段完整 GLSL 函数
```

fabric → GLSL 的编译发生在构造时的 [`initializeMaterial`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L694)：
[`createMethodDefinition`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L854)
把 components 拼成一个 `czm_material czm_getMaterial(czm_materialInput)` 函数体（diffuse/emission 过
`czm_gammaCorrect`），或直接拼接 `source`。**嵌套材质**（fabric.materials）时每个子材质的
`czm_getMaterial` 用 [`replaceToken`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L1356)
改写成唯一名（`czm_getMaterial_0`…），父材质的表达式里引用子材质 id 即变成函数调用——这就是 Fabric 的「组合」。

内置类型注册在 [`Material._materialCache`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L1379)
（Color/Image/Checkerboard/Stripe/Water/PolylineGlow… 每个对应 `Shaders/Materials/` 下的 GLSL 片段），
取用即 [`Material.fromType`](https://github.comCpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L411)
（异步版 [`fromTypeAsync`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L450)，
纹理类材质要先等图）。运行期 [`Material.prototype.update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L531)
做 uniform 脏检测与纹理上传；[`isTranslucent`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Material.js#L501)
的判定结果影响 Primitive 的两趟渲染。生成的 shader 走 Context 的 shaderCache 缓存——与 08 §4 的 pick 派生 shader 同一套缓存机制，
**同一 fabric 只编译一次**。

## 6. GeometryVisualizer：Entity → Primitive 的桥

[03 §5](03-Entity数据体系.md) 说过 Visualizer 的差量同步；这里看几何侧怎么落桶。
[`function GeometryVisualizer`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/GeometryVisualizer.js#L40)
构造时建好一批**静态桶**：`_outlineBatches/_closedColorBatches/_closedMaterialBatches/_openColorBatches/_openMaterialBatches`
（各 × 阴影模式 × 有无 terrainOffset）+ `_groundColorBatches/_groundMaterialBatches`（贴地，按 ClassificationType）+ 一个 `_dynamicBatch`。
Entity 集合变化只记账（[`_onCollectionChanged`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/GeometryVisualizer.js#L549)），
每帧 [`update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/GeometryVisualizer.js#L252) 才把
added/removed/changed 三队列消化掉，由
[`_insertUpdaterIntoBatch`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/GeometryVisualizer.js#L451)
路由：

- **动态**（几何属性非常量，`updater.isDynamic`）→ `_dynamicBatch`：每帧重建几何，保正确、费性能；
- **静态** → 按「贴地 / 闭合体 / 开放面 × 纯色 / 任意材质 × 阴影 × 地形偏移」定位到具体桶
  （[`StaticGeometryColorBatch`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/StaticGeometryColorBatch.js#L407)
  / [`StaticGeometryPerMaterialBatch`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/StaticGeometryPerMaterialBatch.js#L392)
  / [`StaticOutlineGeometryBatch`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/StaticOutlineGeometryBatch.js#L316)）——
  **同桶 = 同外观状态 = 合进一个 Primitive = 一条 DrawCommand**，这是 Entity 数量上千仍能流畅的核心。

每个 Entity 由对应的 Updater 观察（如 [`RectangleGeometryUpdater`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/RectangleGeometryUpdater.js#L55)），
它决定 isDynamic/onTerrain/isClosed，并在几何属性变化时触发重插桶。

## 7. 贴地分类：GroundPrimitive / ClassificationPrimitive

「贴地（clamp to ground）」不是把几何压到地形上，而是**把几何当「分类器」画进地形的深度/模板**：

- [`GroundPrimitive`](https://github.comCpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GroundPrimitive.js#L114)
  把多边形/折线投影成贴地版本，内部
  [`new ClassificationPrimitive(primitiveOptions)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GroundPrimitive.js#L883)
  干活（能力探测 [`GroundPrimitive.isSupported`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GroundPrimitive.js#L360)）；
- [`ClassificationPrimitive`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationPrimitive.js#L72)
  的 [`classificationType`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationPrimitive.js#L111)
  决定分类谁，枚举在 [`ClassificationType.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationType.js)：
  [`TERRAIN`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationType.js#L13)=0（只贴地形）、
  [`CESIUM_3D_TILE`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationType.js#L20)=1（只贴模型）、
  [`BOTH`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationType.js#L27)=2（默认）；
- 命令生成 [`createCommands`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationPrimitive.js#L866)
  按 classificationType 把命令挂进对应 Pass 桶（[L940-L944](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationPrimitive.js#L940)）：
  贴地形 → [`Pass.TERRAIN_CLASSIFICATION`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Pass.js#L20)，
  贴模型 → [`Pass.CESIUM_3D_TILE_CLASSIFICATION`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Renderer/Pass.js#L24)——
  在 [05 §5](05-帧更新与渲染循环.md) 的 Pass 顺序表里，它们排在 Globe 之后、OPAQUE 之前；
- 贴地效果依赖深度测试打在地形上：`scene.globe.depthTestAgainstTerrain`（默认 false，
  [`Globe.js` L326](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Globe.js#L326)，详见 [07](07-地形系统.md)）。
  **不开它，贴地多边形会「沉」到半地下或被地形盖住**——这是新手最常见的坑（§10）。

## 9. 常见坑

- **异步创建的 Primitive 要等 ready**：`asynchronous: true`（默认）时几何在 Worker 里算，本帧拿不到 `_va`；`asynchronous: false` 会阻塞主线程，且贴地场景必须先 `Cesium.GroundPrimitive.initializeTerrainHeights()`（[ClassificationPrimitive.js L61](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ClassificationPrimitive.js#L61) 的注释）；
- **不同材质会打断合批**：§6 的 PerMaterial 桶按「材质相等」分桶，1000 个 1000 种贴图的矩形 ≈ 1000 个 Primitive——能统一纯色就统一；
- **`releaseGeometryInstances: true`（默认）后 `primitive.geometryInstances` 被清空**，想复用同一几何再建一个 Primitive 请显式传 `false` 或自己克隆；
- **顶点格式要匹配外观**：PerInstanceColorAppearance 需要法线（非 flat）——工厂忘了传对应 `vertexFormat` 会出现黑块/报错；用 `PerInstanceColorAppearance.VERTEX_FORMAT` 常量最稳；
- **贴地不生效九成是 `depthTestAgainstTerrain` 没开**（§7）；另一个隐藏代价：开了它之后 pickPosition 会拾取地形遮挡，交互逻辑可能变化；
- **PolygonGeometry 的 `perPositionHeight`**：默认所有顶点压到 `height`；开了才逐点用自身高度——建模「不等高多边形」时别搞反；
- **granularity 过细会爆顶点**：1°→1 角秒是 3600 倍密度，RectangleGeometry/PolygonGeometry 的顶点数按平方增长。

## 10. 小结与下一篇

几何侧 = **Geometry（数据）→ 工厂（顶点计算）→ GeometryPipeline（合批后处理）→ VAO/VBO → DrawCommand**；
外观侧 = **Appearance（shader 模板+状态）× Material（fabric→GLSL）**；Entity 侧由
GeometryVisualizer 的静态桶把两者粘起来；贴地则把「画几何」变成「分类地形/模型的模板通道」。
