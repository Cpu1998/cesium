# 12 · 事件与交互

> 阅读前提：读过 [01-Viewer创建与场景初始化](01-Viewer创建与场景初始化.md)（Viewer/CesiumWidget 分层）、[06 §8](06-相机系统与视角控制.md)（交互层概览）、[08-拾取系统](08-拾取系统.md)（pick pass）。
> 一句话：**鼠标/触摸事件被抽象成「屏幕空间事件」，两类默认消费者——Viewer 的选中/跟踪与相机控制器——把事件翻译成业务行为和相机操作；本篇把这条链从 DOM 事件一路讲到 flyTo。**

本文讲什么：

- 事件抽象层：[`ScreenSpaceEventHandler.js`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js)（DOM → 屏幕空间事件，含 CLICK 合成/修饰键/触摸手势）
- 事件类型枚举：[`ScreenSpaceEventType.js`](../packages/engine/Source/Core/ScreenSpaceEventType.js)、[`KeyboardEventModifier.js`](../packages/engine/Source/Core/KeyboardEventModifier.js)
- Viewer 默认交互：[`Viewer.js`](../packages/widgets/Source/Viewer/Viewer.js)（单击选中/双击跟踪）与 [`CesiumWidget.js`](../packages/engine/Source/Widget/CesiumWidget.js)（handler 创建、trackedEntity 事件）
- 相机翻译层：[`ScreenSpaceCameraController.js`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js) + [`CameraEventAggregator.js`](../packages/engine/Source/Scene/CameraEventAggregator.js)
- 事件×拾取×相机三线汇合：一条 click 的全链 ASCII 图

## 0. 全景：交互层的三个高度

```
高度 3  业务行为      Viewer 默认 handler        单击=选中实体(信息框)  双击=跟踪/缩放实体
                      (widgets 层，可 removeInputAction 覆盖)
高度 2  相机操作      ScreenSpaceCameraController 左拖=旋转  右拖=平移  滚轮=缩放  中拖/CV=倾斜
                      (engine 层，直接写 Camera)
高度 1  事件抽象      ScreenSpaceEventHandler     LEFT_DOWN/UP/CLICK/MOUSE_MOVE/WHEEL/PINCH_*…
                      (engine 层，不关心谁消费)             ↓ 唯一来源
高度 0  浏览器        canvas 上的 DOM 事件          mousedown/up/move、dblclick、wheel、touch*、pointer*
```

三个关键事实：

- **ScreenSpaceEventHandler 不认识 Scene/Camera**——它只是「DOM 事件 → 回调」的分发器，是纯 Core 层工具，[`new Cesium.ScreenSpaceEventHandler(canvas)`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L987) 在没有 Viewer 的裸 canvas 上也能用。
- **高度 2 和高度 3 互不干扰**：相机控制器不走 `setInputAction`，它自己持有一个独立的 [`CameraEventAggregator`](../packages/engine/Source/Scene/CameraEventAggregator.js#L374)（内部也是 ScreenSpaceEventHandler，见 §4）；Viewer 默认行为走 widget 的 `screenSpaceEventHandler`。所以你 `removeInputAction` 掉 LEFT_CLICK 不会影响拖拽转相机。
- **事件处理与渲染循环解耦**：鼠标回调在 DOM 事件线程时机同步执行（不在 rAF 帧内），改相机/实体后需注意 [requestRenderMode](05-帧更新与渲染循环.md) 下要手动 `scene.requestRender()`。

## 1. ScreenSpaceEventHandler：事件抽象核心

### 1.1 数据结构：一张 handlers 表

构造器（[`L987`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L987)）内部核心只有一张 `handlers` 对象，键由 [`getInputEventKey`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L25) 生成——**事件类型 × 修饰键组合**唯一确定一个回调槽位：

| API | 定义行 | 语义 |
|---|---|---|
| `setInputAction(action, type, modifier?)` | [`L1031`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1031) | 注册/覆盖一个槽位（同槽后写覆盖前写） |
| `getInputAction(type, modifier?)` | [`L1061`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1061) | 查槽位（内部派发也走它） |
| `removeInputAction(type, modifier?)` | [`L1082`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1082) | 删槽位（恢复默认行为的标准姿势） |
| `destroy()` | [`L1125`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1125) | 解绑全部 DOM 监听 |

修饰键来自 [`getModifiers`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L36)，取值是 [`KeyboardEventModifier`](../packages/engine/Source/Core/KeyboardEventModifier.js) 的三个枚举：`SHIFT`（[L16](../packages/engine/Source/Core/KeyboardEventModifier.js#L16)）/ `CTRL`（[L24](../packages/engine/Source/Core/KeyboardEventModifier.js#L24)）/ `ALT`（[L32](../packages/engine/Source/Core/KeyboardEventModifier.js#L32)）。于是「Ctrl+左键单击」和「左键单击」天然是两个独立回调——这是 Cesium 官方 Sandcastle 里 shift 拖拽画范围类示例的基础。

### 1.2 事件注册：鼠标/指针双轨 + 全局兜底

[`registerListeners`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L76) 按浏览器能力二选一：

- **支持 Pointer Events**（现代浏览器）：绑 `pointerdown/up/move`（[`handlePointerDown`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L837)/[`Up`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L861)/[`Move`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L877)）+ `pointercancel`（当作 up 处理）——鼠标/触摸/笔统一走 pointer。
- **不支持**：走鼠标三件套（[`handleMouseDown`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L209)/[`Up`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L306)/[`Move`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L355)）+ 触摸三件套（[`handleTouchStart`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L463)/[`End`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L497)/[`Move`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L703)）。

两个易忽略的细节：

1. **mouseup/mousemove 绑在 `document` 上**（`alternateElement`）——拖出 canvas 边界再松手，事件不丢。canvas 上设 `disableRootEvents` 可改回绑元素自身。
2. **触摸会触发合成鼠标事件**（移动端浏览器行为），[`canProcessMouseEvent`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L194) 用时间戳把触摸后 [`mouseEmulationIgnoreMilliseconds`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1137)（800ms）内的鼠标事件全部丢弃，防止一次点击派发两套回调。

### 1.3 CLICK 不是 DOM 事件，是合成出来的

浏览器有 `click` 事件，但 Cesium **不用它**。[`handleMouseUp`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L306) → [`cancelMouseEvent`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L259) 在派发 `*_UP` 后，用 [`checkPixelTolerance`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L201) 检查**按下起点与松开终点距离 ≤ [`_clickPixelTolerance`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1012)（默认 5px）**才补发 `*_CLICK`。原因：拖拽旋转地球时松手（mouseup）不应被解释成「点击了什么」。

双击倒是直通 DOM 的 `dblclick`（[`handleDblClick`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L396)，且只认左键）。滚轮事件 [`handleWheel`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L420) 做了**delta 归一化**：`DOM_DELTA_PIXEL` 原样取反、`LINE`×40、`PAGE`×120，统一成「类 wheelDelta」的数值（正=向上/拉近）再派发 `WHEEL`。

### 1.4 触摸手势：PINCH 三连与长按

两指触摸在 [`handleTouchStart`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L463)/[`handleTouchMove`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L703) 中被合成三个事件（`startPosition`/`endPosition` 存两指中点和距离变化）：

- `PINCH_START`：第二根手指按下
- `PINCH_MOVE`：两指距离变化（`delta` 字段=距离差，`angleAndHeight` 等辅助字段给消费者）
- `PINCH_END`：任一指抬起

单指长按则由 [`touchHoldTimer`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L646)（[`touchHoldDelayMilliseconds`](../packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1145) 默认 1500ms）计时，期间手指动了就 `clearTimeout`。

|---|---|---|---|

| `LEFT_UP`=1 | [L23](../packages/engine/Source/Core/ScreenSpaceEventType.js#L23) | `MIDDLE_UP`=11 | [L79](../packages/engine/Source/Core/ScreenSpaceEventType.js#L79) |
| `LEFT_CLICK`=2 | [L31](../packages/engine/Source/Core/ScreenSpaceEventType.js#L31) | `MIDDLE_CLICK`=12 | [L87](../packages/engine/Source/Core/ScreenSpaceEventType.js#L87) |
| `LEFT_DOUBLE_CLICK`=3 | [L39](../packages/engine/Source/Core/ScreenSpaceEventType.js#L39) | `MOUSE_MOVE`=15 | [L95](../packages/engine/Source/Core/ScreenSpaceEventType.js#L95) |
| `RIGHT_DOWN`=5 | [L47](../packages/engine/Source/Core/ScreenSpaceEventType.js#L47) | `WHEEL`=16 | [L103](../packages/engine/Source/Core/ScreenSpaceEventType.js#L103) |
| `RIGHT_UP`=6 | [L55](../packages/engine/Source/Core/ScreenSpaceEventType.js#L55) | `PINCH_START`=17 | [L111](../packages/engine/Source/Core/ScreenSpaceEventType.js#L111) |

**回调参数统一为「事件对象」**：DOWN/UP/CLICK/DBL_CLICK 传 `{position}`（Cartesian2，CSS 像素，原点左上）；MOUSE_MOVE 传 `{startPosition, endPosition}`（两帧间位移，做 hover/框选就靠它）；WHEEL 传 delta 数值；PINCH 传 `{position, distance, angle}` 系列。

## 3. Viewer 默认交互：单击选中与双击跟踪

### 3.1 handler 的归属链

CesiumWidget 构造时创建（[`L440`](../packages/engine/Source/Widget/CesiumWidget.js#L440)）：

```
viewer.screenSpaceEventHandler          // Viewer.js 属性转发
  = cesiumWidget.screenSpaceEventHandler // CesiumWidget.js getter L745
  = new ScreenSpaceEventHandler(canvas)  // L440，绑在 canvas 上
```

Viewer 构造尾部（[`L1010`](../packages/widgets/Source/Viewer/Viewer.js#L1010)/[`L1014`](../packages/widgets/Source/Viewer/Viewer.js#L1014)）注册**只有两个**默认行为：

- `LEFT_CLICK` → [`pickAndSelectObject`](../packages/widgets/Source/Viewer/Viewer.js#L1005)：`selectedEntity = pickEntity(e)`
- `LEFT_DOUBLE_CLICK` → [`pickAndTrackObject`](../packages/widgets/Source/Viewer/Viewer.js#L989)：有位置则 `trackedEntity = entity`，否则退到 [`viewer.zoomTo(entity)`](../packages/widgets/Source/Viewer/Viewer.js#L2119)；点到空白则取消跟踪

注意**没有默认的 RIGHT_CLICK 行为**（右键拖拽平移是相机控制器的，见 §4），也没有默认 WHEEL 行为（滚轮缩放同样在控制器里）。

### 3.2 pickEntity：从 picked 对象到 Entity

[`pickEntity`](../packages/widgets/Source/Viewer/Viewer.js#L119) 是「事件 → 拾取」的桥，三步：

1. [`viewer.scene.pick(position)`](../packages/engine/Source/Scene/Scene.js#L4833)（转交给 [`Picking.prototype.pick`](../packages/engine/Source/Scene/Picking.js#L419)，颜色编码拾取全链见 [08-拾取系统](08-拾取系统.md)）
2. `picked.id instanceof Entity` 直接返回（为什么 `id` 是 Entity：[03 §7](03-Entity数据体系.md)，GeometryVisualizer 把 entity 塞进 GeometryInstance.id）；3D Tiles 要素被临时包成 Entity 也能命中
3. 拾取不到则降级 `pickImageryLayerFeature`（异步 WMS GetFeatureInfo 之类）

### 3.3 selectedEntity / trackedEntity：两个事件化属性

- **selectedEntity**（setter [`L1549`](../packages/widgets/Source/Viewer/Viewer.js#L1549)）：只驱动绿框出现/消失动画，并广播 [`selectedEntityChanged`](../packages/widgets/Source/Viewer/Viewer.js#L1572)；信息框内容和绿框**位置**由 [`Viewer.prototype._onTick`](../packages/widgets/Source/Viewer/Viewer.js#L1908) 每 tick 算实体包围球刷新（世界坐标 → 屏幕坐标的变换链见 [11 §5](11-坐标变换.md)）。
- **trackedEntity**（真身在 CesiumWidget，setter [`L882`](../packages/engine/Source/Widget/CesiumWidget.js#L882)）：赋值即取消在途缩放、置 `_needTrackedEntityUpdate`，**等下一帧尾** [`updateTrackedEntity`](../packages/engine/Source/Widget/CesiumWidget.js#L1668) 拿到实体包围球后才真正 `new EntityView`（[L1717](../packages/engine/Source/Widget/CesiumWidget.js#L1717)）并**禁掉平移/倾斜**（防拖穿）；之后每 tick [`CesiumWidget._onTick`](../packages/engine/Source/Widget/CesiumWidget.js#L1201) 调 [`EntityView.update`](../packages/engine/Source/DataSources/EntityView.js#L396)（默认视角偏移 [`defaultOffset3D`](../packages/engine/Source/DataSources/EntityView.js#L385)），实现「相机钉在实体旁」。取消跟踪则解锁平移/倾斜、`camera.lookAtTransform(IDENTITY)` 复位。变化事件 [`trackedEntityChanged`](../packages/engine/Source/Widget/CesiumWidget.js#L935)，Viewer 属性转发在 [L1589](../packages/widgets/Source/Viewer/Viewer.js#L1589)。

这套「属性 setter + changed 事件」的契约与 03 篇的 Property 体系一脉相承，是 Cesium 全库通用的观察者范式。

### 3.4 覆盖/恢复默认行为

```js
// 拦截单击：先移除 Viewer 默认行为，再注册自己的
handler.removeInputAction(ScreenSpaceEventType.LEFT_CLICK);
handler.setInputAction(mine, ScreenSpaceEventType.LEFT_CLICK);
// 恢复默认：removeInputAction(mine) 后无法自动找回 Viewer 的回调，
// 只能重写一遍“pick→selectedEntity”逻辑——Viewer 把默认回调存在闭包里没有导出
```

[`Viewer.prototype.destroy`](../packages/widgets/Source/Viewer/Viewer.js#L1776)（[L1781/L1784](../packages/widgets/Source/Viewer/Viewer.js#L1781)）销毁时也正是 `removeInputAction` 这两个默认行为；handler 本体随 [`CesiumWidget.destroy`](../packages/engine/Source/Widget/CesiumWidget.js#L1081) 销毁。

## 4. ScreenSpaceCameraController：事件 → 相机操作翻译层

[06 §8](06-相机系统与视角控制.md) 给过开关速查表，本篇补齐**内部机制**。构造器（[`L35`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L35)）持有：

- [`_aggregator = new CameraEventAggregator(scene.canvas)`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L292)——事件聚合器
- 五张「操作 → 手势」映射表：[`translateEventTypes`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L157)/[`zoomEventTypes`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L168)/[`rotateEventTypes`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L183)/[`tiltEventTypes`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L200)/[`lookEventTypes`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L222)

### 4.1 CameraEventAggregator：把三个事件捏成一个 movement

[`CameraEventAggregator`](../packages/engine/Source/Scene/CameraEventAggregator.js#L374) 内部**也是**一个 ScreenSpaceEventHandler，把 DOWN/MOVE/UP 三段式收敛成语义查询接口：

| 查询 | 定义行 | 返回 |
|---|---|---|
| `isMoving(type)` | [L452](../packages/engine/Source/Scene/CameraEventAggregator.js#L452) | 该手势是否进行中 |
| `getMovement(type)` | [L470](../packages/engine/Source/Scene/CameraEventAggregator.js#L470) | `{startPosition, endPosition}` 本帧位移 |
| `getLastMovement(type)` | [L489](../packages/engine/Source/Scene/CameraEventAggregator.js#L489) | 松手前最后一段位移（惯性种子） |
| `isButtonDown(type)` / `getStartMousePosition` | [L512](../packages/engine/Source/Scene/CameraEventAggregator.js#L512) / [L530](../packages/engine/Source/Scene/CameraEventAggregator.js#L530) | 按下状态/起点 |
| `getButtonPressTime` / `getButtonReleaseTime` | [L555](../packages/engine/Source/Scene/CameraEventAggregator.js#L555) / [L573](../packages/engine/Source/Scene/CameraEventAggregator.js#L573) | 按住时长（松手超过阈值不给惯性） |

这里的手势类型是另一套枚举 [`CameraEventType`](../packages/engine/Source/Scene/CameraEventType.js)：`LEFT_DRAG`=0（[L15](../packages/engine/Source/Scene/CameraEventType.js#L15)）、`RIGHT_DRAG`=1、`MIDDLE_DRAG`=2、`WHEEL`=3、`PINCH`=4。**注意区分**：ScreenSpaceEventType 是「屏幕空间事件类型」（面向 setInputAction），CameraEventType 是「相机手势类型」（面向聚合器），前者比后者细。

### 4.2 每帧翻译：reactToInput → update2D/CV/3D

控制器每帧被 [`Scene.initializeFrame`](../packages/engine/Source/Scene/Scene.js#L4459) 驱动（调 [`controller.update`](../packages/engine/Source/Scene/Scene.js#L4495)，先于 [`camera.update`](../packages/engine/Source/Scene/Scene.js#L4500)，顺序见 06 §8）：

- [`reactToInput`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L481)：把聚合器的 movement 换算成 `_rotate`/`_zoom` 等速率量（滚轮走 [`handleZoom`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L559)，`_zoomFactor` 换算）
- [`prototype.update`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L3010)：按场景模式分派 [`update2D`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L1090)/[`updateCV`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L1785)/[`update3D`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L2873)——同一手势在三种模式下语义不同（2D 左拖=平移地图、3D 左拖=绕地球旋转、CV 左拖=平移+ctrl 倾斜），最终都落到 06 篇讲过的 Camera API（[`move`](../packages/engine/Source/Scene/Camera.js#L1777)/[`rotate`](../packages/engine/Source/Scene/Camera.js#L2028)/[`look`](../packages/engine/Source/Scene/Camera.js#L1966)/[`zoomIn`](../packages/engine/Source/Scene/Camera.js#L2255)）。
- **惯性**：松手后由 [`maintainInertia`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L379)（衰减用 [`decay`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L356) + [`activateInertia`](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L458)）继续滑行，系数 `inertiaSpin`/`inertiaTranslate`/`inertiaZoom`（[L96](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L96)/[L104](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L104)/[L112](../packages/engine/Source/Scene/ScreenSpaceCameraController.js#L112)，默认 0.9/0.9/0.8，设 0 关惯性）。
- **打断飞行**：任何拖拽/滚轮都会先 [`camera.cancelFlight`](../packages/engine/Source/Scene/Camera.js#L3335)——flyTo 是 tween 驱动的（[06 §5](06-相机系统与视角控制.md)），用户输入优先。

想换手势映射直接改表即可，例如把旋转挪到右键：`controller.rotateEventTypes = CameraEventType.RIGHT_DRAG`；`tiltEventTypes`/`lookEventTypes` 支持 `{eventType, modifier}` 组合（如 CTRL+中拖倾斜）。

## 5. 全链走读：一次双击，从 DOM 事件到相机跟随

```
用户双击一个 Billboard entity
│
│ 浏览器: dblclick (canvas)
▼
ScreenSpaceEventHandler.handleDblClick            (SSEH.js L396)
│  button=LEFT → type=LEFT_DOUBLE_CLICK, modifiers=getModifiers
│  getInputAction 查表命中
▼
Viewer.pickAndTrackObject(e)                       (Viewer.js L989)
│  entity = pickEntity(e)                          (Viewer.js L119)
│   ├─ scene.pick({position})                      (Scene.js L4833 → Picking.js L419)
│   │   ├─ pick pass 重画场景(派生命令写 pickColor)  ← 详见 08-拾取系统 §2–§4
│   │   ├─ PickFramebuffer 读像素 → 颜色
│   │   └─ Context.getObjectByPickColor 反查 PickId → {primitive, id}
│   └─ id instanceof Entity → 返回 entity          ← 详见 03-Entity数据体系 §7
│  entity.position 有值 → viewer.trackedEntity = entity   (转发到 CesiumWidget)
▼
CesiumWidget.trackedEntity setter                  (CesiumWidget.js L882)
│  cancelZoom；_needTrackedEntityUpdate = true
│  trackedEntityChanged.raiseEvent(entity)
▼ 本帧渲染完，postRender 尾
updateTrackedEntity(widget)                        (CesiumWidget.js L1668)
│  dataSourceDisplay.getBoundingSphere(entity)     (要等 Visualizer 建好图元，03 §4)
│  new EntityView(entity, scene, ellipsoid)        (L1717)
│  禁用 enableTranslate/enableTilt（3D）           ← §4 的开关在这里被程序化置 false
▼ 此后每个 tick
CesiumWidget._onTick                               (CesiumWidget.js L1201)
│  entityView.update(time)                         (EntityView.js L396)
```

单击分叉（绿框链）多一步：`pickAndSelectObject → selectedEntity setter（L1549，绿框动画+事件）→ Viewer._onTick（L1908）每 tick 算包围球刷新信息框`。若拿到的是 3D Tiles 要素（无 position Property），则走 [`viewer.zoomTo(entity)`](../packages/widgets/Source/Viewer/Viewer.js#L2119)（内部对 Primitive 用 [`camera.flyToBoundingSphere`](../packages/engine/Source/Scene/Camera.js#L3660)，实体路径则 [`flyTo`](../packages/engine/Source/Scene/Camera.js#L3425)，飞行机制见 [06 §5](06-相机系统与视角控制.md)）。

hover 之类没有默认行为的需求就自己拼：`MOUSE_MOVE` + `scene.pick(movement.endPosition)` + [`SceneTransforms.worldToWindowCoordinates`](../packages/engine/Source/Scene/SceneTransforms.js#L46)（世界→屏幕，[11 §5](11-坐标变换.md)）是 tooltip 类功能的标准三件套。需要「穿透遮挡物」用 [`scene.drillPick`](../packages/engine/Source/Scene/Scene.js#L5126)（逐层剥取，[08 §7](08-拾取系统.md)）；要精确坐标（贴地点）用 [`scene.pickPosition`](../packages/engine/Source/Scene/Scene.js#L5103)（深度复原，[08 §6](08-拾取系统.md)）。

## 7. 动手实验（Sandcastle 控制台）

```js
// ① 观察所有鼠标事件流（先做一次左键点击+拖拽+双击）
const h = viewer.screenSpaceEventHandler;
[["LEFT_DOWN",1],["LEFT_UP",1],["LEFT_CLICK",1],["LEFT_DOUBLE_CLICK",1],
 ["RIGHT_DOWN",1],["MOUSE_MOVE",1],["WHEEL",1]].forEach(([t]) => {
  h.setInputAction(e => console.log(t, JSON.stringify(e)),
    Cesium.ScreenSpaceEventType[t]);
});

// ② 证明 CLICK 是合成的：按下后拖 10px 再松手 → 无 LEFT_CLICK
//    （对比 §1.3 的 5px 容差）

// ③ 拆掉双击跟踪，换成 drillPick 打印穿透链
h.removeInputAction(Cesium.ScreenSpaceEventType.LEFT_DOUBLE_CLICK);
h.setInputAction(e => {
  const list = viewer.scene.drillPick(e.position, 5);
  console.log(list.map(p => p.id?.name ?? p.primitive?.constructor.name));
}, Cesium.ScreenSpaceEventType.LEFT_DOUBLE_CLICK);

// ④ 体验 trackedEntity 的副作用：跟踪后拖拽被禁
viewer.trackedEntity = viewer.entities.values[0];
console.log(viewer.scene.screenSpaceCameraController.enableTilt); // false
viewer.trackedEntity = undefined;                                  // 恢复
```

## 8. 常见坑

- **`setInputAction` 覆盖而非叠加**：同一 (type, modifier) 槽位后写覆盖前写；Viewer 默认行为与你注册的同槽时，是「你覆盖默认」，不是「两个都触发」。
- **removeInputAction 找不回默认**：默认回调在 Viewer 闭包里，移除后想恢复只能自己重写「pick → selectedEntity」逻辑（见 §3.4）。
- **拖拽后的 mouseup 不产生 CLICK**（5px 容差），但**产生 UP**——在 UP 上写业务前先想清楚要不要过滤拖拽。
- **`e.position` 是 CSS 像素不是设备像素**：与 `scene.pick`/`SceneTransforms` 同一坐标系，直接传即可；别自己乘 devicePixelRatio。
- **拖拽打断 flyTo 是设计行为**：想在飞行中锁输入，用 `scene.screenSpaceCameraController.enableInputs = false` 而不是反复 restart 飞行。
- ** trackedEntity 后平移/倾斜失效不是 bug**：setter 主动禁的（§3.3），取消跟踪才恢复。
- **触屏上 `MOUSE_MOVE` 不可靠**：走 pointer 路径的设备 OK，老触摸路径只有 touchstart/move/end 合成；跨设备交互优先用 CLICK/DBL_CLICK + PINCH_* 这类稳定语义。

## 9. 小结与下一篇

- ScreenSpaceEventHandler = **类型×修饰键的回调表** + CLICK 合成（5px 容差）+ 触摸/指针归一；对 Scene/Camera 零依赖。
- Viewer 默认只占 LEFT_CLICK/LEFT_DOUBLE_CLICK 两个槽位；selectedEntity（绿框/信息框）与 trackedEntity（EntityView 跟随）是两套独立的事件化属性。
- 相机交互不走 setInputAction，而是 CameraEventAggregator + 五张映射表 + 每帧 update 分模式翻译；惯性在松手后由 maintainInertia 接管。
- 事件回调在帧外执行：改状态后 requestRenderMode 下要手动 requestRender。
