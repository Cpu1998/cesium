# 12 · 事件与交互

> 阅读前提：读过 [01-Viewer创建与场景初始化.md](01-Viewer创建与场景初始化.md)（Viewer/CesiumWidget 分层）与 [08-拾取系统.md](08-拾取系统.md)（pick 的颜色编码原理）——本文讲**事件怎么进来、怎么变成选中/跟踪/相机操作**。
> 一句话：Cesium 把 DOM 事件统一翻译成「屏幕空间事件」（带修饰键），Viewer 在其上装了一层默认交互（点选/双击跟踪），相机则由一个专职翻译层把拖拽/滚轮/捏合变成矩阵运算。

本文的主战场文件：

- [`Core/ScreenSpaceEventHandler.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js) —— 事件抽象核心：DOM → 屏幕空间事件
- [`Core/ScreenSpaceEventType.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventType.js) + [`Core/KeyboardEventModifier.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/KeyboardEventModifier.js) —— 事件类型与修饰键枚举

- [`Scene/ScreenSpaceCameraController.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ScreenSpaceCameraController.js) + [`Scene/CameraEventAggregator.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventAggregator.js) —— 事件 → 相机操作翻译层（06 §8 的展开版）

## 0. 全景：一次点击的完整旅程

```
 手指/鼠标                    Core 层                          widgets 层                     每帧循环
┌──────────┐   ┌────────────────────────────┐   ┌───────────────────────────┐   ┌─────────────────────┐
│ mousedown │──▶│ ScreenSpaceEventHandler    │   │ Viewer 默认 setInputAction│   │ clock.onTick        │
│ mouseup   │   │  DOWN→UP→CLICK(≤5px 视为  │──▶│  LEFT_CLICK:  pickEntity  │   │  _onTick: 查包围球  │
│ dblclick  │   │  没拖动)→派发回调          │   │   → scene.pick → Entity   │──▶│  → 绿框定位(世界→   │
└──────────┘   └────────────────────────────┘   │  LEFT_DOUBLE_CLICK: track │   │  窗口坐标)/InfoBox  │
      触摸等价：单指=左键，长按 1.5s=右键，      │   → trackedEntity=Entity │   │  → EntityView 跟踪  │
      双指=PINCH（缩放/倾斜）                   └───────────────────────────┘   └─────────────────────┘
                                                      │ 点击没拾取到实体？
                                                      ▼
                                              CameraEventAggregator 聚合拖拽/滚轮/捏合
                                                      ▼
                                        ScreenSpaceCameraController.update（每帧）
                                                      ▼
                                        rotate3D/zoom3D/tilt3D → camera 矩阵变更
```

三条铁律先立起来：

1. **事件回调不渲染**：回调里只改状态（选中实体/改 camera），真正画到屏幕要等下一帧（[05 §1](05-帧更新与渲染循环.md) 的三阶段）。
2. **坐标永远是屏幕像素**：回调参数里的 `position` 是 `Cartesian2`（左下原点），要命中场景对象必须走 `scene.pick`（08）或 `scene.pickPosition`。
3. **一套事件、两类消费者**：业务代码用 `ScreenSpaceEventHandler`（自由回调），相机操作被 `ScreenSpaceCameraController` 内置消费（06 §8）。

## 1. ScreenSpaceEventHandler：DOM 事件的统一收发室

[`function ScreenSpaceEventHandler`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L987) 构造时就把监听器挂到 canvas 上（[`registerListeners` L76](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L76)）：

- 支持 Pointer Events 的浏览器走 `pointerdown/up/move/cancel`（分派给 [`handlePointerDown` L837](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L837) 起），否则退回 `mousedown/mousemove` + `touchstart/touchmove` 组合。
- `mouseup/mousemove/touchend` 注册在 **document** 而非 canvas 上——鼠标拖出画布再松开也要收尾。
- 滚轮事件按能力探测：标准 `wheel` → 老式 `mousewheel` → `DOMMouseScroll`（L163–L176）。
- 所有监听都 `{ capture: false, passive: false }`（[`registerListener` L61](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L61)）——`passive: false` 是能 `preventDefault()` 拦掉浏览器滚屏/双击缩放的前提。

**注册表是三件套**（回调全部存进 `_inputEvents` 字典）：

| API | 定义行 | 说明 |
|---|---|---|
| [`setInputAction`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1031) | L1031 | 注册回调；同 type+modifier 再注册会**直接覆盖** |
| [`getInputAction`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1061) | L1061 | 查回调（内部派发也用它） |
| [`removeInputAction`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1082) | L1082 | 注销；不传 modifiers 时删的是**无修饰键**槽位 |
| [`destroy`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1125) | L1125 | `unregisterListeners` 卸掉全部 DOM 监听（L179） |

字典键由 [`getInputEventKey` L25](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L25) 生成：无修饰键是 `"15"`，Shift+Ctrl 是 `"15+0+1"`（排序后拼接）——所以**同一个 LEFT_CLICK，裸按和 Ctrl 按下是两个独立槽位**，互不覆盖。

修饰键识别在 [`getModifiers` L36](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L36)：读 DOM 事件的 `shiftKey/ctrlKey/altKey` 拼成数组，枚举值来自 [`KeyboardEventModifier.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/KeyboardEventModifier.js)（`SHIFT: 0` [L16](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/KeyboardEventModifier.js#L16)、`CTRL: 1` [L24](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/KeyboardEventModifier.js#L24)、`ALT: 2` [L32](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/KeyboardEventModifier.js#L32)）。

## 2. 事件类型全集：15 种屏幕空间事件

[`ScreenSpaceEventType.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventType.js) 的枚举按「键位 × 生命周期」展开：

| 生命周期 | LEFT | MIDDLE | RIGHT |
|---|---|---|---|
| DOWN | [L15](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventType.js#L15) | L71 | L47 |
| UP | L23 | L79 | L55 |
| CLICK | [L31](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventType.js#L31) | L87 | [L63](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventType.js#L63) |
| 其他 | LEFT_DOUBLE_CLICK L39 | MOUSE_MOVE L95 | WHEEL L103 |

触摸系只有三种：`PINCH_START/END/MOVE`（[L111/L119/L127](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventType.js#L111-L127)）。

**CLICK 不是 DOM 事件，是合成的**：[`handleMouseUp` L306](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L306) 逐键调 [`cancelMouseEvent` L259](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L259)：先发 `*_UP`，再比较按下起点与松开点距离，不超过 [`_clickPixelTolerance` L1012](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1012)（**5px**，构造时写死）才补发 `*_CLICK`——按住拖了半屏松手不算点击。双击则直接吃 DOM `dblclick`（[`handleDblClick` L396](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L396)）。

**触摸的三条翻译规则**（全部在 [`fireTouchEvents` L542](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L542) 里）：

1. **单指 = 左键**：触点数变 1 时置 `_buttonDown[LEFT]=true` 并发 `LEFT_DOWN`（L622 起）；松开发 `LEFT_UP`，位移达标补 `LEFT_CLICK`。
2. **长按 1.5s = 右键**：单指落下即起 `setTimeout`（L646），到点 [`touchHoldDelayMilliseconds` L1145](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1145)（1500ms）且没挪出 25px（`_holdPixelTolerance` L1013）就发 `RIGHT_CLICK`——移动端长按弹菜单的由来。
3. **双指 = PINCH**：触点数变 2 发 `PINCH_START`，移动期间 [`handleTouchMove` L703](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L703) 持续发 `PINCH_MOVE`（payload 带两指距离 `distance` 及其变化 `delta`，还有角度变化 `angleAndHeight`），归一发 `PINCH_END`。

防抖动：碰过触摸后 800ms 内忽略一切鼠标事件（[`canProcessMouseEvent` L194](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L194) + [`mouseEmulationIgnoreMilliseconds` L1137](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L1137)）——浏览器会跟在 touch 后补发合成鼠标事件，不去重就会「点一次选中两次」。

## 3. 事件载荷速查表

不同事件类型的回调参数形状（复用对象，**勿存引用**——下次派发会被覆写）：

| 事件 | 载荷字段 | 用途 |
|---|---|---|
| DOWN/UP/CLICK/DOUBLE_CLICK | `position: Cartesian2` | 定位单点（拾取入口） |
| MOUSE_MOVE | `startPosition` + `endPosition` | 拖拽/悬停检测 |
| WHEEL | `delta: number` | 缩放强度（[handleWheel L420](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L420) 把 `wheelDelta`/`DOMMouseScroll.detail` 归整成统一符号的像素数） |
| PINCH_START/END | `position1/position2: Cartesian2` | 两指落点/离点 |
| PINCH_MOVE | `distance` + `delta`（像素）、`angleAndHeight: Cartesian2` | 二指距离及其变化 → 缩放；角度/高度变化 → 旋转/倾斜 |

这些形状即 JSDoc 里的 `PositionedEventCallback / MotionEventCallback / WheelEventCallback / TwoPointEventCallback / TwoPointMotionEventCallback` 五族（[L972 起](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/ScreenSpaceEventHandler.js#L972)）。

## 4. Viewer 的默认交互层

CesiumWidget 构造时自建唯一的 canvas 级 handler：[`new ScreenSpaceEventHandler(canvas)`（CesiumWidget.js L440）](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L440)，经 [`screenSpaceEventHandler` 属性](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L745) 暴露。相机控制器与 Viewer 默认行为都**共用这一个实例**——谁后 `setInputAction` 谁说了算。

Viewer 在其上装了两个默认回调（[Viewer.js L1008 起](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1008)）：

| 默认手势 | 注册行 | 回调 | 效果 |
|---|---|---|---|
| LEFT_CLICK | [L1010](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1010) | `pickAndSelectObject`（L1006） | `selectedEntity = pickEntity(...)` |
| LEFT_DOUBLE_CLICK | [L1014](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1014) | `pickAndTrackObject`（[L988](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L988)） | 有位置则 `trackedEntity = entity`，否则 `zoomTo(entity)`；点到空白则解除跟踪 |

[`pickEntity` L119](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L119) 是「拾取结果 → Entity」的归一器，三层兜底：

1. [`viewer.scene.pick(e.position)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Picking.js#L419) 拿到 pick 结果后取 `picked.id ?? picked.primitive.id`，`instanceof Entity` 就直接返回——**`primitive.id = entity` 是 Entity 体系与拾取体系唯一的接缝**（[08 §7](08-拾取系统.md)、[03 §Visualizer](03-Entity数据体系.md) 在创建图元时写入）。
2. 拾取到 `Cesium3DTileFeature/Cesium3DTileVectorFeature` 就**现场造一个临时 Entity**（name/description 从 feature 属性提取）——InfoBox 因此能显示 3D Tiles 属性。
3. 都不是则异步问影像层要素（[`pickImageryLayerFeature` L183](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L183)，先放「Loading...」Entity，Promise 回来替换）。

[`Viewer.prototype.destroy` L1776](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1776) 收尾时先 [`removeInputAction`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1781) 摘掉这两个回调再销毁 widget——handler 归 CesiumWidget 所有，Viewer 只借不改生命周期。

## 5. selectedEntity / trackedEntity：两个状态两个事件

选中态归 Viewer，跟踪态归 CesiumWidget，各配一个广播事件：

**选中（绿框 + InfoBox）**：[`Viewer.selectedEntity` setter（L1553 起）](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1553) 只做两件事——驱动 SelectionIndicator 的出现/消失动画（部件创建见 [L588](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L588)），并 `raiseEvent` [`selectedEntityChanged` L1578](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1578)。绿框**跟随动画**不在事件里做，而在 [`_onTick` L1908](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1908)（挂在 `clock.onTick` 上，订阅登记进 [`_eventHelper` L581](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L581)）：每个 tick 算选中实体的包围球 → 喂给绿框 ViewModel 和 InfoBox → 绿框内部再用世界→窗口坐标换算（[11 §6](11-坐标变换.md)）钉在实体头顶。

**跟踪（相机锁定实体）**：[`CesiumWidget.trackedEntity` setter（L882 起）](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L882) 的三步：

1. `cancelZoom` 掐掉在途的 zoomTo 动画；
2. 新目标有 position 则只置 `_needTrackedEntityUpdate = true`（**等包围球就绪再真正启动**，帧尾由 [`updateTrackedEntity` L1666](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L1666) 建 [`EntityView`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/EntityView.js#L324) 并**禁掉平移/倾斜**防穿模；解除跟踪时反向解锁 + `camera.lookAtTransform(Matrix4.IDENTITY)` 复位参考系）；
3. 广播 [`trackedEntityChanged` L935](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L935)（Viewer 侧同名属性 [L1589](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L1589) 只是转发）。

之后每个渲染帧 `_onTick`（[L1201](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L1201)）都会调 [`EntityView.update` L396](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/EntityView.js#L396)：用实体当前 position 换算 ENU 参考系，按固定偏移（[`defaultOffset3D` L385](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/EntityView.js#L385)，默认 `(-14000, 3500, 3500)`）`lookAtTransform`——本质是「连续 lookAt」，与 [06 §5](06-相机系统与视角控制.md) 的「飞行=连续 setView」同构。

**事件基件**：引擎不直接用 DOM 事件语义，自备 [`Event.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Event.js)——[`addEventListener` L71](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Event.js#L71) 返回**注销函数**（闭包按 listener+scope 索引）、[`removeEventListener` L113](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Event.js#L113)、[`raiseEvent` L168](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/Event.js#L168) 逐个调用。`clock.onTick`、`Entity.definitionChanged`（[Entity.js L145](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/DataSources/Entity.js#L145)，见 [03 §definitionChanged](03-Entity数据体系.md)）、`scene.postUpdate` 全是它；widgets 侧大量订阅统一登记进 [`EventHelper`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EventHelper.js)，destroy 时一把 `removeAll` 防泄漏。

## 6. 相机翻译层：从事件到矩阵

[06 §8](06-相机系统与视角控制.md) 已给过结论，这里拆开看两层结构：

**第一层 [`CameraEventAggregator`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventAggregator.js#L374)（聚合器）**：自己另开一个 `ScreenSpaceEventHandler`（不与 Viewer 共用），把原子事件聚合成「语义手势」——按下→拖动 = 某个 `CameraEventType`（[`LEFT_DRAG` L15 / `RIGHT_DRAG` L23 / `MIDDLE_DRAG` L31 / `WHEEL` L39 / `PINCH` L47](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventType.js#L15)）的 movement。查询接口：[`isMoving` L452](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventAggregator.js#L452)、[`getMovement` L470](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventAggregator.js#L470)（startPosition→endPosition）、[`getLastMovement` L489](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventAggregator.js#L489)、[`getStartMousePosition` L530](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/CameraEventAggregator.js#L530)。

## 7. 一条 LEFT_CLICK 的逐步时序（带行号）

```
浏览器事件队列
 └─ mousedown(canvas) ─▶ getPosition L11（clientXY−rect，转左下原点 Cartesian2）
 │                      getModifiers L36 → handleMouseDown L209：_buttonDown[LEFT]=true，
 │                      派发 LEFT_DOWN（若有注册）+ preventDefault
 └─ mouseup(document) ─▶ cancelMouseEvent L259：派发 LEFT_UP；起点/终点 ≤5px → 合成 LEFT_CLICK
      │
      ▼ Viewer 默认槽位（Viewer.js L1010 注册的 pickAndSelectObject L1006）
 pickEntity L119 ─▶ scene.pick L419（Picking.js）
      │              └─ 08 §2 全流程：pick pass 重画场景 → readPixel → PickId 反查
      ▼
 picked.id instanceof Entity？
      ├─ 是 ─▶ Viewer.selectedEntity setter L1553：绿框动画 + selectedEntityChanged L1578
      │         └─ 下一帧起 _onTick L1908 每 tick：getBoundingSphere → 绿框/InfoBox 刷新
      ├─ 3DTileFeature ─▶ 临时 Entity（name/description 从 feature 取）→ 同上
      └─ 否 ─▶ pickImageryLayerFeature L183 异步兜底（Loading... Entity 占位）
                                   本帧末
              scene.requestRender（Scene.js L4795）让上面所有状态变更真正上屏（05 §4）
```

双击则走 `dblclick` → `pickAndTrackObject` → 有 position 走 §4 的 trackedEntity 三步；没有 position 退化 [`zoomTo` L2119](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L2119)（内部即 [CesiumWidget.zoomTo L1352](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Widget/CesiumWidget.js#L1352) → `zoomToOrFly` L1388 → boundingSphere 就绪后起飞，[06 §5](06-相机系统与视角控制.md)）。

## 8. 动手实验（Sandcastle 控制台可直接粘）

```js
const handler = new Cesium.ScreenSpaceEventHandler(viewer.canvas);

// 1. Ctrl+左键单独一个槽位，不影响裸左键
handler.setInputAction(
  (click) => console.log("ctrl+click", click.position),
  Cesium.ScreenSpaceEventType.LEFT_CLICK,
  Cesium.KeyboardEventModifier.CTRL,
);

// 2. 拖拽测量：MOVE 的 payload 是 {startPosition, endPosition}
handler.setInputAction(
  (movement) => console.log(movement.startPosition, movement.endPosition),
  Cesium.ScreenSpaceEventType.MOUSE_MOVE,
);

// 3. 剥夺 Viewer 默认点选（同槽位直接覆盖）：再点不会出现绿框
handler.setInputAction(
  (click) => {
    const picked = viewer.scene.pick(click.position);
    viewer.selectedEntity = undefined; // 手动接管选中态
    if (picked?.id instanceof Cesium.Entity) viewer.selectedEntity = picked.id;
  },
  Cesium.ScreenSpaceEventType.LEFT_CLICK,
);

// 4. 长按/惯性等参数是静态量，改全局
Cesium.ScreenSpaceEventHandler.touchHoldDelayMilliseconds = 3000; // 长按判定 1.5s→3s
viewer.scene.screenSpaceCameraController.inertiaSpin = 0; // 关掉旋转惯性

// 5. 恢复默认：removeInputAction 只删对应槽位
handler.removeInputAction(Cesium.ScreenSpaceEventType.LEFT_CLICK);
handler.destroy(); // 自建 handler 用完必销毁，防监听堆积
```

## 9. 常见坑

- **`setInputAction` 是覆盖不是叠加**：同一 type+modifier 二次注册会静默顶掉前一个（含 Viewer 默认行为）——想要叠加语义得自己保存旧回调手工转发。
- **修饰键是独立命名空间**：注册了 `LEFT_CLICK + SHIFT` 的回调，裸点击不会触发；反之亦然。两者共存时按下的修饰键集合精确匹配到槽位。
- **回调里拿到的坐标不能直接用**：`pickPosition`/`pickEllipsoid` 才能把屏幕点换算成世界坐标（08）；直接把像素当米是新手重灾区。
- **requestRenderMode 下事件本身会触发重绘**（Scene 在交互时自动 [`requestRender` L4795](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Scene.js#L4795)），但在事件回调里改 Entity 属性后想立刻看到，仍要理解「这一帧还没画」——状态变更统一下一帧生效（05 §4）。
- **双击的 DOM 语义**：`dblclick` 之前必然先来两次完整的 down/up/click——同时监听 CLICK 和 DOUBLE_CLICK 会收到「click, click, doubleclick」序列，需要自己做去抖。
- **触屏长按出菜单**：Cesium 用 `preventDefault()` 拦截了默认长按菜单（L672），若你在 canvas 外层 DOM 上加自己的监听，注意别与 `passive: false` 的假设冲突。
- **自建 handler 要接管就必须自己接手默认行为**：置空 `viewer.cesiumWidget.screenSpaceEventHandler` 上的 LEFT_CLICK 后，点选、双击跟踪、绿框、InfoBox 都会失效（它们全靠那两个默认回调驱动）；不想要交互可以直接 `new Cesium.Viewer(container, { ... })` 后重用 `viewer.screenSpaceEventHandler`，而不是另开一个（两个 handler 各自 preventDefault 会互相打架）。
- **handler 生命周期归属**：`viewer.screenSpaceEventHandler` 归 CesiumWidget 所有，销毁 Viewer 时随 widget 一起 destroy；自己 `new` 的 handler（如 CameraEventAggregator 内部那个）必须自己 destroy，否则 canvas 上的 DOM 监听永不释放。
