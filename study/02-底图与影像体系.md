## 1. 概念模型：四个角色各管一件事

初读源码最容易把「底图」当做一个东西，实际上它被拆成四个角色：

```
Provider（数据源）          Layer（图层）           Collection（集合）         Globe+四叉树（画布）
「瓦片从哪个服务器来」  →   「这层皮怎么渲染」  →    「多层按什么顺序叠」  →    「皮贴在哪些三角形上」
UrlTemplateImageryProvider  ImageryLayer            ImageryLayerCollection     GlobeSurfaceTileProvider
BingMaps / WMS / ...        alpha/gamma/调色/show    add/remove/raise           GlobeSurfaceTile(imagery[])
                            + 请求/纹理生命周期      + 拾取反查                  QuadtreePrimitive(调度)
```

- **ImageryProvider**：只回答「第 z 层第 x 行 y 列的图，URL 是什么、怎么拉」。接口见
  [`ImageryProvider.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryProvider.js)（[`requestImage`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryProvider.js#L196)/[`pickFeatures`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryProvider.js#L218)/[`tilingScheme`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryProvider.js#L110)/`maximumLevel`…），纯数据，不碰渲染。
- **ImageryLayer**：包住一个 provider，加上渲染参数（`show`/`alpha`/`gamma`/`brightness`…），
  并管理这一层的影像瓦片缓存、请求、纹理上传、重投影（文件头注释里有主链路）。
  一个 provider 可以被两个 Layer 各包一次（两层同源不同调色完全合法）。
- **ImageryLayerCollection**：`scene.imageryLayers` 就是它。内部就是 `_layers` 数组，
  **下标即渲染顺序：0 = 最底层（先画、被压住），length-1 = 最上层**。增删/调序会抛
  `layerAdded/layerRemoved/layerMoved/layerShownOrHidden` 四个事件（见 [`ImageryLayerCollection.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L31) [构造函数](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L31)）。
- **Globe + QuadtreePrimitive**：地球表面的地形三角形由四叉树瓦片提供（[`Globe.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Globe.js#L51) [构造函数](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Globe.js#L51)里
  [`QuadtreePrimitive({tileProvider: new GlobeSurfaceTileProvider(...)})`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/QuadtreePrimitive.js#L50) 的组装现场）。
  影像纹理最终贴在这些地形瓦片的 `data.imagery[]`（[`GlobeSurfaceTile`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTile.js#L57)）上。

> **为什么这样拆？** 「换数据源」与「调渲染效果」与「控制层叠」是三个正交需求。
> Viewer 的 `options.baseLayer` 只是「创建时往 Collection 里 add 第一个 Layer」的语法糖（见 §7）。

### 「基底层」的特殊地位

[`ImageryLayerCollection._update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L816) 会把**最底部的可见层**标记为 `_isBaseLayer`（[`ImageryLayer.isBaseLayer()`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L629)）。
基底层享有特权：影像没覆盖到的地方，会把瓦片边缘像素**拉伸铺满**（见
  [`ImageryLayer._createTileImagerySkeletons`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L704) 中「no overlap」分支），保证地球永远不露黑底。
非基底层不覆盖就透明。这就是为什么「第一层必须全球覆盖」是个实践铁律——它会被拉伸兜底。

## 2. 瓦片金字塔与 tilingScheme：{z}/{x}/{y} 的坐标系

### 两种常用 tilingScheme

| | [`WebMercatorTilingScheme`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/WebMercatorTilingScheme.js#L27) | [`GeographicTilingScheme`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/GeographicTilingScheme.js#L23) |
|---|---|---|
| 投影 | Web 墨卡托（EPSG:3857） | 等距圆柱（EPSG:4326） |
| 第 0 层瓦片数 | 1×1 | **2×1**（经度 360° 拆两块） |
| 纬度范围 | ±85.0511°（墨卡托极限） | ±90° |
| 单瓦片尺寸 | 默认 256×256（`tileWidth/tileHeight` 可改 512） | 同左 |
| 每升一层 | 行列数 ×2，即 4 叉细分 | 同左 |
| 典型服务 | 绝大多数 XYZ 瓦片 / Bing / 天地图墨卡托 | GeoServer WMS-C / 部分国土源 |

- 层级 `z` 每加 1，瓦片边长减半：第 `z` 层 WebMercator 有 `2^z × 2^z` 块（[`getNumberOfXTilesAtLevel`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/WebMercatorTilingScheme.js#L130)）。
- `x` 从经度 -180° 向东递增；`y` 从**北**向南递增（TDT/OSM 习惯）。部分服务编号方向相反，
  [`UrlTemplateImageryProvider`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js) 提供 `{reverseX}/{reverseY}/{reverseZ}` 标签换算（[`reverseXTag`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L730) 等函数）。
- **quadkey**（四叉树键）是 XYZ 的另一种编码：把 x/y 的二进制位交叉拼接成四进制字符串，
  多见于 Bing Maps（[`BingMapsImageryProvider`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/BingMapsImageryProvider.js) 内部用 [`quadKeyToTileXY`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/BingMapsImageryProvider.js#L651) 换算）。XYZ 与 quadkey 一一对应，
  例：z=3, x=3, y=5 → quadkey "213"。

### UrlTemplate 的模板标签速查

`UrlTemplateImageryProvider` 用 `https://host/{z}/{x}/{y}.png` 这类模板描述任意 XYZ 服务，
展开逻辑在 [`buildImageResource`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L631)（正则抳 `{tag}` → 查 [`tags` 注册表](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L31)逐个求值）：

| 标签 | 含义 | 备注 |
|---|---|---|
| `{z}` `{x}` `{y}` | 层/列/行 | 最常用组合 |
| `{reverseX}` `{reverseY}` `{reverseZ}` | 反向编号 | 国产瓦片服务常见 |
| `{s}` | 子域名轮询 | 配 `subdomains: "123"`，按 (x+y+z) 取模，绕开同域并发限制 |
| `{westDegrees}` 等 4 个 | 瓦片西南东北经纬度 | WMS 风格 BBOX 需要 |
| `{westProjected}` 等 4 个 | 投影坐标版 | 墨卡托米制坐标 |
| `{width}` `{height}` | 瓦片分辨率 | 256/512 混布服务 |
| `{i}` `{j}` | 瓦片内像素坐标 | 仅 `pickFeaturesUrl` 用 |

未识别的标签原样保留，方便路径里嵌自定义段。`urlSchemeZeroPadding` 可让 `{x}` 补零（[`padWithZerosIfNecessary`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L703)）。

> **重要差异**：地形四叉树永远用 Geographic（`Globe` 构造时 [`EllipsoidTerrainProvider`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/EllipsoidTerrainProvider.js#L26) 的 tilingScheme），
> 而影像服务多为 WebMercator——两者**不是同一棵树**。这就是 §3 里「瓦片化」和「重投影」存在的根本原因。

## 3. 一张 XYZ 瓦片的完整生命周期

场景：用户缩放地图，视野进入杭州，需要 z=11 的某块瓦片。以下按时间顺序，全部可在源码中对照
（每步都插有 `【导读】` 注释）。

```
视野变化
  │
  ├─① QuadtreePrimitive.selectTilesForRendering   遍历 levelZeroTiles→visitIfVisible→visitTile
  │    screenSpaceError 判定「这格还不够细」→ 四个子瓦片进渲染名单，当前瓦片需加载
  │
  ├─② 三级加载队列                                  queueTileLoad → High/Medium/Low
  │    processTileLoadQueue 时间片轮转（每帧只花固定毫秒数，防卡帧）
  │    ↓ tileProvider.loadTile（GlobeSurfaceTileProvider.js）
  │
  ├─③ GlobeSurfaceTile.processStateMachine          先地形后影像（terrainOnly 策略）
  │    ├─ 地形：requestTileGeometry→transform→createResources（骨骼就绪）
  │    └─ prepareNewTile→layer._createTileImagerySkeletons  ★瓦片化入口
  │         · 求地形瓦片 ∩ 影像 coverage 矩形（无交集：基底层建拉伸骨架，否则跳过）
  │         · getLevelWithMaximumTexelSpacing 按地形几何误差反推影像层级 z'
  │         · 夹到 [minimumLevel, maximumLevel]
  │         · 双重循环扫过 z' 层所有覆盖瓦片 → getImageryFromCache 取/建 Imagery（自动链 parent）
  │         · 每块算 UV 百分比矩形 → 包成 TileImagery 存入 GlobeSurfaceTile.imagery[]
  │
  ├─④ 请求与状态机（Imagery.processStateMachine，每帧推一步）
  │    UNLOADED ──_requestImagery──▶ RECEIVED ──_createTexture──▶ TEXTURE_LOADED
  │        │                           │                              │
  │        │ Request(throttleByServer, │ discardPolicy 判空→INVALID     └─_reprojectTexture──▶ READY
  │        │ type=IMAGERY 进调度器)    │                                  (仅 Geographic 贴图需要)
  │        └ 立刻回退：TileImagery.processStateMachine 沿 parent 链找
  │          最近 READY 祖先当 readyImagery（父图替代，先糊一张低清的）
  │
  ├─⑤ 失败与重试
  │    · 请求被限流 → Request 保持未完成，下帧重试（loadImage 返回 undefined 的语义）
  │    · 瓦片 404/超时 → TileProviderError 事件（retry=true 可重发）；多次失败标 FAILED，
  │      继续用祖先图；若祖先也从未加载，TileImagery 会主动「推一把」最近的未加载祖先
  │      （有些祖先瓦片不直接挂在地形瓦片上，没人推就永远不加载）
  │    · 地形数据不存在 → FAILED → upsample 从父瓦片上采样补块
  │
  ├─⑥ 重投影（WebMercator→Geographic）
  │    墨卡托纹理的 v 坐标与纬度非线性，极地/2D 模式必须按地理坐标采样：
  │    ImageryLayer._reprojectTexture 排一个 ComputeCommand（GPU 上 2×64 网格重采样，
  │    reprojectToGeographic），由 collection.queueReprojectionCommands 每帧统一执行。
  │    双纹理并存：textureWebMercator（原版）/ texture（重投影版），按需生成。
  │
  ├─⑦ 上屏（showTileThisFrame → addDrawCommandsForTile）
  │    · 数就绪纹理数 → 按「纹理数」分桶（=着色器里 dayTexture 数组长度，桶不同 shader 变体不同）
  │    · 每层纹理装进 dayTextures[i] + UV 平移缩放 + alpha/调色 uniform（详见 §4）
  │    · 纹理数超 GPU 纹理单元上限时一个瓦片画多遍：第一遍不透明，后续遍 alpha 混合
  │    · GlobeFS 采样混合 → 像素上屏
  │
  └─⑧ 淘汰：TileReplacementQueue.trimTiles（tileCacheSize 上限）+ Imagery 引用计数归零才真释放
```

### 关键机制单独说

**先地形后影像（terrainOnly）**：[`GlobeSurfaceTileProvider.loadTile`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L694) 里，如果瓦片包围盒还是
「借来的」（boundingVolumeSourceTile ≠ 自己），说明可见性没把握，先只拉地形；地形到了、
包围盒精确了、瓦片还可见，就**立刻**再推一次带影像的状态机，不等下一帧。

**父图替代（readyImagery vs loadingImagery）**：[`TileImagery`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/TileImagery.js#L21) 维护两个引用。
`loadingImagery` 是正在加载的目标瓦片；加载完转正前，先把 parent 链上最近的 READY 祖先设为
`readyImagery` 糊上屏（配 [`_calculateTextureTranslationAndScale`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L1090) 的 UV 缩放，父图的一小格
拉伸盖满本地形瓦片）。这就是缩放时「先模糊后清晰」的原理。

**瓦片共享与缓存**：多个地形瓦片可覆盖同一块影像瓦片（层级错位时尤其常见），
[`ImageryLayer.getImageryFromCache`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L1487) 按 `[x,y,level]` 复用同一个 [`Imagery`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/Imagery.js#L17)，靠 `referenceCount`
管理生命周期；[`_onLayerAdded`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1251) 里清空缓存是为了换 provider 后不串图。

**中途加层的体验**：[`GlobeSurfaceTileProvider._onLayerAdded`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1251) 给所有已加载瓦片重建骨架时，
会把瓦片 `renderable` 置 false（正在渲染的除外）——所以运行时 `imageryLayers.add(...)` 不会白屏，
只是局部先糊父图再变清晰。

## 4. 多层叠加：顺序、透明度与调色

### 顺序

- Collection 数组序 = 绘制序：**后画的盖先画的**。[`add(layer)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L101) 追加到最上层；
  [`raise/lower`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L306)（一层）、[`raiseToTop`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L332)/`lowerToBottom`（到顶/到底）、`add(layer, index)`（插队）。
- 层序变化 → `layerMoved` 事件 → [`GlobeSurfaceTileProvider.initialize`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L412) 把每个瓦片的
  `imagery[]` 按 `_layerIndex` 重排（[`sortTileImageryByLayerIndex`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1438)），draw command 顺序跟着变。

### 每层参数（ImageryLayer 构造 options / 属性）

| 参数 | 语义 | 上屏位置 |
|---|---|---|
| `show` | 整层开关（false 不建骨架、不占纹理） | [`processImagery`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTile.js#L347) 跳过 |
| `alpha` | 整层不透明度 0~1 | dayTextureAlpha[i] uniform |
| `nightAlpha` / `dayAlpha` | 开 `globe.enableLighting` 后夜/昼两侧的 alpha | dayTextureNight/DayAlpha[i] |
| `brightness` / `contrast` / `hue` / `saturation` | 逐层调色 | dayTexture* [i] |
| `gamma` | 伽马校正 | dayTextureOneOverGamma[i] |
| `colorToAlpha` + `colorToAlphaThreshold` | 把某颜色抠成透明（如去黑色背景） | colorsToAlpha[i] |
| `cutoutRectangle` | 矩形镂空（露出下层） | dayTextureCutoutRectangles[i] |
| `splitDirection` | 卷帘左右分屏 | dayTextureSplit[i] |
| `minimumTerrainLevel` / `maximumTerrainLevel` | 仅在特定地形 LOD 区间显示 | [`_createTileImagerySkeletons`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L704) 入口判断 |

**性能开关的巧思**（[`addDrawCommandsForTile`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L2528)）：装 uniform 时逐项检查「是否等于默认值」，
全默认就不开对应 `apply*` 宏 → GlobeFS 里那些调色分支整个被编译期剔除。什么都不调 = 最快路径。

### 叠加的数学

[`GlobeFS`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Shaders/GlobeFS.glsl) 里逐层采样后混合（`initialColor` 白色起步）：
第一遍 draw 用不透明 renderState 打底，第二遍起用 `ALPHA_BLEND`——所以**底层建议不透明全球图**，
半透明层放上面，混合成本和视觉都最稳。

### 拾取（点击查「我点的是哪个图层/要素」）

- [`imageryLayers.pickImageryLayers(ray, scene)`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L455)：同步，返回命中层列表。

## 5. 集合事件：增删层时引擎内部发生了什么

`ImageryLayerCollection` 的四个事件由 [`GlobeSurfaceTileProvider`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L85) 构造时订阅
（`layerAdded/layerRemoved/layerMoved/layerShownOrHidden` → [`_onLayerAdded`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1251) 等回调）：

| 事件 | 引擎内部反应 |
|---|---|
| `layerAdded` | 清该层影像缓存 → 遍历全部已加载瓦片：删旧层位 TileImagery、原地重建骨架、`renderable=false`（渲染中的瓦片豁免）→ `imageryLayersUpdatedEvent` 通知上层（Scene 用它触发重绘） |
| `layerRemoved` | 释放该层在瓦片里的 TileImagery 引用；若是基底层被删，[`_update`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L816) 会重选基底层并触发受影响瓦片重建 |
| `layerMoved` | 标记 `_layerOrderChanged`，下帧 [`initialize`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L412) 重排所有瓦片 imagery[] |
| `layerShownOrHidden` | show 切换：补建/删除骨架（等价于局部 add/remove） |

这也是 `Viewer` 里「传 `baseLayer` 覆盖默认底图」段（`Viewer.js` options.baseLayer 覆盖逻辑，
[`removeAll()`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L204)+[`add()`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L101)）能无缝生效的原因——removeAll 抛 layerRemoved、add 抛 layerAdded，全链路自动响应。

## 8. 动手实验：Sandcastle 换 UrlTemplate 底图，映射回源码

最小示例：

```js
const viewer = new Cesium.Viewer("cesiumContainer", {
  baseLayer: Cesium.ImageryLayer.fromProviderAsync(
    Cesium.UrlTemplateImageryProvider.fromUrl(
      "https://webst0{s}.is.autonavi.com/appmaptile?style=6&x={x}&y={y}&z={z}",
      { subdomains: ["1", "2", "3", "4"], maximumLevel: 18 },
    ),
  ),
  baseLayerPicker: false,
});
```

对照源码逐行解释（建议开着 GitHub 对照读）：

1. **`UrlTemplateImageryProvider.fromUrl(...)`** → 异步建 provider。真正构造发生在
   [`function UrlTemplateImageryProvider`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L201)：记下模板、subdomains、默认 [`WebMercatorTilingScheme`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Core/WebMercatorTilingScheme.js#L27)。
   高德瓦片是墨卡托，默认正好；若换成经纬度切片服务要传 `tilingScheme: new GeographicTilingScheme()`。
   `{s}` + subdomains：展开时 [`sTag`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L760) 按 (x+y+z) 取模轮询 4 个域名。
2. **`ImageryLayer.fromProviderAsync(promise)`** → [`ImageryLayer.js`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L550)：先返回一个 provider 为空的
   Layer（`_skeletonPlaceholder` 占位），Promise resolve 后 [`handlePromise`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L1762) 填入并抛 `readyEvent`。
3. **`baseLayer: layer`** → [`Viewer.js` 覆盖段](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/widgets/Source/Viewer/Viewer.js#L751) → `imageryLayers.add(layer)` → [`_onLayerAdded`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L1251)
   （§5 表第 1 行）为每个地形瓦片建骨架——此刻还没发一个请求。
4. **第一帧渲染** → [`selectTilesForRendering`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/QuadtreePrimitive.js#L522) 选中根瓦片 → [`loadTile`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/GlobeSurfaceTileProvider.js#L694) → 先地形后影像 →
   [`_createTileImagerySkeletons`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L704) 把根瓦片映射到 z=0 的那 1 块影像 → [`_requestImagery`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayer.js#L1134) 发出
   第一个瓦片请求（[`buildImageResource`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/UrlTemplateImageryProvider.js#L631) 展开 URL：`webst01.is.autonavi.com/...?style=6&x=0&y=0&z=0`）。
5. **观察父图替代**：把 `viewer.scene.globe.maximumScreenSpaceError` 调小（如 1）快速拖动地图，
   能看到瓦片先糊后清——糊的那张就是 parent 链上的 `readyImagery`（§3）。
6. **观察层序**：再 `viewer.imageryLayers.addImageryProvider(new Cesium.SingleTileImageryProvider({url, rectangle}))`
   盖一块小图，然后 [`raise`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L306)/[`lower`](https://github.com/Cpu1998/cesium/blob/study/1.145-annotated/packages/engine/Source/Scene/ImageryLayerCollection.js#L319) 调序，对照 `layerMoved` → `_layerOrderChanged` → 重排。
7. **观察调色宏**：`viewer.imageryLayers.get(0).brightness = 2.0`，抓帧会看到 shader 分支变化
   （`applyBrightness` 打开，§4）。
