# 00 · 总览：Cesium 1.145 架构与目录地图

> 阅读前提：无。本文是整个导读的地基——先建立"包—层—对象"的心理地图，再进具体文件。
> 引用约定：源码一律「文件路径 + 函数名」，不用行号。

## 1. 仓库三大包

```
cesium/
├── packages/
│   ├── engine/      ← 引擎包（@cesium/engine）：一切与"渲染一个三维地球"有关的能力
│   ├── widgets/     ← 部件包（@cesium/widgets）：现成 UI 组合层，构建于 engine 之上
│   └── sandcastle/  ← 官方示例沙盒（Sandcastle），不是运行时依赖
├── Apps/            ← 官方演示应用（CesiumViewer 等）
├── Specs/           ← 单元/端到端测试
└── Tools/ scripts/  ← 构建（gulp）、文档（jsdoc）等工程设施
```

三个包的依赖方向是单向的：`widgets → engine`，`sandcastle → widgets + engine`。
日常业务代码 `import * as Cesium from "cesium"` 拿到的是 engine + widgets 的合并出口。

## 2. engine 包的分层

```
packages/engine/Source/
├── Core/          ← 数学与基础设施（无渲染语义）
│   ├─ Cartesian3 / Matrix4 / Quaternion …   向量、矩阵、四元数
│   ├─ Ellipsoid / Cartographic              椭球与经纬度（弧度）
│   ├─ JulianDate / Clock                    仿真时间与时钟
│   ├─ ScreenSpaceEventHandler               鼠标/触摸事件规范化
│   └─ Resource / loadWithXhr …              网络请求、worker、调度
├── DataSources/   ← 声明式数据层："描述了什么"，不关心怎么画
│   ├─ Entity / Property 体系（ConstantPositionProperty…）
│   ├─ DataSourceCollection / CustomDataSource / GeoJsonDataSource…
│   └─ DataSourceDisplay（Entity → 可视化 的转换中枢）
├── Scene/         ← 场景层：管理"要画的所有东西"与调度（最大的目录）
│   ├─ Scene（渲染入口/帧状态/Pass 编排）   ├─ Globe（地形+影像地球）
│   ├─ ImageryLayer / 各类 ImageryProvider  ├─ Cesium3DTileset（3D Tiles）
│   ├─ Camera / 各 ScreenSpaceCameraController ├─ SkyBox / Sun / Moon / Atmosphere
│   └─ Primitive / Geometry 体系（GeometryInstance、Batch…）
├── Renderer/      ← WebGL 薄封装：Context、ShaderProgram、Texture、Framebuffer、
│   ├─ DrawCommand / ClearCommand / ComputeCommand（渲染命令抽象）
│   └─ ShaderCache / ShaderBuilder（着色器管理与拼装）
├── Shaders/       ← 内置 GLSL 源码（本导读不碰 GLSL，只在文档里描述）
├── Widget/        ← 引擎层唯一 UI 组件：CesiumWidget（最小可用三维地球）
├── Workers/       ← Web Worker（几何批处理、编码解码等重活）
├── Assets/        ← 星空纹理、默认字体等静态资源
└── ThirdParty/    ← 打包进来的第三方库
```

分层依赖大致自上而下：`Widget → Scene → Renderer → Core`；`DataSources` 横向使用 Core，
由 `DataSourceDisplay`（DataSources 目录）桥接到 Scene。

## 3. 对象树：一次 `new Viewer()` 之后内存里长什么样

```
Viewer                          (widgets 包，组装层：UI + 事件接线)
└─ CesiumWidget                (engine 包，最小三维组件：canvas/时钟/渲染循环)
   ├─ canvas : HTMLCanvasElement        ← WebGL 绘制目标
   ├─ clock   : Clock                   ← 仿真时间（Viewer 与 CesiumWidget 共享同一个）
   ├─ ScreenSpaceEventHandler           ← 输入事件（单击/双击/滚轮…）
   ├─ Scene                            ← ★ 渲染世界的根对象
   │  ├─ camera : Camera               ← 视点/视锥/飞行动画
   │  ├─ globe  : Globe                ← 地球 = 地形网格 + 影像贴图
   │  │  ├─ terrainProvider            ← 地形高程从哪来（瓦片金字塔）
   │  │  └─ imageryLayers : ImageryLayerCollection
   │  │     └─ ImageryLayer × N        ← 底图与叠加图层（默认 = ion 世界影像）
   │  ├─ primitives : PrimitiveCollection   ← 显式三维内容（Primitive/3D Tiles/点云…）
   │  ├─ skyBox / sun / moon / skyAtmosphere
   │  ├─ postProcessStages             ← 后处理链（泛光/FXAA/夜景…）
   │  └─ frameState : FrameState       ← 每帧的只读快照（相机/模式/Pass 标志…）
   ├─ DataSourceDisplay               ← Entity → Primitive 的可视化中枢
   │  └─ defaultDataSource.entities    ← viewer.entities 的真身
   └─ dataSources : DataSourceCollection ← 数据源容器（CZML/GeoJSON/KML…）
```

要点：
- `Viewer` 的 `scene/camera/imageryLayers/entities` 等属性全是**转发**给 CesiumWidget/Scene（见
  `packages/widgets/Source/Viewer/Viewer.js` 的 `Object.defineProperties(Viewer.prototype, …)`）。
- 真正创建 WebGL 上下文的是 `new Scene(...)`（在
  `packages/engine/Source/Widget/CesiumWidget.js` 的构造函数里调用），Scene 内部再建
  `Renderer/Context.js` 的 `Context`。

## 4. 端到端链路：一个坐标从数据到像素

以「`viewer.entities.add({position : Cartesian3…, point : {…}})` 之后屏幕上出现一个点」为例：

```
【数据】Entity{position, point}                          （DataSources/Entity.js）
   │  DataSourceDisplay.update(time)  每 clock.onTick 触发一次
   ▼
【转换】Entity 属性 → 可视化对象（点→ BillboardCollection/Primitive…）
   │  （DataSources/DataSourceDisplay.js —— 第 3 棒深挖）
   ▼
【场景】Primitive.update(frameState)                      （Scene 层）
   │  位置 → 模型矩阵；几何 → 顶点缓冲；生成 DrawCommand 列表
   │  Globe 侧：地形瓦片调度 + 影像瓦片贴图 —— 第 2 棒深挖
   ▼
【帧】Scene.render(time)                                  （Scene/Scene.js 的 Scene.prototype.render）
   │  requestRenderMode 未开启时每帧执行；开启后只在"脏"时执行
   │  ① onTick/preUpdate 事件 → ② 相机与视锥 → ③ 剔除(culling)
   │  → ④ 多 Pass（Globe→3D Tiles→不透明→半透明→拾取…）→ ⑤ 后处理
   ▼
【渲染】DrawCommand → Context.drawCommands → WebGL 调用   （Renderer/Context.js）
   │  gl.drawElements / uniform 上传 / 着色器绑定
   ▼
【像素】canvas 上的一帧 = 你看到的一个点                   【帧循环 → 第 5 棒深挖】
```

整条链路的"心跳"来自 `packages/engine/Source/Widget/CesiumWidget.js` 的 `startRenderLoop`：
`requestAnimationFrame` 每帧调 `CesiumWidget.prototype.render`（骨架：`scene.initializeFrame`
→ `clock.tick` → `scene.render(currentTime)`）。
